[Sazabi](https://sazabi.com) is AI-native log search and incident investigation. The Sazabi adapter sends your wide events to a Sazabi log stream over **OTLP/HTTP**, so every field you set with `log.set()` arrives as a searchable attribute.

Add the Sazabi drain adapter to send evlog wide events to Sazabi.

1. Identify which framework I'm using and follow its evlog integration pattern
2. Install evlog if not already installed
3. Import createSazabiDrain from 'evlog/sazabi'
4. Wire createSazabiDrain() into my framework's drain configuration
5. Set SAZABI_INTAKE_URL environment variable in .env
6. Test by triggering a request and checking the log stream in Sazabi

Adapter docs: https://www.evlog.dev/integrate/adapters/cloud/sazabi
Framework setup: https://www.evlog.dev/integrate/frameworks/overview

::

## Installation

The Sazabi adapter comes bundled with evlog:

```typescript [src/index.ts]
import { createSazabiDrain } from 'evlog/sazabi'
```

## Quick Start

### 1. Copy your intake URL

1. In Sazabi, open **Log streams** and create or open an **OpenTelemetry** log stream
2. Copy its **Intake URL**. The stream's public key is part of the URL, so there is no separate API key to set

### 2. Set environment variables

```bash [.env]
SAZABI_INTAKE_URL=https://<key>.us-west-2.intake.sazabi.com
```

### 3. Wire the drain to your framework

## Configuration

The adapter reads configuration from multiple sources (highest priority first):

1. **Overrides** passed to `createSazabiDrain()`
2. **Runtime config** at `runtimeConfig.evlog.sazabi` or `runtimeConfig.sazabi` (Nuxt/Nitro only)
3. **Environment variables** (`SAZABI_*`)

### Environment Variables

| Variable | Description |
|----------|-------------|
| `SAZABI_INTAKE_URL` | Intake URL of the log stream. evlog posts to `<intake URL>/v1/logs`; a URL that already ends with `/v1/logs` is used as is |
| `SAZABI_SERVICE_NAME` | Override `service.name` |
| `OTEL_SERVICE_NAME` | Fallback for `service.name` (same as the OTLP adapter) |

### Runtime Config (Nuxt only)

```typescript [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    sazabi: {
      // endpoint: '', // Set via SAZABI_INTAKE_URL
    },
  },
})
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `endpoint` | `string` | `SAZABI_INTAKE_URL` | Intake URL of the log stream |
| `serviceName` | `string` | `event.service` | Override `service.name` |
| `resourceAttributes` | `object` | - | Additional OTLP resource attributes |
| `timeout` | `number` | `5000` | Request timeout in milliseconds |
| `retries` | `number` | `2` | Retry attempts on transient failures |
| `recordShape` | `'compact' \| 'json'` | `'compact'` | Log record shape: a one-line summary body with dotted attributes, or the serialized event as the body |
| `semanticConventions` | `boolean` | `true` | Add OpenTelemetry semantic convention attribute names (`http.request.method`, `url.path`, ...) next to the evlog ones |

### Keep the 2.x Output

By default, records use the `compact` shape and carry OpenTelemetry semantic convention names. To keep the 2.x output, set both options:

```typescript [server/plugins/evlog-drain.ts]
import { createSazabiDrain } from 'evlog/sazabi'

createSazabiDrain({
  recordShape: 'json',
  semanticConventions: false,
})
```

## How It Works

The adapter is a thin layer over the [OTLP adapter](/integrate/adapters/hybrid/otlp): it normalizes the intake URL and sends the batch with the same OTLP/JSON encoding.

- The event's `service`, `environment`, `version`, `region` and `commitHash` become resource attributes
- `level` maps to the OTLP severity
- Records use the compact shape: the body is a one-line summary such as `POST /api/checkout (500)`
- Semantic convention names such as `http.request.method` sit next to the evlog names, unless `semanticConventions: false`
- Every other field of the wide event becomes a log attribute, with nested fields flattened to dotted keys, so `user.plan` or `cart.total` can be filtered and grouped in Sazabi

## Querying logs in Sazabi

Open the log stream and ask a question in plain language, for example "how many checkout requests failed in the last hour?", or filter on any field the wide event carries.

## Troubleshooting

### Missing endpoint error

```
[evlog/sazabi] Missing endpoint. Set SAZABI_INTAKE_URL, or pass to createSazabiDrain()
```

Set `SAZABI_INTAKE_URL` in the environment the server runs in, or pass `endpoint` to `createSazabiDrain()`.

### 4xx from the intake

Copy the intake URL again from the log stream: a truncated host or an old stream's URL is rejected.

## Direct API Usage

Send events without the drain, for scripts and jobs:

```typescript [scripts/send.ts]
import { sendBatchToSazabi, sendToSazabi } from 'evlog/sazabi'

await sendToSazabi(event, { endpoint: process.env.SAZABI_INTAKE_URL! })
await sendBatchToSazabi(events, { endpoint: process.env.SAZABI_INTAKE_URL! })
```
