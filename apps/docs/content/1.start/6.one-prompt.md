Paste the prompt below into your coding agent. It installs the evlog CLI, runs [`evlog init`](/cli/init) to wire your framework, and leaves an `AGENTS.md` block and the [agent skills](/reference/agent-skills) behind, so the next handler the agent writes logs through `useLogger` instead of `console.log` and throws `createError` instead of `new Error`.

## The prompt

::prompt
---
description: Add evlog to this project
icon: i-lucide-wand-sparkles
actions:
  - copy
  - cursor
  - claude
---

Add evlog (https://www.evlog.dev) to this project for structured logging with wide events.

1. Read https://www.evlog.dev/llms.txt to find the guide for this project's framework.
2. If you can run terminal commands, install the CLI as a dev dependency with this project's package manager and run init through the same one:
   - pnpm: pnpm add -D @evlog/cli, then pnpm exec evlog init --yes
   - npm: npm install -D @evlog/cli, then npx evlog init --yes
   - yarn: yarn add -D @evlog/cli, then yarn evlog init --yes
   - bun: bun add -d @evlog/cli, then bunx evlog init --yes
   It detects the framework, installs evlog, writes evlog.config.ts, registers the integration, adds an evlog block to AGENTS.md and installs the evlog agent skills. Apply every manual step it prints, and fix anything the doctor check at the end flags.
3. If evlog init reports the framework as unsupported, or you cannot run commands, add the evlog package and follow the framework guide by hand.
4. When you write or change server code from now on:
   - Get the request logger from the integration (useLogger) and build one wide event per request with log.set({ ... }), fields grouped into objects.
   - Throw createError({ message, status, why, fix }) from evlog, never new Error(...).
   - Use log.error(error), never console.log or console.error, for application logs.
   - Never log passwords, tokens, API keys or a raw request body.

Docs: https://www.evlog.dev/llms.txt
::

Cursor and Claude Code open the prompt directly from the buttons. For v0, Lovable, Bolt or any other agent, copy it into the chat.

## What the agent runs

With a terminal, the prompt comes down to two commands, run with the project's package manager:

::code-group
```bash [pnpm]
pnpm add -D @evlog/cli
pnpm exec evlog init --yes
```
```bash [bun]
bun add -d @evlog/cli
bunx evlog init --yes
```
```bash [yarn]
yarn add -D @evlog/cli
yarn evlog init --yes
```
```bash [npm]
npm install -D @evlog/cli
npx evlog init --yes
```
::

`@evlog/cli` as a dev dependency is what the `evlog` binary itself recommends when it has to fetch the CLI: a pinned version that starts instantly on the next run (`packages/evlog/bin/evlog.mjs`). `--yes` skips every question and takes the defaults, so the agent never waits on a keystroke: local NDJSON files in development and no production destination until you pick one ([non-interactive flags](/cli/init#non-interactive)).

`evlog init` wires Nuxt, Nitro, Next.js, TanStack Start, Hono, Express and Fastify, and stops with an error on anything else. For the other [framework integrations](/integrate/frameworks/overview), step 3 of the prompt sends the agent to the guide instead.

## AGENTS.md

`evlog init` and [`evlog agents`](/cli/agents) write a fuller version of this block into `AGENTS.md` for you, with the logger accessor that matches your framework. To add it by hand, paste it into the `AGENTS.md` at the root of the repository:

```md [AGENTS.md]
## Logging with evlog

This project logs with [evlog](https://www.evlog.dev). Follow these rules when you add or change logging.

- One wide event per operation: a request, a job, a user action. Not one log line per step.
- Get the request logger from the integration: `useLogger(event)` on Nuxt and Nitro, `useLogger()` from `lib/evlog.ts` on Next.js.
- Add context as you learn it: `log.set({ user: { id, plan }, cart: { items, total } })`. Group fields into objects.
- List the fields you log. Never pass a raw request body to `log.set`.
- Throw `createError({ message, status, why, fix })` from `evlog`. Never `throw new Error(...)`.
- Never use `console.log` or `console.error` for application logs. Use `log.error(error)` for a caught error.
- Never log passwords, tokens, API keys, card numbers or session JWTs.

Docs: https://www.evlog.dev/llms.txt
```

Cursor reads `AGENTS.md` at the root and in subdirectories ([Cursor rules](https://cursor.com/docs/context/rules)). Claude Code reads it when the repository has no `CLAUDE.md` ([Claude Code memory](https://code.claude.com/docs/en/memory)).

## Cursor rules

The same rules as a Cursor project rule. Project rules live in `.cursor/rules` and need the `.mdc` extension; with a `description` and `alwaysApply: false`, the agent pulls the rule in when the task is about logging or errors ([Cursor rules](https://cursor.com/docs/context/rules)).

```md [.cursor/rules/evlog.mdc]
---
description: Logging and error handling with evlog. Use when adding logs, handling errors, or writing API routes and server handlers.
alwaysApply: false
---

- One wide event per request, job or user action. Not one log line per step.
- Get the request logger with `useLogger` from the evlog integration and add context with `log.set({ ... })`, fields grouped into objects.
- Throw `createError({ message, status, why, fix })` from `evlog`. Never `throw new Error(...)`.
- Never use `console.log` or `console.error` for application logs. Use `log.error(error)`.
- Never log passwords, tokens, API keys or a raw request body.
- Docs: https://www.evlog.dev/llms.txt
```

Set `alwaysApply: true` to load it on every request instead, or add `globs` to attach it only when server files are open.

## FAQ

::accordion{type="single"}
  ::accordion-item{label="Does the prompt work in v0, Lovable and Bolt?"}
  Paste the same prompt. When the agent can run commands it takes step 2. When it cannot, step 3 has it add the `evlog` package and follow the framework guide, so the app is wired but the agent skills, which `evlog init` installs through the skills CLI, are not.
  ::
  ::accordion-item{label="Will it overwrite my files?"}
  No. `evlog init` appends and never rewrites: a file that already exists is left alone and reported, and anything it cannot patch safely becomes a manual step with the snippet to paste ([It will not overwrite your code](/cli/init#it-will-not-overwrite-your-code)). In `AGENTS.md` it only replaces the text between `<!-- evlog:start -->` and `<!-- evlog:end -->`.
  ::
  ::accordion-item{label="AGENTS.md or .cursor/rules?"}
  `AGENTS.md`, unless you only use Cursor and want the rule scoped to some files. Cursor, Claude Code and the other agents read the same `AGENTS.md`, while `.cursor/rules` is read by Cursor alone.
  ::
  ::accordion-item{label="Can I run it again?"}
  Yes. A second `evlog init` reports what is already wired and writes nothing, so the agent can re-run it after a failed step without duplicating config.
  ::
::
