Your Node.js server handles a request and you need to know what happened: ten `console.log` lines across three files, and you are still grepping by timestamp hoping the pieces line up. Structured logging in Node.js means emitting one JSON event per unit of work with all its context attached, and evlog gives you that in Node without a framework requirement.

## The wrong shape: scattered lines

```typescript [src/checkout.ts]
console.log('processing order', orderId)
console.log('user', userId)
// ...on failure:
console.error('payment failed', err)
```

When this request fails, you grep for the order id, match timestamps across files, and reconstruct the story by hand. Levels, redaction, and delivery are all on you.

## The right shape: one wide event

```typescript [src/checkout.ts]
import { createLogger, createError } from 'evlog'

const log = createLogger({ orderId, userId })
try {
  const charge = await chargeCard(order)
  log.set({ payment: { chargeId: charge.id } })
} catch (err) {
  log.error(err as Error)
  throw err
} finally {
  log.emit()
}
```

One JSON row per request, queryable by `orderId`, `userId`, or error code. evlog accumulates context over the operation and emits once, including when the handler throws.

## What you get in Node.js specifically

- **JSON in production, pretty output in dev**, the same split pino gives you, with redaction applied before anything leaves the process.
- **Drains instead of transports.** pino writes through a transport you assemble ([transports](https://getpino.io/#/docs/transports)). evlog ships [drain adapters](/integrate/adapters/overview) and the pipeline that batches and retries them.
- **Request lifecycle in HTTP frameworks.** In Express, Fastify, NestJS, or Hono, the middleware creates and emits the event for you. See [framework integrations](/integrate/frameworks/overview).
- **Works outside Node too.** The same API runs on Cloudflare Workers, Deno, Bun, and the browser. See [Standalone TypeScript](/integrate/frameworks/standalone).
