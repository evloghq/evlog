The wide event already contains the full `gen_ai` metadata, but you often want the same data inside your handler: to persist it, surface it to end-users, bill against it, or stream incremental progress to the client.

`AILogger` exposes three methods for that, with no need to touch internal state.

## `getMetadata()`: final snapshot

Returns a structured `AIMetadata` object that mirrors the `gen_ai` field on the wide event. Safe to call at any point, including after the run completes or inside the AI SDK's `onFinish`:

```typescript [server/api/chat.post.ts]
import { useLogger } from 'evlog'
import { createAILogger } from 'evlog/ai'
import { generateText } from 'ai'

export default defineEventHandler(async (event) => {
  const log = useLogger(event)
  const ai = createAILogger(log, {
    cost: { 'claude-sonnet-4.6': { input: 3, output: 15 } },
  })

  await generateText({
    model: ai.wrap('anthropic/claude-sonnet-4.6'),
    prompt: 'Summarize this document',
  })

  const metadata = ai.getMetadata()

  await db.aiRuns.insert({
    userId: event.context.userId,
    model: metadata.request?.model,
    inputTokens: metadata.usage.input_tokens,
    outputTokens: metadata.usage.output_tokens,
    estimatedCost: metadata.usage.estimated_cost,
    finishReasons: metadata.response?.finish_reasons,
    responseId: metadata.response?.id,
  })

  return { ok: true }
})
```

The snapshot is a fresh copy: mutating it never affects the underlying state or subsequent calls.

## `getEstimatedCost()`: quick cost check

Convenience for `getMetadata().usage.estimated_cost`. Returns the cost in dollars, or `undefined` if no `cost` map was provided or the model is not in the map.

```typescript
const ai = createAILogger(log, {
  cost: { 'claude-sonnet-4.6': { input: 3, output: 15 } },
})

await generateText({ model: ai.wrap('anthropic/claude-sonnet-4.6'), prompt })

const cost = ai.getEstimatedCost()
console.log(`This call cost $${cost?.toFixed(4)}`)
```

## `onUpdate(callback)`: incremental updates

Subscribe to metadata updates. The callback fires every time the underlying state flushes:

- Once per step in multi-step agent runs
- Once per `captureEmbed` call
- On model errors
- On `createEvlogIntegration`'s `onEnd` (v7) or `onFinish` (v6)

Each invocation receives a fresh snapshot. Returns an unsubscribe function. Subscriber errors are isolated and never break the AI flow.

```typescript [server/api/agent.post.ts]
import { ToolLoopAgent, createAgentUIStreamResponse, stepCountIs } from 'ai'
import { useLogger } from 'evlog'
import { createAILogger } from 'evlog/ai'

export default defineEventHandler(async (event) => {
  const log = useLogger(event)
  const { messages } = await readBody(event)
  const ai = createAILogger(log)

  ai.onUpdate((metadata) => {
    pushToClient(event, {
      type: 'ai-progress',
      step: metadata.steps,
      tokens: metadata.usage.total_tokens,
      cost: metadata.usage.estimated_cost,
    })
  })

  const agent = new ToolLoopAgent({
    model: ai.wrap('anthropic/claude-sonnet-4.6'),
    tools: { searchWeb, queryDatabase },
    stopWhen: stepCountIs(5),
  })

  return createAgentUIStreamResponse({ agent, uiMessages: messages })
})
```

For one-off cleanup:

```typescript
const off = ai.onUpdate((metadata) => { /* ... */ })
// later
off()
```

## `AIMetadata` shape

`AIMetadata` is a public type alias for the snapshot returned by `getMetadata()` and passed to `onUpdate` listeners. It has the same shape as the `gen_ai` field on the wide event.

```typescript
import type { AIMetadata, AIMetadataListener } from 'evlog/ai'

function handleProgress(metadata: AIMetadata) {
  console.log(`${metadata.calls} calls, $${metadata.usage.estimated_cost ?? 0}`)
}

const listener: AIMetadataListener = handleProgress
ai.onUpdate(listener)
```

## Every field the middleware records

Every AI field sits under `gen_ai`. Names follow the [OpenTelemetry GenAI semantic conventions](https://github.com/open-telemetry/semantic-conventions-genai) where they define one, so a drain that flattens the event, such as [OTLP](/integrate/adapters/hybrid/otlp), sends the attributes OTel backends read. Fields the conventions do not define (marked evlog) live under the same key, so one query or chart reaches all of them. The conventions are still in Development status upstream; evlog follows their renames in a minor release.

| Wide event field | Source | Description |
|-----------------|--------|-------------|
| `gen_ai.calls` | evlog | Number of AI calls in this request |
| `gen_ai.provider.name` | OTel | Provider (`anthropic`, `openai`, `google`, etc.) |
| `gen_ai.request.model` | OTel | Model that served the response (`response.modelId`) |
| `gen_ai.request.models` | evlog | Array of all models used (only when > 1) |
| `gen_ai.usage.input_tokens` | OTel | Total input tokens across all calls, cached ones included |
| `gen_ai.usage.output_tokens` | OTel | Total output tokens across all calls |
| `gen_ai.usage.total_tokens` | evlog | `input_tokens + output_tokens` |
| `gen_ai.usage.cache_read.input_tokens` | OTel | Tokens served from prompt cache |
| `gen_ai.usage.cache_write.input_tokens` | OTel | Tokens written to prompt cache |
| `gen_ai.usage.reasoning.output_tokens` | OTel | Reasoning tokens (extended thinking) |
| `gen_ai.usage.estimated_cost` | evlog | Estimated cost in dollars (requires the `cost` option) |
| `gen_ai.response.finish_reasons` | OTel | One reason per call (`stop`, `tool-calls`, `error`, `abort`, ...) |
| `gen_ai.response.id` | OTel | Provider-assigned response ID (e.g. Anthropic's `msg_...`) |
| `gen_ai.response.time_to_first_chunk` | OTel | Seconds to the first streamed chunk (streaming only) |
| `gen_ai.response.duration_ms` | evlog | Total stream duration (streaming only) |
| `gen_ai.response.tokens_per_second` | evlog | Output tokens per second (streaming only) |
| `gen_ai.tool_calls` | evlog | `string[]` of tool names by default, or `Array<{ name, input }>` when `toolInputs` is enabled |
| `gen_ai.tools` | evlog | Per-tool `{ name, duration_ms, success, error? }` (requires `createEvlogIntegration`) |
| `gen_ai.input.text` | evlog | Formatted text of the prompt sent to the first model call (only with the `prompt` option) |
| `gen_ai.output.text` | evlog | Text generated by the last model call (only with the `output` option) |
| `gen_ai.steps` | evlog | Number of LLM calls (only when > 1) |
| `gen_ai.steps_usage` | evlog | Per-step `{ model, input_tokens, output_tokens, tool_calls? }` (only when > 1 step) |
| `gen_ai.error` | evlog | Error message if a model call fails |
| `gen_ai.duration_ms` | evlog | Total generation wall time (requires `createEvlogIntegration`) |
| `gen_ai.embedding` | evlog | `{ model?, tokens, dimensions?, count? }` from `captureEmbed` |
