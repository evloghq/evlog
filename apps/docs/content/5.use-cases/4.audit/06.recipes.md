Pick the recipe that matches your drain, drop it in, and you have a tamper-evident audit log. Each recipe composes the same primitives (`auditOnly`, `signed`) over different drains.

## Audit logs on disk

::code-group

```typescript [Input: server/plugins/evlog.ts]
import { auditOnly, signed } from 'evlog'
import { createFsDrain } from 'evlog/fs'

nitro.hooks.hook('evlog:drain', auditOnly(
  signed(createFsDrain({ dir: '.audit', maxFiles: 30 }), { strategy: 'hash-chain' }),
))
```

## Audit logs to a dedicated Axiom dataset

::code-group

```typescript [Input: server/plugins/evlog.ts]
import { auditOnly } from 'evlog'
import { createAxiomDrain } from 'evlog/axiom'

nitro.hooks.hook('evlog:drain', createAxiomDrain({ dataset: 'logs' }))
nitro.hooks.hook('evlog:drain', auditOnly(
  createAxiomDrain({ dataset: 'audit', apiKey: process.env.AXIOM_AUDIT_API_KEY }),
))
```

```kusto [Output: Axiom query]
['audit']
| where audit.action == "invoice.refund"
| summarize count() by audit.outcome, bin(_time, 1h)
```

```kusto [Output: denials by actor]
['audit']
| where audit.outcome == "denied"
| summarize count() by audit.actor.id, audit.action
| order by count_ desc
```

::

Splitting datasets means the audit dataset can have a longer retention (7y), tighter access controls, and a separate billing line, without touching the rest of your pipeline.

## Audit logs in Postgres

Key the table on the record's `id`, so a drain that retries a write keeps one row:

```typescript [server/plugins/evlog.ts]
import { auditOnly } from 'evlog'
import type { DrainContext } from 'evlog'

const postgresAudit = async ({ event }: DrainContext) => {
  const record = event.audit!
  await db.insert(auditEvents).values({
    id: record.id,
    tenantId: record.tenantId,
    timestamp: new Date(record.timestamp),
    record,
  }).onConflictDoNothing()
}

nitro.hooks.hook('evlog:drain', auditOnly(postgresAudit))
```

`await log.audit()` resolves once the insert is done, so the row exists before your handler returns. A table that also needs a request log join keeps `event.requestId` in its own column.

## Show each customer their audit log

Your customers read their own trail from your store, with the same tenant filter on every query. Page with the record's position, newest first, and pass the last position back as a cursor:

```typescript [server/api/audit.get.ts]
export default defineEventHandler(async (event) => {
  const { teamId } = await requireTeamMember(event)
  const { before } = getQuery(event)
  return db.select().from(auditEvents)
    .where(and(
      eq(auditEvents.tenantId, teamId),
      before ? lt(auditEvents.id, String(before)) : undefined,
    ))
    .orderBy(desc(auditEvents.id))
    .limit(50)
})
```

UUIDv7 ids sort by creation time, so they work as the cursor. A table with a `bigserial` primary key can page on that column instead, and the same column is the cursor a [webhook relay](/use-cases/audit/pipeline#send-each-tenants-audits-to-their-endpoint) moves through. Export to CSV and retention per plan live here too, on the table you own.

## Test what you recorded

`mockAudit()` captures every record `log.audit()`, `log.audit.deny()`, `audit()` and `withAudit()` make, with its `id`, as soon as the call is made:

```typescript
import { mockAudit } from 'evlog'

it('refunds the invoice and records an audit', async () => {
  const captured = mockAudit()

  await refundInvoice({ id: 'inv_889' }, { actor: { type: 'user', id: 'u1' } })

  captured.assertAudit({
    action: 'invoice.refund',
    target: { type: 'invoice', id: 'inv_889' },
    outcome: 'success',
  })

  captured.restore()
})
```

Prefer `assertAudit()` when a missing audit should fail the test with a readable message. Use `toIncludeAuditOf()` when you need a boolean inside `expect(...)`.

Always call `captured.restore()` in an `afterEach` (or wrap with a fixture) so a failing assertion never leaks into the next test.

## Every audit export

| Symbol | Kind | Notes |
|---|---|---|
| `AuditFields` | type | The record an audit event carries in `audit` |
| `defineAuditAction(name, opts?)` | factory | Typed action registry, infers target shape |
| `defineAuditCatalog(prefix, map)` | factory | Bundle of typed audit actions sharing a prefix |
| `log.audit(input)` | method | Records one action as its own event; resolves once every drain has it |
| `log.audit.deny(reason, input)` | method | Records a denied action |
| `audit(input)` | function | Standalone, for scripts, jobs and Nitro tasks |
| `withAudit({ action, target })(fn)` | wrapper | Records success, failure or denied around `fn` |
| `buildAuditFields(input)` | helper | Makes a record without emitting it |
| `auditDiff(before, after)` | helper | Redact-aware JSON Patch for `changes` |
| `mockAudit()` | test util | Capture records; `assertAudit()` or `toIncludeAuditOf()` |
| `auditEnricher({ tenantId })` | enricher | Fills `tenantId` from the request when the call left it empty |
| `auditOnly(drain)` | wrapper | Makes a drain the audit store: audit records only, identities kept |
| `signed(drain, opts)` | wrapper | Integrity wrapper (hmac / hash-chain) |
| `relayAudit(opts)` | function | Forwards stored records to a destination behind a cursor |
| `auditRedactPreset` | config | Strict PII for audit events |

These ship from the main `evlog` entrypoint. The webhook helpers ship from `evlog/webhook`:

| Symbol | Notes |
|---|---|
| `createWebhookDrain(opts?)` | Drain that POSTs each audit record as a signed Standard Webhooks message |
| `sendAuditWebhook(records, config)` | Sends records in order, throws at the first refusal; for `relayAudit` |
| `verifyWebhook(body, headers, secret)` | Checks a message on the receiving side and returns its record |
| `signWebhook(id, body, secret)` | The three signature headers for a body you send yourself |
| `generateWebhookSecret()` | A new `whsec_` secret |
| `WebhookVerificationError` | Thrown by `verifyWebhook` |

The [webhook drain page](/integrate/adapters/hybrid/webhook) covers each one.
