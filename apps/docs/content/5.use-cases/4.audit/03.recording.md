Five APIs cover every shape of audit recording: in-request, denied, standalone, auto-instrumented, and typed. Each call records one action as its own event.

## `log.audit()`

`log.audit()` records one action and emits it right away, through the same enrichers and drains as the request's wide event:

```typescript
await log.audit({
  action: 'invoice.refund',
  actor: { type: 'user', id: user.id },
  target: { type: 'invoice', id: 'inv_889' },
  tenantId: invoice.orgId,
})
```

This is the form you'll use most. The record gets its own `id` and `timestamp`, plus the request's `requestId`, `traceId`, IP and user agent. Sampling, `log.discard()` and the `include` / `exclude` route filters apply to request logs only, so they never drop an audit. A call after the request event was emitted still records, which covers work that finishes after the response.

### Record several actions in one request

Call it once per action. Adding a member and renaming the team in one request gives two records, with ids in call order and one `requestId`:

```typescript
await log.audit({ action: 'member.add', actor, target: { type: 'user', id: 'usr_77' }, tenantId: team.id })
await log.audit({ action: 'team.rename', actor, target: { type: 'team', id: team.id }, tenantId: team.id, metadata: { from: 'Acme', to: 'Acme Inc' } })
```

```json [Output: two records]
[
  { "id": "01a204b0-d5ba-713d-afa3-e9121d56d762", "action": "member.add", "requestId": "de784f65-48e0-4776-9ac6-3dcb65dc0e7b" },
  { "id": "01a204b0-d5bb-7029-a9d9-f3c7e7a4a7b9", "action": "team.rename", "requestId": "de784f65-48e0-4776-9ac6-3dcb65dc0e7b" }
]
```

The request's own wide event does not carry an `audit` field. Join the two on `requestId`. Setting `audit` yourself with `log.set()` makes no audit record: `auditOnly` drains skip it.

## Choose when the record is stored

`log.audit()` returns a promise that resolves once every drain has handled the event. It never rejects: a drain that throws is reported on the console, and the other drains still receive the event.

| You write | The record is stored | Costs |
| --- | --- | --- |
| `await log.audit(...)` | Before your handler continues, so before the response | The drain's write time, on the response |
| `log.audit(...)` | After the response | Nothing on the response. The runtime stays alive until the write lands |

Await it when something reads the trail right after the action, such as a UI that shows the audit log or a test that checks it. Without `await`, evlog keeps the delivery alive:

- **With `waitUntil`** (Vercel, Cloudflare Workers, Next.js), the delivery is registered with it. On Vercel this includes Nuxt and Nitro 2 apps, whose Vercel preset passes no `waitUntil` of its own.
- **Without it** (a Node server, AWS Lambda), the integration waits for the delivery before it finishes the request.

Lint rules such as `@typescript-eslint/no-floating-promises` flag an unawaited call. Write `void log.audit(...)` to say the write may land after the response.

## `log.audit.deny()`

`log.audit.deny(reason, fields)` records AuthZ-denied actions. Most teams forget to log denials, but they're exactly what auditors and security teams ask for:

::code-group

```typescript [Input]
if (!user.canRefund(invoice)) {
  await log.audit.deny('Insufficient permissions', {
    action: 'invoice.refund',
    actor: { type: 'user', id: user.id },
    target: { type: 'invoice', id: invoice.id },
    tenantId: invoice.orgId,
  })
  throw createError({ status: 403, message: 'Forbidden' })
}
```

## Standalone `audit()`

For non-request contexts (jobs, scripts, CLIs, Nitro tasks), use the standalone `audit()`. In a Nuxt or Nitro app it goes through your `evlog:enrich` and `evlog:drain` hooks, and elsewhere through the `initLogger` drain and plugins:

::code-group

```typescript [scripts/cleanup.ts]
import { audit } from 'evlog'

await audit({
  action: 'cron.cleanup',
  actor: { type: 'system', id: 'cron' },
  target: { type: 'job', id: 'cleanup-stale-sessions' },
  metadata: { deleted: 42 },
})
```

```json [Output: audit event]
{
  "timestamp": "2026-11-22T19:17:07.644Z",
  "level": "info",
  "service": "billing-api",
  "environment": "production",
  "audit": {
    "id": "01a204b0-d5bc-768c-9fad-ab2ffc27651c",
    "timestamp": "2026-11-22T19:17:07.644Z",
    "action": "cron.cleanup",
    "actor": { "type": "system", "id": "cron" },
    "target": { "type": "job", "id": "cleanup-stale-sessions" },
    "outcome": "success",
    "metadata": { "deleted": 42 },
    "version": 2
  }
}
```

::

::note
Standalone `audit()` events have no `requestId`, no `context.ip`, no `userAgent`, because there is no request to read them from. Put what matters for forensics in `metadata` (`{ jobId, queue, runId }`). Await the call in a script, so the process does not exit before the drains have the event.
::

## `defineAuditAction()`

Define audit actions in one place to avoid magic strings and get full type-safety on `target`:

```typescript
import { defineAuditAction } from 'evlog'

const refund = defineAuditAction('invoice.refund', { target: 'invoice' })

await log.audit(refund({
  actor: { type: 'user', id: user.id },
  target: { id: 'inv_889' }, // type inferred as 'invoice'
}))
```

Pair this with the action dictionary from [Schema → Action naming](/use-cases/audit/schema#action-naming).

## `defineAuditCatalog()`

For more than a handful of actions, group them in a typed **catalog** instead of declaring `defineAuditAction` one-by-one. Same convention as error catalogs: `UPPER_SNAKE_CASE` keys, `lower.dot.case` prefix, wire `action` is `${prefix}.${KEY}`.

::code-group
```typescript [audit/billing.ts]
import { defineAuditCatalog } from 'evlog'

export const billingAudit = defineAuditCatalog('billing', {
  INVOICE_REFUND: {
    target: 'invoice',
    severity: 'high',
    requiresChanges: true,
    description: 'Refund an invoice to the customer',
    redactPaths: ['cardNumber'],
  },
  INVOICE_CREATE:      { target: 'invoice' },
  INVOICE_VOID:        { target: 'invoice', severity: 'high', requiresReason: true },
  SUBSCRIPTION_CANCEL: { target: 'subscription', severity: 'high' },
})
```
```typescript [server/api/refund.post.ts]
import { billingAudit } from '~/audit/billing'

await log.audit(billingAudit.INVOICE_REFUND({
  actor: { type: 'user', id: user.id },
  target: { id: 'inv_889' }, // type inferred as 'invoice'
}))
```
::

Each entry produces a thin wrapper around `defineAuditAction` (target type is fixed at definition time, action name is auto-prefixed). Catalog metadata is exposed on each factory and on `_actions` / `_prefix`:

```typescript
billingAudit.INVOICE_REFUND.action           // 'billing.INVOICE_REFUND' (literal type)
billingAudit.INVOICE_REFUND.target           // 'invoice'
billingAudit.INVOICE_REFUND.severity         // 'high'
billingAudit.INVOICE_REFUND.requiresChanges // true
billingAudit.INVOICE_REFUND.redactPaths      // ['cardNumber']
billingAudit._actions                        // readonly ['billing.INVOICE_REFUND', ...]
```

| Entry field | Purpose |
|---|---|
| `target` | Default `target.type` injected at call sites |
| `description` | Human-readable label for docs, SIEM rules, review tooling |
| `severity` | `'low' \| 'medium' \| 'high' \| 'critical'`, for alerting and review priority |
| `requiresChanges` | Document that callers should attach `changes` (e.g. via `auditDiff`) |
| `requiresReason` | Document that callers should attach `reason` (especially denials) |
| `redactPaths` | Default paths for `auditDiff({ redactPaths: [...] })` on this action |

### `defineAuditAction` vs `defineAuditCatalog`: when to choose

Both produce the same call-site factory shape. Pick by scale:

- **`defineAuditAction(action, opts?)`**: one-off actions, or per-file organisation in very large repos. Mirrors `defineError`. Equivalent to a catalog with a single entry but with no prefix derivation: you write the full wire `action` directly.
- **`defineAuditCatalog(prefix, map)`**: group anything beyond a handful of related actions under one prefix. Mirrors `defineErrorCatalog`. The wire `action` is auto-derived as `${prefix}.${KEY}`, catalog metadata (`_actions`, `_prefix`) is exposed for introspection, and a single `declare module 'evlog'` line surfaces the whole bundle in the typed `AuditAction` union.

You can mix the two in the same codebase. Keep cross-cutting one-off actions as `defineAuditAction`, group bounded contexts (`billing`, `auth`, `subscription`) as catalogs.

### Type-safe actions everywhere (opt-in)

Mirror the error catalog augmentation by augmenting `RegisteredAuditCatalogs`:

```typescript
import type { billingAudit } from './audit/billing'

declare module 'evlog' {
  interface RegisteredAuditCatalogs {
    billing: typeof billingAudit
  }
}
```

This surfaces the union of all registered actions on the typed `AuditAction` export, useful for shared helpers, dashboards, and refactor-safe comparisons.

## `auditDiff()`

For mutating actions, use `auditDiff()` to produce a compact, redact-aware JSON Patch:

::warning
**Don't feed entire DB rows into `auditDiff()`.** Strip computed columns, hashed passwords, internal flags, and large JSON blobs before diffing. The point of `changes` is *what changed semantically* (status went from `paid` → `refunded`), not *what bytes changed* (a `lastModified` timestamp ticked). A noisy `changes` field is the fastest way to make audit logs unreadable.
::

::code-group

```typescript [Input]
import { auditDiff } from 'evlog'

const before = await db.users.byId(id)
const after = await db.users.update(id, patch)

await log.audit({
  action: 'user.update',
  actor: { type: 'user', id: actorId },
  target: { type: 'user', id },
  changes: auditDiff(before, after, { redactPaths: ['password', 'token'] }),
})
```

```json [Output: changes]
{
  "patch": [
    { "op": "replace", "path": "/email", "value": "new@example.com" },
    { "op": "replace", "path": "/role", "value": "admin" },
    { "op": "replace", "path": "/password", "value": "[REDACTED]" }
  ]
}
```

::

Pass `includeBefore` or `includeAfter` to also store the redacted snapshots next to the patch.

## `withAudit()`: auto-instrumentation

Devs forget to call `log.audit()`. Wrap the function and never miss a record:

::tip
**When to wrap vs. call manually.** Wrap functions that are *pure audit-worthy actions* (refund, delete, role change, password reset): outcome resolution is automatic and you can't accidentally skip the call. Stick to manual `log.audit()` when the audit is one of several decisions inside a larger handler, or when you need to emit the audit *before* the action completes (e.g. "user requested deletion").
::

::code-group

```typescript [Input]
import { withAudit, AuditDeniedError } from 'evlog'

const refundInvoice = withAudit(
  { action: 'invoice.refund', target: input => ({ type: 'invoice', id: input.id }) },
  async (input: { id: string }, ctx) => {
    if (!ctx.actor) throw new AuditDeniedError('Anonymous refund denied')
    return await db.invoices.refund(input.id)
  },
)

await refundInvoice({ id: 'inv_889' }, {
  actor: { type: 'user', id: user.id },
  tenantId: invoice.orgId,
  correlationId: requestId,
})
```

```json [Output: success]
{
  "level": "info",
  "audit": {
    "id": "01a204b0-d5bd-7732-aac0-33dedc5cdd66",
    "timestamp": "2026-11-22T19:17:07.645Z",
    "action": "invoice.refund",
    "actor": { "type": "user", "id": "usr_42" },
    "target": { "type": "invoice", "id": "inv_889" },
    "tenantId": "org_acme",
    "outcome": "success",
    "correlationId": "a566ef91-7765-4f59-b6f0-b9f40ce71599",
    "version": 2
  }
}
```

```json [Output: failure]
{
  "level": "warn",
  "audit": {
    "id": "01a204b0-d5bd-7733-8e54-92d1117ab771",
    "timestamp": "2026-11-22T19:17:07.645Z",
    "action": "invoice.refund",
    "actor": { "type": "user", "id": "usr_42" },
    "target": { "type": "invoice", "id": "inv_889" },
    "tenantId": "org_acme",
    "outcome": "failure",
    "reason": "Stripe error: charge already refunded",
    "correlationId": "a566ef91-7765-4f59-b6f0-b9f40ce71599",
    "version": 2
  }
}
```

```json [Output: denied]
{
  "level": "warn",
  "audit": {
    "id": "01a204b0-d5be-7584-8bab-d468a4bac4bf",
    "timestamp": "2026-11-22T19:17:07.646Z",
    "action": "invoice.refund",
    "actor": { "type": "user", "id": "usr_42" },
    "target": { "type": "invoice", "id": "inv_889" },
    "tenantId": "org_acme",
    "outcome": "denied",
    "reason": "Anonymous refund denied",
    "correlationId": "a566ef91-7765-4f59-b6f0-b9f40ce71599",
    "version": 2
  }
}
```

::

Outcome resolution:

- `fn` resolves: `outcome: 'success'`.
- `fn` throws an `AuditDeniedError` (or any error with `status === 403`): `outcome: 'denied'`, and the error message becomes `reason`.
- Other thrown errors: `outcome: 'failure'`, then re-thrown.

The wrapper waits for the record to be stored before it returns or re-throws. It records through standalone `audit()`, so the record has no request context: pass `correlationId: requestId` to join it to the request.
