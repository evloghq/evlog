`createSignals(options)` takes your signals and returns one evlog [plugin](/extend/plugins) with a `keep` hook, an `enrich` hook, and a `stats()` reader. Every option below has a default that runs, so the only required field is `signals`.

| Option | Default | Notes |
| --- | --- | --- |
| `signals` | | The signals to run. Names must be unique, or `createSignals` throws at startup. |
| `model` | `'typesafe-ai/jev'` | AI SDK evaluation model: a gateway id or a provider instance. |
| `budget.perMinute` | `600` | Model calls per minute, shared by all signals, per process. |
| `budget.cooldownMs` | `30000` | How long to stop calling the model after a failed call. |
| `timeoutMs` | `2000` | Per call. A call that overruns is aborted and counts as an error. |
| `state` | whole event minus signal columns | What the model reads. |
| `maxStateChars` | `100000` | Largest state sent, in characters of JSON. Larger events are skipped. |
| `providerOptions` | | Forwarded to the model call, e.g. `{ gateway: { zeroDataRetention: true } }`. |
| `evaluate` | AI SDK `experimental_evaluate` | Replace the model call. Tests, record and replay. |

## Pick the model

The default is `typesafe-ai/jev` through Vercel AI Gateway. It reads `AI_GATEWAY_API_KEY`, or OIDC when the process runs on Vercel, and needs no code. For a direct TypeSafe key, install `@ai-sdk/typesafe-ai` and pass its `jev` model instance as `model`.

Any model that implements the AI SDK evaluation contract works. One that returns text instead of a probability distribution fails every call: the plugin counts it in `stats().errors`, warns with the model id, and the events pass through unjudged. The model id that answered is stamped on every judged event as `signalsModel`, so you can tell verdicts from two models apart in your drain.

## Cap what it costs

`budget.perMinute` is a fixed one-minute window, and `budget.cooldownMs` is a circuit breaker. Both fail open: when the window is spent or a call just failed, events flow through unjudged and `stats().skipped` goes up. Nothing queues, nothing retries, and the request path never waits on a budget.

The limit that binds in practice is the account rate, 1,200 requests per minute per TypeSafe account, about 20 a second. `budget.perMinute` is per process, so with four instances on one account set it to 300 and let the breaker absorb a stray 429.

Signals that share a `when` share a call: all signals due for one event go into a single request, so a second question costs one more question in the prompt, not one more slot of the budget.

## Bound what the model reads

By default the model reads the whole wide event, minus the `signals` and `signalsModel` columns. That is the right default for accuracy and the wrong one for two things: tokens, which you pay for, and egress, since a keep signal runs before redaction and sees the request context as your handlers logged it.

`state` picks the fields:

```typescript
createSignals({
  signals,
  state: e => ({
    status: e.status,
    path: e.path,
    durationMs: e.durationMs,
    error: e.error,
    payment: e.payment,
  }),
})
```

`state` may also return a string when you want to hand the model a rendered summary instead of JSON. `maxStateChars` is the backstop: an event whose state serializes past it is skipped rather than failing the call for the events batched with it.

`providerOptions` is passed through untouched. `{ gateway: { zeroDataRetention: true } }` is the one to set when the gateway must not store what it saw.

## Read the counters

`plugin.stats()` returns a snapshot. Expose it on a health route or push it to your metrics on a timer:

```typescript
const plugin = createSignals({ signals })

plugin.stats()
// { calls: 412, skipped: 3, errors: 1, cached: 1180, inputTokens: 618000 }
```

| Field | Counts |
| --- | --- |
| `calls` | Model calls made. |
| `skipped` | Events with due signals that were not judged: budget spent, breaker open, or state over `maxStateChars`. |
| `errors` | Calls that failed or timed out. |
| `cached` | Verdicts served from a `cacheKey` without a call. |
| `inputTokens` | Tokens billed, as reported by the model. |

`cached` next to `calls` tells you what [`cacheKey`](/use-cases/signals/define#collapse-an-error-storm-with-cachekey) saved. `skipped` climbing while `errors` stays flat means the budget is too low for your traffic, not that the model is down.

## Script the model in tests

`@evlog/signals/testing` ships `scriptedEvaluate`, an `evaluate` function that answers from a callback instead of a model and records every request it received. Pass it as `evaluate` and no key, no network, and no budget are involved:

```typescript [signals.test.ts]
import { createSignals } from '@evlog/signals'
import { answers, scriptedEvaluate } from '@evlog/signals/testing'

const mock = scriptedEvaluate((name, question) => {
  if (name === 'fault') return answers.choice(question, 'upstream', 0.93)
  return answers.first(question)
})

const plugin = createSignals({ signals, evaluate: mock.evaluate })

// after running a request through evlog
expect(mock.calls).toHaveLength(1)
expect(mock.calls[0].questions).toHaveProperty('fault')
```

`answers` builds responses with a full probability distribution, the shape a decision model returns: `answers.boolean(p)`, `answers.choice(question, pick, p)`, `answers.score(question, levelIndex, p)`, and `answers.first(question)` for a confident default of the right type. The callback receives the state too, so a mock can read the same fields a model would. The playground does this when `AI_GATEWAY_API_KEY` is unset, labelled `mock (not jev)` in `signalsModel`.

The same hook replays recorded verdicts: wrap a map of `requestId` to answers in `scriptedEvaluate` and the catalog runs against yesterday's events without a call.
