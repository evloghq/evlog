Your logs tell you a request returned 502. A signal tells you it was Stripe, that a retry would have worked, and that it is not worth waking anyone. Your logs tell you a checkout returned 200. A signal tells you the customer left without an order.

`@evlog/signals` asks a decision model one question per event and writes the answer onto the event as a column, with a confidence. You query it like any other field.

## What you get

Fifteen requests through the package's demo, twelve signals, `info` sampled at 0%:

```text [pnpm --filter @evlog/signals demo -- --mock]
request                status  outcome                  signals
checkout-silent        200     kept by silent-failure   silent-failure=yes 0.93
checkout-upstream      502     kept (error)             fault=upstream 0.93  severity=watch 0.60  retryable=yes 0.90
orders-bug             500     kept (error)             fault=us 0.91        severity=page 0.78   retryable=no 0.92
signup-validator-bug   400     kept by validation-bug   fault=us 0.72        validation-bug=yes 0.90
webhook-dropped        200     kept by webhook-ignored  webhook-ignored=yes 0.95
agent-looping          200     kept by turn-looping     turn-looping=yes 0.94
audit-export           200     kept by audit-review     audit-review=yes 0.88
checkout-ok            200     sampled out              -
...

15 requests, info sampled at 0%: 8 drained
model calls 14, input tokens 1569, estimated cost $0.00007
```

Three things happened there that a rule could not have done:

- **Every error got a reason.** `fault=upstream` on the Stripe reset, `fault=us` on the null deref. Two 5xx that look identical on a status chart are now two rows in a `GROUP BY`. Over a week that is a number: how much of your error budget is yours.
- **Five requests that sampling deleted came back.** A checkout that said "we will email you shortly" instead of creating an order. A valid email rejected by your validator. A webhook acknowledged and dropped. An agent looping on the same tool call. None of them had a status code that said anything was wrong.
- **It cost seven thousandths of a cent.** Fourteen model calls, 1,569 input tokens, no key in evlog's hands. [What It Costs](/use-cases/signals/cost) has what that becomes at your traffic.

Run it yourself: `pnpm --filter @evlog/signals demo -- --mock` uses scripted answers. Drop the flag with `AI_GATEWAY_API_KEY` set to call the model.

## Add your first signal

Add @evlog/signals to my evlog app.

- Install: pnpm add @evlog/signals ai (ai 7.0.105 or later)
- Define signals with defineSignal({ name, when, ask }) plus choice: {...} for a pick-one answer or score: [...] for a rubric; keep: v => ... promotes the event past sampling
- Register with createSignals({ signals }): on Nuxt or Nitro hook plugin.keep on 'evlog:emit:keep' and plugin.enrich on 'evlog:enrich' in a server plugin; on Next.js or standalone pass it in initLogger({ plugins: [...] }); on Hono, Express, Fastify or Elysia pass it in the middleware's plugins option
- Set AI_GATEWAY_API_KEY (default model typesafe-ai/jev through AI Gateway)
- Verdicts land on event.signals.<name>.{ value, confidence } through drains, not in console output
- In tests, pass evaluate from scriptedEvaluate() in @evlog/signals/testing so no model is called

Docs: https://www.evlog.dev/use-cases/signals/overview

::

::steps{level="3"}

### Install

```bash [Terminal]
pnpm add @evlog/signals ai
```

The default model is `typesafe-ai/jev` through Vercel AI Gateway. Set `AI_GATEWAY_API_KEY`, or nothing on Vercel, where OIDC is picked up.

### Write the question

A signal is a name, a predicate that decides which events it applies to, and the question. This one labels every failure:

```typescript [server/signals.ts]
import { defineSignal } from '@evlog/signals'

export const fault = defineSignal({
  name: 'fault',
  when: e => (e.status ?? 0) >= 400,
  ask: 'Who is responsible for this failure?',
  choice: {
    user: 'Bad input, expired session, client mistake',
    us: 'A bug or misconfiguration in our own code',
    upstream: 'A third-party dependency failed',
  },
})
```

### Register it

`createSignals` returns an evlog plugin. On Nuxt and Nitro, hook its two functions in a server plugin:

```typescript [server/plugins/evlog-signals.ts]
import { createSignals } from '@evlog/signals'
import { fault } from '../signals'

export default defineNitroPlugin((nitroApp) => {
  const plugin = createSignals({ signals: [fault] })
  nitroApp.hooks.hook('evlog:emit:keep', plugin.keep)
  nitroApp.hooks.hook('evlog:enrich', plugin.enrich)
})
```

:::collapsible{name="other frameworks"}

Every other integration takes the plugin in its `plugins` array:

::::code-group
```typescript [Next.js / standalone]
import { initLogger } from 'evlog'
import { createSignals } from '@evlog/signals'
import { fault } from './signals'

initLogger({ plugins: [createSignals({ signals: [fault] })] })
```

```typescript [Hono]
import { evlog } from 'evlog/hono'
import { createSignals } from '@evlog/signals'
import { fault } from './signals'

app.use(evlog({ plugins: [createSignals({ signals: [fault] })] }))
```

```typescript [Express]
import { evlog } from 'evlog/express'
import { createSignals } from '@evlog/signals'
import { fault } from './signals'

app.use(evlog({ plugins: [createSignals({ signals: [fault] })] }))
```
::::

### Read the column

The next 500 that reaches your drain carries the answer:

```json [Wide Event]
{
  "method": "POST",
  "path": "/api/checkout",
  "status": 502,
  "error": { "name": "FetchError", "message": "request to https://api.stripe.com/... failed, reason: read ECONNRESET" },
  "signals": {
    "fault": { "value": "upstream", "confidence": 0.93 }
  },
  "signalsModel": "jev-1.13.0"
}
```

`value` is the answer, `confidence` is its probability. Columns arrive through [drains](/integrate/adapters/overview); console output is written before enrichment, so they do not appear in the dev terminal.

::

## Then keep what sampling drops

Add `keep` to a signal and a `true` verdict forces the event past sampling. This is the signal that rescued the silent checkout above:

```typescript [server/signals.ts]
export const silentFailure = defineSignal({
  name: 'silent-failure',
  when: e => e.status === 200 && e.path === '/api/checkout',
  ask: 'Returned 200, but the customer did not get what they came for',
  keep: v => v.value && v.confidence > 0.8,
})
```

`keep` only promotes. It never drops an event a [sampling rule](/learn/sampling) would have kept, and the promoted event carries `kept: true` on the column so your counts stay honest.
