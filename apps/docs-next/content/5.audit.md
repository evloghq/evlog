An auditor asks who refunded invoice 1842, and who tried to without permission. A request log answers how a request behaved. An audit event answers who tried to do what, and whether it was allowed.

```typescript [route:POST /api/invoices/refund]
log.audit({
  action: 'invoice.refund',
  actor: { type: 'user', id: user.id, email: user.email },
  target: { type: 'invoice', id: invoice.id },
  outcome: 'success',
  reason: 'Customer requested refund',
})
```

An audit event is a wide event with a reserved `audit` field. Drains, enrichers, redaction and sampling rules apply to it as they are; there is no second logging library and no parallel pipeline.

::audit-force-keep
::

## Turn it on

One enricher and one drain wrapper, next to the drain you already have:

```typescript [server/plugins/evlog.ts]
import { auditEnricher, auditOnly, signed } from 'evlog'
import { createAxiomDrain } from 'evlog/axiom'
import { createFsDrain } from 'evlog/fs'

export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('evlog:enrich', auditEnricher())
  nitro.hooks.hook('evlog:drain', createAxiomDrain())
  nitro.hooks.hook('evlog:drain', auditOnly(
    signed(createFsDrain({ dir: '.audit' }), { strategy: 'hash-chain' }),
    { await: true },
  ))
})
```

| Piece | What it does |
| --- | --- |
| `auditEnricher()` | Adds the request id, trace id, IP and user agent to `audit.context`, and the actor from Better Auth when you set none |
| `auditOnly(drain)` | Sends only audit events to that drain. `{ await: true }` flushes them before the response returns |
| `signed(drain, { strategy })` | Chains each event to the previous one (`hash-chain`) or signs it with a secret (`hmac`), so an edit or a deletion is detectable |

## Record a denial

The action that was refused is the one an auditor asks about first, and the one most teams forget to log:

```typescript [route:POST /api/invoices/refund]
if (!user.canRefund(invoice)) {
  log.audit.deny('Insufficient permissions', {
    action: 'invoice.refund',
    actor: { type: 'user', id: user.id },
    target: { type: 'invoice', id: invoice.id },
  })
  throw createError({ status: 403, message: 'Forbidden' })
}
```

## Name your actions

`defineAuditCatalog` gives each action a typed factory, the same way [error catalogs](/errors/catalogs) do for errors:

```typescript [src/audit.ts]
import { defineAuditCatalog } from 'evlog'

export const audit = defineAuditCatalog('app', {
  USER_LOGIN: { target: 'user', severity: 'medium' },
  USER_DELETE: { target: 'user', severity: 'high', requiresChanges: true, requiresReason: true },
})
```

Audit events are always kept: [sampling](/events/sampling) never drops them. The `build-audit-logs` [skill](/skills) walks an agent through the policy, the wiring and the review.
