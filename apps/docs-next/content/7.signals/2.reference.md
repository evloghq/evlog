Every option, field and counter of `@evlog/signals`, with its default. [Signals](/signals) shows how the parts fit together.

```bash [Terminal]
pnpm add @evlog/signals ai
```

`ai` 7.0.130 or later (below 8) and `evlog` 3 are peer dependencies. The package has two entry points:

| Entry point | Exports |
| --- | --- |
| `@evlog/signals` | `defineSignal`, `createSignals`, `knownError`, `clientFault`, `errorFingerprint`, and the types |
| `@evlog/signals/testing` | `scriptedEvaluate`, `answers` |

## defineSignal

`defineSignal(options)` validates its input and returns a `Signal`. The shape of the answer follows the input: `ask` alone is a yes or no, `ask` with `choice` picks an option, `ask` with `score` places the event on a rubric.

| Option | Type | What it does |
| --- | --- | --- |
| `name` | `string` | Column name under `event.signals`. Letters, digits and dashes, starting with a letter. Unique across the signals of one plugin |
| `ask` | `string` | The question, in plain English |
| `when` | `(event) => boolean` | Predicate over the event. No model call when it returns `false`. Required with `keep` |
| `choice` | `Record<option, description>` | At least two options, each with the description the model matches against. Makes a choice signal |
| `score` | `[level, level, ...]` | Levels ordered lowest first, at least two. Makes a score signal |
| `criteria` | `{ true?, false? }` | Yes or no signals only. What makes each answer true |
| `keep` | `(verdict) => boolean`, or a number on a yes or no signal | Promotes the event past sampling when it returns `true`. It never drops an event. `keep: 0.8` keeps a yes with a confidence above 0.8 |
| `cacheKey` | `(event) => string \| undefined` | Events that return the same key share one verdict. `undefined` skips the cache |

`keep` is typed on the verdict the shape produces, so `v.value === 'app'` is checked against the options of a choice signal.

`defineSignal` throws when the signal is defined, on:

- a name that does not match the pattern,
- an empty `ask`,
- `keep` without `when`,
- a `keep` number outside `[0, 1)`,
- fewer than two options in `choice` or two levels in `score`.

### What a signal sees

`when` and `cacheKey` receive the wide event in `enrich`, or the request context plus `status`, `path`, `method` and `durationMs` in `keep`. Five fields are typed: `status`, `path`, `method`, `durationMs` and `requestId`. Everything your handlers logged is there as `unknown`.

### The signal object

| Field | What it holds |
| --- | --- |
| `kind` | `'boolean'`, `'choice'` or `'score'` |
| `name`, `ask`, `when`, `cacheKey` | What you passed |
| `keep` | Your function, or the function built from the number |
| `criteria`, `choice`, `score` | The one that matches `kind` |
| `read(event)` | This signal's column on a judged event, typed on its options or levels, or `undefined` when the event was not judged |

Use `read` where code acts on a verdict, such as a retry policy:

```typescript [server/jobs/retry.ts]
if (retryable.read(event)?.value) await queue.retry(job)
```

## createSignals

`createSignals(options)` returns a `SignalsPlugin`: an evlog [plugin](/reference/plugins) with `name`, `keep`, `enrich` and `stats()`. Only `signals` is required.

| Option | Default | What it does |
| --- | --- | --- |
| `signals` | required | The signals to run. A duplicate name throws at startup |
| `name` | `'signals'` | Plugin name. evlog keeps one plugin per name, so a second instance, such as one for client events with its own budget, needs its own |
| `model` | `'typesafe-ai/jev'` | AI SDK decision model: a gateway id or a provider instance. See [Pick the model](#pick-the-model) |
| `budget.perMinute` | `600` | Model calls per minute, shared by all signals, per process |
| `budget.keepShare` | `0.25` | Share of `perMinute` that only `keep` signals spend |
| `budget.maxConcurrent` | `16` | Model calls in flight at once. An event past it passes through unjudged and counts as `skipped`. Nothing queues |
| `budget.cooldownMs` | `30000` | Pause after three failed calls in a row |
| `cacheTtlMs` | `300000` | How long a `cacheKey` verdict is reused before the next event with that key asks again |
| `timeoutMs` | `2000` | Per call. An overrun aborts the call and counts as an error |
| `state` | Whole event minus `signals` and `signalsModel` | `(event) => string \| object`: what the model reads |
| `maxStateChars` | `100000` | Largest state sent, in characters of JSON. A larger event is skipped |
| `providerOptions` | none | Forwarded to the model call, keyed by provider name, for example `{ gateway: { zeroDataRetention: true } }` |
| `evaluate` | AI SDK `experimental_decide` | Replaces the model call. For tests, and for record and replay |
| `stampModel` | `false` | Also writes the answering model's id on `event.signalsModel`, keyed by plugin `name` |

The cache holds the last 1,000 verdicts of each plugin instance.

All signals due for one event go into a single model call. When a `keep` signal is due, every other due signal is asked in that call, so `enrich` does not make a second one. If the model refuses a call that other signals rode along on, the `keep` signals are asked again on their own.

`evaluate` receives `{ model, state, questions, abortSignal, providerOptions }` and resolves to `{ answers, modelId, inputTokens? }`. `questions` and `answers` are keyed by signal name.

## Register the plugin

| Where | How |
| --- | --- |
| Nuxt, Nitro, TanStack Start | In a server plugin: `nitroApp.hooks.hook('evlog:emit:keep', plugin.keep)` and `nitroApp.hooks.hook('evlog:enrich', plugin.enrich)` |
| `evlog.config.ts` | `defineEvlog({ plugins: [plugin] })` |
| Next.js, standalone | `initLogger({ plugins: [plugin] })` |
| Hono, Express, Fastify, Elysia, NestJS, oRPC, SvelteKit, React Router, Cloudflare Workers | The integration's `plugins` option, as in `evlog({ plugins: [plugin] })` |
| `createMiddlewareLogger` from `evlog/toolkit` | `plugins: [plugin]` on the call |

[Signals](/signals#ask-your-first-question) has the snippet for each framework.

## Pick the model

`model` takes a gateway id as a string, or a provider instance. A provider reads its own options from `providerOptions`, keyed by provider name.

### AI Gateway

The default. It reads `AI_GATEWAY_API_KEY`, or OIDC on Vercel with no key at all.

```typescript [evlog.config.ts]
createSignals({
  model: 'typesafe-ai/jev',
  signals: [fault, silentFailure],
})
```

`liquid/d1` is another decision model on the gateway. Both return a probability distribution, so every column has a `confidence`. To compare two models, change the id and set `stampModel: true`, so the verdicts of each can be told apart in the drain.

### TypeSafe AI

A direct key to the model behind the default. Install `@ai-sdk/typesafe-ai`. It reads `TYPESAFE_AI_API_KEY`.

```typescript [evlog.config.ts]
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

createSignals({
  model: typeSafeAi.evaluationModel('jev-latest'),
  signals: [fault, silentFailure],
})
```

The distributions and the columns are the same as through the gateway.

### OpenAI

A general model prompted to answer. Install `@ai-sdk/openai`. It reads `OPENAI_API_KEY`.

```typescript [evlog.config.ts]
import { openai } from '@ai-sdk/openai'

createSignals({
  model: openai.evaluationModel('gpt-6-luna'),
  signals: [fault, silentFailure],
})
```

A prompted model returns the probability of yes for a yes or no question, and a bare answer for choice and score. Those columns carry `value` without `confidence`. The call is slower than a decision model's, so raise `timeoutMs` if `stats().errors` climbs.

Any other provider that exposes `evaluationModel()` plugs in the same way.

## The column

A verdict lands on `event.signals.<name>`.

| Shape | `value` | `confidence` | Extra |
| --- | --- | --- | --- |
| Yes or no | `boolean` | Probability of `value`, always present | |
| Choice | One of the option names | Probability of that option, when the model returns a distribution | |
| Score | The most likely level name | Probability of that level, when the model returns a distribution | `score`: probability-weighted position, from `0` to `levels - 1` |

Two more fields can appear on any column:

| Field | When | Meaning |
| --- | --- | --- |
| `kept: true` | The signal promoted the event past sampling | Lets you count promoted events apart from sampled ones |
| `rate` | The budget skipped events before this one | The verdict stands for `1 / rate` events. See [How the budget is spent](#how-the-budget-is-spent) |

```typescript [Types]
interface BooleanVerdict { value: boolean; confidence: number }
interface ChoiceVerdict<Option extends string> { value: Option; confidence?: number }
interface ScoreVerdict<Level extends string> { value: Level; score: number; confidence?: number }
type SignalColumn = Verdict & { kept?: true, rate?: number }
```

With `stampModel: true`, the model's id is on `event.signalsModel`, keyed by plugin name (`signals` for the default instance), as the model reported it. Two named instances that judge one event each keep their own id.

Columns are written in `enrich`, before the console line. They reach stdout, platform logs such as Vercel, and every [drain](/drains). The response is already sent by then. The console line waits for the model, for at most `timeoutMs` per call, so a late line in the dev terminal is the model and not a slow request.

## How the budget is spent

`budget.perMinute` is a token bucket per process, refilled evenly over the minute. It holds 10 seconds of budget, so a spike after a quiet hour spends at most a sixth of `perMinute` at once: 100 calls at the default.

`budget.keepShare` reserves a quarter of it for `keep` signals. A storm of 5xx judged in `enrich` cannot starve the signal that decides which checkouts to keep. `keep` signals fall back on the rest when their share runs out, and `enrich` signals never touch the reserved share.

When events arrive faster than the budget refills, each one is judged with the probability the budget can afford. A spike is sampled evenly instead of judging its first seconds and nothing after. A verdict judged after skipped events carries `rate`: it stands for `1 / rate` events, itself and the ones skipped since the last call of the same kind (`keep` or `enrich`). `sum(1 / rate)` over judged events estimates how many events the spike had.

Three failed calls in a row open a breaker for `budget.cooldownMs`. A 429 or an outage at the model costs a 30 s gap in verdicts and no queue. One slow call does not open it, and a refusal never counts as a failure. Events skipped while the breaker is open, or for an oversized state, are not counted in `rate`.

A failed call prints one `console.warn` that starts with `[evlog/signals]`. The event drains unjudged.

## stats()

`plugin.stats()` returns a snapshot of the counters of this plugin instance:

| Field | Counts |
| --- | --- |
| `calls` | Model calls made |
| `skipped` | Events with due signals that were not judged: budget spent, `maxConcurrent` calls already running, breaker open, or state over `maxStateChars` |
| `errors` | Calls that failed or timed out |
| `refused` | Calls the model declined to answer. No verdict is written and the breaker stays closed |
| `cached` | Verdicts served from a `cacheKey` without a call, including events that waited on a call already running for the same key |
| `inputTokens` | Tokens billed, as reported by the model |

`cached` next to `calls` is what `cacheKey` saved. `skipped` climbing while `errors` stays flat means the budget is below your traffic, and the model is up.

## Ready-made signals and keys

### knownError

`knownError(errors)` returns a choice signal named `known-error`, built from your [error catalogs](/errors/catalogs). `errors` is an array of catalogs from `defineErrorCatalog`, factories from `defineError`, or both. [Recipes](/signals/recipes#match-raw-errors-to-your-catalog) shows it on real errors.

| Part | Value |
| --- | --- |
| Options | One per entry `code`, described by its string `message` and its `why`, or by the code alone when it has neither. Plus `new` for a failure none of them describes |
| `when` | The event has an `error` whose `code` is not one of the catalog's |
| `cacheKey` | The error's name and message |

It throws on an empty list and on an entry whose code is `new`.

### clientFault

`clientFault` is a choice signal named `client-fault` for errors logged in the browser. [Recipes](/signals/recipes#triage-browser-errors) shows how to register it on its own instance.

| Part | Value |
| --- | --- |
| Options | `app`, `network`, `third-party`, `browser` |
| `when` | `source` is `'client'` and `level` is `error` or `fatal` |
| `cacheKey` | The error's name and message, or the `tag` and `message` of a log line without an error object |

### errorFingerprint

`errorFingerprint` is a `cacheKey` function. It keys on the error's name and message, with timestamps, UUIDs, emails, hex ids, prefixed ids such as `ch_3Pq…` and numbers replaced by placeholders. Two messages that differ only by ids share one verdict. It returns `undefined` for an event without an `error`.

```typescript [server/signals.ts]
defineSignal({ name: 'retryable', when: e => (e.status ?? 0) >= 500, ask: '…', cacheKey: errorFingerprint })
```

## Testing

`@evlog/signals/testing` replaces the model with a script. It needs no key and no network. The budget still applies to a scripted `evaluate`, so raise `budget.perMinute` in a test that judges many events at once.

```typescript [signals.test.ts]
import { createSignals } from '@evlog/signals'
import { answers, scriptedEvaluate } from '@evlog/signals/testing'

const mock = scriptedEvaluate((name, question) =>
  question.type === 'choice' ? answers.choice(question, 'upstream', 0.93) : answers.first(question),
)

const plugin = createSignals({ signals, evaluate: mock.evaluate })

// after a request has run through evlog
expect(mock.calls).toHaveLength(1)
expect(mock.calls[0].questions).toHaveProperty('fault')
```

| Export | What it does |
| --- | --- |
| `scriptedEvaluate(answer, modelId?)` | Returns `{ evaluate, calls }`. `answer(name, question, state)` runs once per question, and `calls` records every request in order. `modelId` is `'scripted'` by default |
| `answers.boolean(p)` | A yes or no answer where the probability of yes is `p` |
| `answers.choice(question, pick, p)` | Picks `pick` at `p` and spreads the rest over the other options |
| `answers.score(question, levelIndex, p)` | Level `levelIndex` at `p`, with the weighted `score` computed |
| `answers.first(question)` | A confident default of the right type: first option at 0.9, last level at 0.8, yes at 0.94 |

`answers.choice` and `answers.score` take a question of their own type, so narrow on `question.type` first.

The same hook replays recorded verdicts. A `scriptedEvaluate` that looks answers up by `requestId` runs your signals against yesterday's events without a call.
