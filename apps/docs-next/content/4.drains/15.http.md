Server events tell you what the backend did. The clicks, page views and frontend errors that never reach it stay in the user's console unless you ship them. The HTTP drain batches browser logs and posts them to an endpoint on your server.

```typescript [app.ts]
import { initLogger, log } from 'evlog'
import { createHttpLogDrain } from 'evlog/http'

initLogger({
  drain: createHttpLogDrain({ drain: { endpoint: '/api/_evlog/ingest' } }),
})

log.info({ action: 'page_view', path: location.pathname })
```

## What it does in the browser

1. `log.info()`, `log.warn()` and `log.error()` push events into a buffer.
2. The buffer is sent every 25 events or every 2 seconds, whichever comes first.
3. Requests use `fetch` with `keepalive`, so a batch survives a page navigation.
4. When the tab is hidden, what is left in the buffer goes out with `navigator.sendBeacon`.

Your endpoint receives a JSON array of events. On Nuxt, the module serves one: set `transport: { enabled: true }` in `nuxt.config.ts`, and client events reach your drain with `source: 'client'`, after the same sampling rates as server events.
