Server events tell you what the backend did. The clicks, page views and frontend errors that never reach it stay in the user's console unless you ship them. The HTTP drain batches browser logs and posts them to an endpoint on your server.

```typescript [app.ts]
import { initLogger, log } from 'evlog'
import { createHttpLogDrain } from 'evlog/http'

initLogger({
  drain: createHttpLogDrain({ drain: { endpoint: '/v1/ingest' } }),
})

log.info({ action: 'page_view', path: location.pathname })
```

## What it does in the browser

1. `log.info()`, `log.warn()` and `log.error()` push events into a buffer.
2. The buffer is sent every 25 events or every 2 seconds, whichever comes first.
3. Requests use `fetch` with `keepalive`, so a batch survives a page navigation.
4. When the tab is hidden, what is left in the buffer goes out with `navigator.sendBeacon`.

Your endpoint receives a JSON array of events, so it is a route you write: see [The server endpoint](#the-server-endpoint). Do not point this drain at `/api/_evlog/ingest`, the route the Nuxt module serves for the [client transport](/events/client). That route accepts one event per request and answers `400` to an array.

## Options

`createHttpLogDrain({ drain, pipeline, autoFlush })` is the pre-composed form. It returns a [pipeline](/drains/pipeline) drain, with `flush()`, `pending` and `stats()`, plus `dispose()` to remove its `visibilitychange` listener.

| Option | Default | What it does |
| --- | --- | --- |
| `drain` | required | The transport options in the next table |
| `pipeline` | `{ batch: { size: 25, intervalMs: 2000 }, retry: { maxAttempts: 2 } }` | Pipeline options. A `batch` or `retry` object you pass replaces the default one whole, so set both of its keys |
| `autoFlush` | `true` | Flushes the buffer when the page becomes hidden |

| `drain` option | Default | What it does |
| --- | --- | --- |
| `endpoint` | required | URL of the ingest endpoint on your server |
| `headers` | | Headers sent with each `fetch` request, such as `Authorization` or `X-API-Key` |
| `timeout` | `5000` | Milliseconds before a request is aborted |
| `useBeacon` | `true` | Uses `sendBeacon` when the page is hidden |
| `credentials` | `'same-origin'` | The fetch credentials mode: `'omit'`, `'same-origin'` or `'include'`. Set `'include'` for a cross-origin endpoint |

`createHttpDrain(config)` is the transport on its own. Use it to build the pipeline yourself:

```typescript [app.ts]
import { createHttpDrain } from 'evlog/http'
import { createDrainPipeline } from 'evlog/pipeline'
import type { DrainContext } from 'evlog'

const transport = createHttpDrain({
  endpoint: 'https://logs.example.com/v1/ingest',
})
const pipeline = createDrainPipeline<DrainContext>({
  batch: { size: 100, intervalMs: 10000 },
  retry: { maxAttempts: 5 },
})

const drain = pipeline(transport)
```

## Protect the endpoint

Pass `headers` to authenticate the request:

```typescript [app.ts]
const drain = createHttpLogDrain({
  drain: {
    endpoint: 'https://logs.example.com/v1/ingest',
    headers: {
      'Authorization': 'Bearer ' + token,
    },
  },
})
```

`sendBeacon` cannot send custom headers, so a batch sent while the page is hidden arrives without them. When your endpoint requires authentication, check a session cookie instead, with `credentials: 'include'` for a cross-origin endpoint, or set `useBeacon: false`.

Browsers also cap a `sendBeacon` payload at about 64 KB, and the drain throws when the browser refuses one. The default batch of 25 events stays well under that.

## The server endpoint

You write the endpoint: a POST route that accepts a JSON array of `DrainContext`, each one `{ event }`.

::framework-tabs
```typescript [Express] src/index.ts
app.post('/v1/ingest', express.json(), (req, res) => {
  for (const entry of req.body) {
    console.log('[BROWSER]', JSON.stringify(entry))
  }
  res.sendStatus(204)
})
```
```typescript [Hono] src/index.ts
app.post('/v1/ingest', async (c) => {
  const body = await c.req.json()
  for (const entry of body) {
    console.log('[BROWSER]', JSON.stringify(entry))
  }
  return c.body(null, 204)
})
```
::

The [browser example](https://github.com/evloghq/evlog/tree/main/examples/browser) is a working Hono server with a browser page.

## Identity headers

Every HTTP request a drain sends says it comes from evlog, so the receiver can tell that traffic apart, follow an evlog upgrade through the `User-Agent` values, or isolate one drain:

| Header | Value |
| --- | --- |
| `User-Agent` | `evlog/<version>`, on server runtimes only |
| `X-Evlog-Source` | The drain's name: `axiom`, `datadog`, `otlp`, `posthog`, `sentry`, `better-stack`, and so on |

A browser does not let a script set `User-Agent`, so the HTTP drain on this page sends only `X-Evlog-Source: client`, and only on `fetch` requests: a `sendBeacon` batch carries neither header.

A [custom drain](/drains/custom) built with `defineHttpDrain()` sends both without any code: its `name` becomes `X-Evlog-Source`. `EVLOG_VERSION` and `EVLOG_USER_AGENT` are exported from `evlog/toolkit` for a drain or a receiver that needs the exact values.

A drain built on `httpPost` directly sets them with `source` and `userAgent`:

```typescript [lib/my-platform-drain.ts]
import { httpPost } from 'evlog/toolkit'

await httpPost({
  url: 'https://my-platform.example.com/ingest',
  headers: { 'Content-Type': 'application/json' },
  body: '[]',
  timeout: 5000,
  label: 'my-platform',
  source: 'my-platform',           // sent as X-Evlog-Source
  userAgent: 'my-fork/1.0',        // overrides the default User-Agent
  // userAgent: false,             // suppress the header entirely
})
```

Without `source`, `httpPost` sends no `X-Evlog-Source`. A `User-Agent` or `X-Evlog-Source` already present in `headers` is kept as it is.
