[Sazabi](https://sazabi.com) reads your logs and answers questions about them. The drain sends each wide event to a log stream as one OTLP record, with nested fields flattened to attributes such as `user.plan` that Sazabi can filter on.

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { createSazabiDrain } from 'evlog/sazabi'

export default defineEvlog({
  service: 'my-app',
  drain: createSazabiDrain(),
})
```

## Credentials

Copy the intake URL of a log stream. The stream's public key is part of the URL, so there is no header to set:

```bash [.env]
SAZABI_INTAKE_URL=https://your-key.us-west-2.intake.sazabi.com
```

evlog appends `/v1/logs`. A URL that already ends with it is used as is.

## Options

| Option | Env | What it is |
| --- | --- | --- |
| `endpoint` | `SAZABI_INTAKE_URL` | The stream's intake URL |
| `serviceName` | `SAZABI_SERVICE_NAME`, `OTEL_SERVICE_NAME` | `service.name` on the resource |
| `resourceAttributes` | | Extra resource attributes |
| `recordShape` | | `'compact'` by default: a one-line body and dotted attributes. `'json'` sends the whole event as the body |
| `semanticConventions` | | `true` by default: also emits `http.request.method`, `url.path`, `exception.*` and the like |
| `timeout` | | Request timeout in ms, `5000` by default |
| `retries` | | Retries on a transient failure, `2` by default |

On Nuxt, each variable also reads with a `NUXT_` prefix, such as `NUXT_SAZABI_INTAKE_URL`.
