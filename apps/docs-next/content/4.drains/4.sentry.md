title: Sentry
description: "Send wide events to Sentry Logs, and open an issue for each server error with the trace id of the request that threw it."

::product-facts{entry="evlog/sentry" status="stable"}
::

The drain sends every wide event to [Sentry Logs](https://docs.sentry.io/product/explore/logs/), with the event's fields as attributes. Turn on `issues` and the events that ended in a server error also open Sentry issues.

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { createSentryDrain } from 'evlog/sentry'

export default defineEvlog({
  service: 'my-app',
  drain: createSentryDrain({ issues: true }),
})
```

## Credentials

The drain needs the project DSN, from the project's Client Keys settings:

```bash [.env]
SENTRY_DSN=https://key@o0.ingest.sentry.io/0
```

`environment` and `release` come from the event's own `environment` and `version` unless you set `SENTRY_ENVIRONMENT` or `SENTRY_RELEASE`.

## Issues

With `issues: true`, an `error` or `fatal` event is sent twice: once as a log, once as an error event that opens an issue and triggers your alert rules. The issue carries the event's `trace_id`, so it links back to the log of the same request.

An event with a 4xx status stays a log. A declined card or an expired session is the client's doing, and should not page anyone.

## Options

| Option | Env | What it is |
| --- | --- | --- |
| `dsn` | `SENTRY_DSN` | The project DSN |
| `environment` | `SENTRY_ENVIRONMENT` | Overrides the event's `environment` |
| `release` | `SENTRY_RELEASE` | Overrides the event's `version` |
| `tags` | | Extra attributes on every log |
| `issues` | | Also open issues for server errors, `false` by default |
| `timeout` | | Request timeout in ms, `5000` by default |
| `retries` | | Retries on a transient failure, `2` by default |

On Nuxt, each variable also reads with a `NUXT_` prefix, such as `NUXT_SENTRY_DSN`.
