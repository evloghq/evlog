title: HyperDX

[HyperDX](https://hyperdx.io) ingests OpenTelemetry. The drain encodes each wide event as one OTLP log record and sends it with your ingestion key.

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { createHyperDXDrain } from 'evlog/hyperdx'

export default defineEvlog({
  service: 'my-app',
  drain: createHyperDXDrain(),
})
```

## Credentials

```bash [.env]
HYPERDX_API_KEY=your-ingestion-key
```

The drain sends to `https://in-otel.hyperdx.io` by default. For a self-hosted HyperDX, set `HYPERDX_OTLP_ENDPOINT` to its OTLP HTTP base URL; evlog appends `/v1/logs`.

## Options

| Option | Env | What it is |
| --- | --- | --- |
| `apiKey` | `HYPERDX_API_KEY` | The ingestion key, sent as the `authorization` header |
| `endpoint` | `HYPERDX_OTLP_ENDPOINT` | The OTLP HTTP base URL |
| `serviceName` | `HYPERDX_SERVICE_NAME`, `OTEL_SERVICE_NAME` | `service.name` on the resource. Defaults to the event's `service` |
| `resourceAttributes` | | Extra resource attributes |
| `recordShape` | | `'compact'` by default: a one-line body and dotted attributes. `'json'` sends the whole event as the body |
| `semanticConventions` | | `true` by default: also emits `http.request.method`, `url.path`, `exception.*` and the like |
| `timeout` | | Request timeout in ms, `5000` by default |
| `retries` | | Retries on a transient failure, `2` by default |

On Nuxt, each variable also reads with a `NUXT_` prefix, such as `NUXT_HYPERDX_API_KEY`.
