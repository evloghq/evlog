::product-facts{entry="evlog/stream" status="stable"}
::

A devtool, a dashboard or a script that wants to watch events live should not have to write a drain. `evlog/stream` gives it two layers:

- `createStreamDrain()` is a drain you subscribe to from code in the same process.
- `startStreamServer()` serves that stream over Server-Sent Events on a local port, for a browser tab, a CLI or a desktop devtool.

::callout{icon="i-lucide-shield" color="neutral"}
Both layers live in one Node, Bun or Deno process. They work in development and on long-lived servers, VMs and containers. They do not work on Vercel Functions, Cloudflare Workers or AWS Lambda, where a subscriber in one instance never sees events emitted by another. Use a broker such as Redis Streams, NATS or Pub/Sub there.
::

## Subscribe in the same process

::stream-bus
::

Register `stream.drain` like any drain, on the `evlog:drain` hook as here or as the `drain` option of your config, then subscribe. Nothing is serialized and nothing leaves the process.

```typescript [stream.ts]
import { createStreamDrain } from 'evlog/stream'

const stream = createStreamDrain({ buffer: 200 })

nitroApp.hooks.hook('evlog:drain', stream.drain)

const off = stream.subscribe((event) => {
  if (event.level === 'error') notify(event)
})
off()

for (const past of stream.recent()) {
  bootstrap(past)
}
for await (const event of stream.events()) {
  bootstrap(event)
}
```

| Option | Default | What it does |
| --- | --- | --- |
| `buffer` | `500` | Events kept in the ring buffer that `recent()` returns. `0` turns it off |
| `perSubscriberQueue` | `1000` | Events queued for one `events()` iterator before its oldest are dropped. The drain is never blocked |
| `filter` | | A predicate run on each event. `false` skips it: it is neither buffered nor delivered |

| Member | What it does |
| --- | --- |
| `drain(ctx)` | Takes one context or a batch |
| `subscribe(listener)` | Calls a synchronous listener for each event and returns the unsubscribe function. A listener that throws is logged and does not affect the others |
| `events()` | A new async iterator over live events. It does not replay the buffer, and `break` unsubscribes it |
| `recent()` | A snapshot of the buffer, oldest first |
| `subscriberCount` | Active listeners and iterators |
| `droppedCount` | Events dropped from the ring buffer or from a slow iterator's queue |
| `close()` | Disconnects every subscriber. The stream stays usable |

`getDefaultStream()` returns the one stream the built-in integrations and the stream server share, so you can subscribe to it without registering a second drain. `setDefaultStream()` replaces it, which is mostly useful in tests.

## Serve it over SSE

::sse-wire
::

`startStreamServer()` starts a small `node:http` server in your app's process and leaves your own routes alone. Nothing starts unless you ask for it, in development included.

::framework-tabs
```typescript [Nuxt] nuxt.config.ts
export default defineNuxtConfig({
  modules: ['evlog/nuxt'],
  evlog: {
    stream: true,
    // or: stream: { port: 4444, token: process.env.EVLOG_STREAM_TOKEN }
  },
})
```
```typescript [Next.js] instrumentation.ts
import { defineStreamedInstrumentation } from 'evlog/next/stream'

export const { register } = defineStreamedInstrumentation({
  stream: true,
})
```
```typescript [Standalone] src/index.ts
import { startStreamServer } from 'evlog/stream'

if (process.env.NODE_ENV !== 'production' && process.env.EVLOG_STREAM === '1') {
  const { drain } = await startStreamServer()
  // Plug `drain` into the evlog drain hook for your framework
}
```
::

Hono, Express, Fastify and Elysia use the standalone form: call `startStreamServer()` once at startup and register the `drain` it returns like any other drain. On Nuxt and Next.js the integration registers it for you.

When it starts, the server:

1. Listens on `127.0.0.1`, on a free port the OS picks unless you set one.
2. Writes its URL to `.evlog/stream.url`.
3. Prints `[evlog] Stream → http://127.0.0.1:<port>` in the server console.
4. Serves the SSE stream on `GET /` and `{ evlogVersion, bufferSize, heartbeatMs }` on `GET /info`.

On `SIGINT`, `SIGTERM` or process exit it closes and removes the URL file. A second call to `startStreamServer()` returns the running server, which exposes `url`, `port`, `drain`, `stream` and `close()`.

| Option | Default | What it does |
| --- | --- | --- |
| `port` | `0` | The TCP port. `0` lets the OS pick one |
| `host` | `'127.0.0.1'` | The listen address, not reachable from the LAN. Set `0.0.0.0` only with a `token` |
| `token` | | When set, every request must send `Authorization: Bearer <token>` or gets a 401 |
| `heartbeatMs` | `15000` | Interval between `ping` frames |
| `buffer` | `500` | Ring buffer of the default stream, replayed to a client that passes `?since=<iso>` |
| `banner` | `true` | Prints the startup line |
| `urlFileDir` | `'.evlog'` | Directory where `stream.url` is written. `false` writes no file |

Without a `token`, a connection is accepted only when its `Host` header is `localhost`, `127.0.0.1` or `[::1]`, and its `Origin` header, if sent, names one of those hosts exactly. `https://localhost.example.com` and a page reached through a domain that resolves to `127.0.0.1` get a 403. Responses allow any origin, so those two checks, or the token, are what keep another site out.

## Find the URL

The port changes on every start, so a consumer reads the URL instead of hard-coding it:

```typescript [devtool.ts]
import { readFile } from 'node:fs/promises'

const url = (await readFile('.evlog/stream.url', 'utf-8')).trim()
```

In a Nuxt app, a browser tab asks the discovery route, which answers `{ url: null }` when the server is not running. The route allows cross-origin reads from loopback origins only:

```typescript [app/composables/useEvlogStream.ts]
const { url } = await fetch('/api/_evlog/stream-info').then(r => r.json())
```

## Wire format

Every SSE message is a JSON envelope `{ evlog: '1', type, data }`:

| `type` | When | `data` |
| --- | --- | --- |
| `hello` | First frame after connecting | `{ evlogVersion, bufferSize, heartbeatMs }` |
| `replay` | After `hello`, one per buffered event at or after `?since=<iso>` | A wide event |
| `event` | Every event emitted from then on | A wide event |
| `ping` | Every `heartbeatMs` | `{ t: number }`, the time in epoch ms |

`ping` frames carry the SSE event name `ping`, so `EventSource.onmessage` never sees them. Listen with `addEventListener('ping', ...)` if you want them.

## Consume it

In a browser, an `EventSource` and a list are a working event panel. Accept `replay` next to `event` when you connect with `?since=`, and cap the list:

```typescript [app/devtool.ts]
const { url } = await fetch('/api/_evlog/stream-info').then(r => r.json())
const es = new EventSource(url)

es.onmessage = (msg) => {
  const { type, data } = JSON.parse(msg.data)
  if (type === 'event') events.push(data)
}
```

`EventSource` cannot send an `Authorization` header, so a server started with a `token` needs a client that can, such as `curl` or `fetch`.

From a terminal, `curl -N` keeps the connection streaming and `jq` filters:

```bash [Terminal]
URL=$(cat .evlog/stream.url)
curl -N "$URL" | jq -c 'select(.type == "event") | .data'

# Only errors
curl -sN "$URL" | jq -c 'select(.type == "event" and .data.level == "error") | .data'

# Only one service
curl -sN "$URL" | jq -c 'select(.type == "event" and .data.service == "checkout") | .data'

# Slow requests
curl -sN "$URL" | jq -c 'select(.type == "event" and .data.durationMs > 500) | .data'
```

In Node or Bun, `fetch` and a stream reader speak the same protocol:

```typescript [scripts/stream-client.ts]
import { readFile } from 'node:fs/promises'

const url = (await readFile('.evlog/stream.url', 'utf-8')).trim()
const res = await fetch(url)
const reader = res.body!.getReader()
const decoder = new TextDecoder()
let buffer = ''

while (true) {
  const { value, done } = await reader.read()
  if (done) break
  buffer += decoder.decode(value, { stream: true })

  let idx
  while ((idx = buffer.indexOf('\n\n')) !== -1) {
    const frame = buffer.slice(0, idx)
    buffer = buffer.slice(idx + 2)
    const dataLine = frame.split('\n').find(l => l.startsWith('data:'))
    if (!dataLine) continue
    const env = JSON.parse(dataLine.slice(5).trim())
    if (env.type === 'event') console.log(env.data)
  }
}
```

The server sends every event to every client and takes no filter, so one consumer's filter cannot starve another. Filter and aggregate where you consume:

```typescript [app/devtool.ts]
// Just errors
const errors = events.filter(e => e.level === 'error')

// Group by service
const byService = Object.groupBy(events, e => e.service)

// Rolling error rate (last 100 events)
const last100 = events.slice(0, 100)
const errorRate = last100.filter(e => e.level === 'error').length / last100.length
```

The server relays exactly what your app emitted. A field [redaction](/events/redaction) did not mask reaches every connected client.

The ring buffer replays but never writes to disk. For history that survives a restart, read the [file system drain](/drains/fs#read-events-from-code), which also shows how to replay from disk and then go live on this stream.
