OTLP is the protocol every OpenTelemetry backend accepts: Grafana, Honeycomb, New Relic, a collector you run. The drain turns each wide event into one log record.

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { createOTLPDrain } from 'evlog/otlp'

export default defineEvlog({
  service: 'my-app',
  drain: createOTLPDrain(),
})
```

```bash [.env]
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
```

The drain reads the standard OpenTelemetry variables: `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` is used as the full logs URL, `OTEL_EXPORTER_OTLP_ENDPOINT` (or `OTLP_ENDPOINT`) gets `/v1/logs` appended, and `OTEL_SERVICE_NAME` names the service.

## The record shape

In evlog 3, records are compact by default:

- The body is a one-line summary, such as `POST /api/checkout (500)`.
- Nested fields become dotted attributes, such as `user.id`.
- Records also carry the OpenTelemetry semantic conventions: `http.request.method`, `url.path`, `http.response.status_code`, `exception.*` and `gen_ai.*`. The evlog field names stay next to them.

For the same 100 events, that takes the request from 151,235 to 140,250 bytes as JSON. To keep the 2.x output:

```typescript [evlog.config.ts]
createOTLPDrain({ recordShape: 'json', semanticConventions: false })
```

HyperDX and Sazabi are built on this encoder, so they share the same defaults.
