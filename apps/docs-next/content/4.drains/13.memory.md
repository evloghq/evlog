The drain keeps the most recent wide events in memory, 1,000 by default, and drops the oldest past that. `readMemoryLogs()` returns them, filtered, from anywhere in the same process.

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { createMemoryDrain } from 'evlog/memory'

export default defineEvlog({
  service: 'my-app',
  drain: createMemoryDrain(),
})
```

The drain uses no file system and no network, so it also runs where the [file system drain](/drains/fs) cannot: Cloudflare Workers, Deno Deploy and other edge runtimes.

## In tests

Assert on the event a request produced, not on console output:

```typescript [checkout.test.ts]
import { clearMemoryLogs, readMemoryLogs } from 'evlog/memory'

beforeEach(() => clearMemoryLogs())

it('records the declined card', async () => {
  await request(app).post('/api/checkout').send({ card: 'declined' })

  const [event] = readMemoryLogs({ level: 'error' })
  expect(event.status).toBe(402)
  expect(event.error.why).toBe('Card declined by issuer')
})
```

`clearMemoryLogs()` empties the `default` store, and `clearMemoryLogs('auth')` a named one.

## For an agent

Expose the buffer on a route that only exists in development, and an agent can read the app's events over HTTP while it works:

```typescript [src/index.ts]
import { parseReadMemoryLogsQuery, readMemoryLogs } from 'evlog/memory'

if (process.env.NODE_ENV !== 'production') {
  app.get('/_evlog/logs', c => c.json(readMemoryLogs(parseReadMemoryLogsQuery(c.req.query()))))
}
```

`parseReadMemoryLogsQuery` turns `?level=error,warn&limit=50&since=2026-10-25T00:00:00Z` into typed options. It also reads `store` and `until`.

The response is a JSON array of wide events, oldest first, in the shape every other drain receives. The parser takes the framework's query object, such as `c.req.query()` on Hono or `req.query` on Express:

| Query parameter | Becomes | Rule |
| --- | --- | --- |
| `store` | `string` | Passed through |
| `since`, `until` | `string` | An ISO 8601 date, parsed by `readMemoryLogs` |
| `level` | `LogLevel \| LogLevel[]` | Comma-separated (`error,warn`) or repeated. A value that is not a level is dropped |
| `limit` | `number` | Read with `parseInt`. Left out when it is not a number |

A query string cannot carry the `filter` predicate.

## Read the buffer

`readMemoryLogs()` returns a copy of the buffer, oldest event first. It takes the filters of `readFsLogs()`, plus `store` and `limit`:

```typescript [src/index.ts]
import { readMemoryLogs } from 'evlog/memory'

// All events
const all = readMemoryLogs()

// Errors only
const errors = readMemoryLogs({ level: 'error' })

// Last 10 minutes
const recent = readMemoryLogs({
  since: new Date(Date.now() - 10 * 60 * 1000),
})

// Custom predicate
const slow = readMemoryLogs({
  filter: e => (e.durationMs ?? 0) > 1000,
})

// Most recent 50 events
const latest = readMemoryLogs({ limit: 50 })
```

| Option | Type | What it does |
| --- | --- | --- |
| `store` | `string` | The store to read, `default` by default |
| `since` | `Date \| string` | Returns events with `timestamp >= since` |
| `until` | `Date \| string` | Returns events with `timestamp <= until` |
| `level` | `LogLevel \| LogLevel[]` | Returns events at these levels |
| `filter` | `(event) => boolean` | Your own predicate. `false` skips the event |
| `limit` | `number` | Returns at most this many events, the most recent ones that match. `0` or less returns none |

With `since` or `until` set, an event whose `timestamp` does not parse is left out. A `since` or `until` that is not a date is ignored.

## Named stores

Two drains with different `store` names fill two buffers, which keeps the events of one service, or of one test suite, apart from the others:

```typescript [src/index.ts]
import { createMemoryDrain, readMemoryLogs, clearMemoryLogs } from 'evlog/memory'

// Two separate buffers
const authDrain = createMemoryDrain({ store: 'auth' })
const apiDrain = createMemoryDrain({ store: 'api' })

// Read from a specific store
const authErrors = readMemoryLogs({ store: 'auth', level: 'error' })

// Clear a store (useful in tests)
clearMemoryLogs('auth')
```

Two drains with the same name share one buffer. `maxEvents` is applied on each write, so with different values the drain that wrote last decides how many events remain.

## Memory in development, a hosted drain in production

The buffer answers the agent on your machine. Production events go to a destination that keeps them:

```typescript [evlog.config.ts]
import { defineEvlog, type DrainContext } from 'evlog'
import { createMemoryDrain } from 'evlog/memory'
import { createAxiomDrain } from 'evlog/axiom'

const memory = createMemoryDrain()
const axiom = createAxiomDrain()

const drain = async (ctx: DrainContext) => {
  if (process.env.NODE_ENV === 'development') {
    await memory(ctx)
  } else {
    await axiom(ctx)
  }
}

export default defineEvlog({
  service: 'my-app',
  drain,
})
```

## Options

| Option | Env | What it is |
| --- | --- | --- |
| `store` | `EVLOG_MEMORY_STORE` | A named buffer. Drains with the same name share it. `default` by default |
| `maxEvents` | `EVLOG_MEMORY_MAX_EVENTS` | The buffer size, `1000` by default |

The buffer lives in one process. On serverless platforms, each instance has its own and loses it when it stops.

An option passed to `createMemoryDrain()` wins. On Nuxt and Nitro, `runtimeConfig.evlog.memory` is read next, then `runtimeConfig.memory`. The environment comes last, where `NUXT_EVLOG_MEMORY_STORE` and `NUXT_EVLOG_MEMORY_MAX_EVENTS` are read before the unprefixed names.

`maxEvents` is rounded down to a whole number. A value that is not a number, or is `0` or less, falls back to `1000`. The drain has no credentials and no request, so it is never unconfigured and has no timeout or retry.

## Limits

- The buffer is bounded. With `maxEvents: 5`, the sixth event removes the first, so memory use stays constant however long the process runs.
- A restart of the process or the worker empties it. To keep events, use the file system drain on a Node runtime, or [NuxtHub](/drains/nuxthub).

## Write without the drain

`writeToMemory()` appends events to a store directly, which sets up a test without a logger:

```typescript [src/index.ts]
import { writeToMemory } from 'evlog/memory'

writeToMemory([event], { store: 'default', maxEvents: 1000 })
```

It takes a complete config and reads nothing from the environment.
