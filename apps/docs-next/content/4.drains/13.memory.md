---
title: Memory
description: "Keep the last wide events in an in-process ring buffer, and read them back in tests or from a dev-only endpoint an agent can call."
---

::product-facts{entry="evlog/memory" status="stable"}
::

The drain keeps the most recent wide events in memory, 1,000 by default, and drops the oldest past that. `readMemoryLogs()` returns them, filtered, from anywhere in the same process.

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { createMemoryDrain } from 'evlog/memory'

export default defineEvlog({
  service: 'my-app',
  drain: createMemoryDrain(),
})
```

## In tests

Assert on the event a request produced, not on console output:

```typescript [checkout.test.ts]
import { clearMemoryLogs, readMemoryLogs } from 'evlog/memory'

beforeEach(() => clearMemoryLogs())

it('records the declined card', async () => {
  await request(app).post('/api/checkout').send({ card: 'declined' })

  const [event] = readMemoryLogs({ level: 'error' })
  expect(event.status).toBe(402)
  expect(event.error.why).toBe('Card declined by issuer')
})
```

## For an agent

Expose the buffer on a route that only exists in development, and an agent can read the app's events over HTTP while it works:

```typescript [src/index.ts]
import { parseReadMemoryLogsQuery, readMemoryLogs } from 'evlog/memory'

if (process.env.NODE_ENV !== 'production') {
  app.get('/_evlog/logs', c => c.json(readMemoryLogs(parseReadMemoryLogsQuery(c.req.query()))))
}
```

`parseReadMemoryLogsQuery` turns `?level=error,warn&limit=50&since=2026-10-25T00:00:00Z` into typed options. It also reads `store` and `until`.

## Options

| Option | Env | What it is |
| --- | --- | --- |
| `store` | `EVLOG_MEMORY_STORE` | A named buffer. Drains with the same name share it. `default` by default |
| `maxEvents` | `EVLOG_MEMORY_MAX_EVENTS` | The buffer size, `1000` by default |

The buffer lives in one process. On serverless platforms, each instance has its own and loses it when it stops.
