The drain posts each wide event to the [Datadog Logs](https://docs.datadoghq.com/logs/) HTTP intake. Every field becomes a log attribute you can facet on, such as `@user.plan` or `@status`.

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { createDatadogDrain } from 'evlog/datadog'

export default defineEvlog({
  service: 'my-app',
  drain: createDatadogDrain(),
})
```

## Credentials

Create an API key with Logs intake permission. The drain reads the variables the Datadog agent already uses:

```bash [.env]
DD_API_KEY=your-api-key
DD_SITE=datadoghq.eu
```

`DD_SITE` is `datadoghq.com` when unset. Set it to the site in your Datadog URL: `datadoghq.eu`, `us3.datadoghq.com`, `us5.datadoghq.com`, `ap1.datadoghq.com` or `ddog-gov.com`. `DATADOG_API_KEY` and `DATADOG_SITE` work too.

## Options

| Option | Env | What it is |
| --- | --- | --- |
| `apiKey` | `DD_API_KEY` | An API key with Logs intake permission |
| `site` | `DD_SITE` | The Datadog site, `datadoghq.com` by default |
| `intakeUrl` | `DATADOG_LOGS_URL` | A full intake URL. Overrides `site` |
| `timeout` | | Request timeout in ms, `5000` by default |
| `retries` | | Retries on a transient failure, `2` by default |

On Nuxt, each variable also reads with a `NUXT_` prefix, such as `NUXT_DATADOG_API_KEY`.
