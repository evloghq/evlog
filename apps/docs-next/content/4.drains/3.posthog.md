The drain sends each wide event to [PostHog Logs](https://posthog.com/docs/logs) over OTLP. When the event carries a user id and a session id, PostHog shows the log on that person's profile and next to their session replay.

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { createPostHogDrain } from 'evlog/posthog'

export default defineEvlog({
  service: 'my-app',
  drain: createPostHogDrain(),
})
```

## Credentials

Use the project API key, the one your frontend already sends with:

```bash [.env]
POSTHOG_API_KEY=phc_your_project_key
POSTHOG_HOST=https://eu.i.posthog.com
```

`POSTHOG_HOST` is `https://us.i.posthog.com` when unset. Set it for the EU cloud or a self-hosted instance.

## Link logs to people and replays

Record the ids on the event, and the drain sends them as the attributes PostHog matches on:

```typescript [server/api/checkout.post.ts]
log.set({
  userId: user.id,
  sessionId: getHeader(event, 'x-posthog-session-id'),
})
```

Read the session id in the browser with `posthog.get_session_id()` and pass it in a header. The fields are `userId` and `sessionId` by default; `distinctIdField` and `sessionIdField` take another dot path, such as `user.id`.

## Logs or events

| `mode` | Where events land | When to pick it |
| --- | --- | --- |
| `'logs'` | PostHog Logs, over OTLP | The default, and the cheapest |
| `'events'` | Custom events through `/batch/`, named `evlog_wide_event` | You want to chart events in Insights next to product events |

In `'events'` mode, nested fields are flattened to dotted properties such as `ai.costUsd`, because PostHog filters and breaks down by top-level properties.

## Options

| Option | Env | What it is |
| --- | --- | --- |
| `apiKey` | `POSTHOG_API_KEY` | The project API key |
| `host` | `POSTHOG_HOST` | The PostHog host, `https://us.i.posthog.com` by default |
| `mode` | | `'logs'` or `'events'` |
| `eventName` | | The event name in `'events'` mode, `evlog_wide_event` by default |
| `distinctId` | | One person id for every event |
| `distinctIdField` | | The field holding the person id, `userId` by default |
| `sessionIdField` | | The field holding the session id, `sessionId` by default |
| `recordShape` | | `'compact'` by default, or `'json'` |
| `semanticConventions` | | Logs mode only. `true` by default: also emits `http.request.method`, `url.path`, `exception.*` and the like |
| `timeout` | | Request timeout in ms, `5000` by default |
| `retries` | | Retries on a transient failure, `2` by default |

On Nuxt, each variable also reads with a `NUXT_` prefix, such as `NUXT_POSTHOG_API_KEY`.
