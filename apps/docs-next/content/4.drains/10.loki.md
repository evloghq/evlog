[Loki](https://grafana.com/oss/loki/) indexes labels, not content. The drain turns a few fields of each wide event into stream labels and sends the whole event as the log line, which LogQL's `| json` reads back.

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { createLokiDrain } from 'evlog/loki'

export default defineEvlog({
  service: 'my-app',
  drain: createLokiDrain(),
})
```

## Credentials

Self-hosted, the endpoint is enough:

```bash [.env]
LOKI_ENDPOINT=http://localhost:3100
```

On Grafana Cloud, add the instance ID and a token. Together they are sent as Basic auth:

```bash [.env]
LOKI_ENDPOINT=https://logs-prod-eu-west-0.grafana.net
LOKI_USER=123456
LOKI_API_KEY=glc_your_token
```

A token without a user is sent as a Bearer token. A multi-tenant self-hosted Loki takes `LOKI_TENANT_ID`, sent as `X-Scope-OrgID`.

`LOKI_USER` is the numeric instance ID of the Loki data source, listed under Connections, Data sources, Loki in your Grafana Cloud stack. It is not your account email. The token is an access policy token.

The header follows from what is set:

| You set | Header sent |
| --- | --- |
| `user` and `apiKey` | `Authorization: Basic`, with `user:apiKey` in base64 |
| `apiKey` alone | `Authorization: Bearer <apiKey>`, for an instance behind an authenticating proxy |
| `tenantId` | `X-Scope-OrgID: <tenantId>`, alone or next to either `Authorization` header |
| `user` alone, or none of them | No auth header |

The drain posts to `<endpoint>/loki/api/v1/push`. An endpoint that already ends with that path is used as is.

## Labels

Each distinct set of label values is a separate stream in Loki, so labels must stay few and low-cardinality. The drain labels by `service`, `environment` and `level`:

```logql
{service="my-app", level="error"} | json | status >= 500
```

`labelFields` changes the list, and `labels` adds static ones such as a region. Never label by `requestId`, `userId` or `path`: each value would open a new stream.

Add a label only for a field you filter on and whose values form a small, bounded set:

```typescript [evlog.config.ts]
createLokiDrain({
  // `region` has a handful of values
  labelFields: ['service', 'environment', 'level', 'region'],
  // Static labels for everything in this deployment
  labels: { cluster: 'prod-eu' },
})
```

`labelFields` names top-level fields of the event. A field becomes a label when the event has it and its value is a string, a number or a boolean. An object or an array is left in the line. When a static label and a field share a name, the field's value wins.

## What Loki receives

| Part of the push | What the drain puts there |
| --- | --- |
| Stream labels | The `labels` you set, then each `labelFields` entry found on the event |
| Entry timestamp | The event's `timestamp` in nanoseconds. The time of the push when it does not parse |
| Log line | The whole event as JSON, the labelled fields included |

Events that share a label set go in one stream, sorted by timestamp, because Loki rejects out-of-order entries within a stream. Everything that is not a label is in the line: the drain sends no structured metadata.

The drain pushes once per event. Wrapped in the [pipeline](/drains/pipeline), it pushes once per batch, for example up to 100 events every 5 seconds with `batch: { size: 100, intervalMs: 5000 }`.

## Query in Grafana

Filter by label first, then reach into the wide event with `| json`:

```logql
# Server errors of one service
{service="checkout", environment="production"} | json | status >= 500

# Slow requests on one route
{service="checkout"} | json | path="/api/orders" | durationMs > 1000

# One request end to end
{service="checkout"} | json | requestId="4a8ff3a8-..."

# Error rate per service
sum by (service) (rate({environment="production", level="error"}[5m]))
```

## Options

| Option | Env | What it is |
| --- | --- | --- |
| `endpoint` | `LOKI_ENDPOINT`, `LOKI_URL` | The Loki base URL, without the push path. Required |
| `apiKey` | `LOKI_API_KEY`, `GRAFANA_API_KEY` | A token |
| `user` | `LOKI_USER`, `GRAFANA_USER` | The Grafana Cloud instance ID. Switches to Basic auth |
| `tenantId` | `LOKI_TENANT_ID` | The tenant, for multi-tenant Loki |
| `labelFields` | | Fields promoted to labels, `['service', 'environment', 'level']` by default |
| `labels` | | Static labels on every stream |
| `timeout` | | Request timeout in ms, `5000` by default |
| `retries` | | Retries on a transient failure, `2` by default |

An option passed to `createLokiDrain()` wins. On Nuxt and Nitro, `runtimeConfig.evlog.loki` is read next, then `runtimeConfig.loki`. The environment comes last, where the four `LOKI_` names of the first column are also read with a `NUXT_` prefix, such as `NUXT_LOKI_ENDPOINT`, before the unprefixed names.

## When a request fails

Without an endpoint, the drain sends nothing and logs `[evlog/loki] Missing endpoint` with the variables to set, each time it is called.

A push that gets no answer within `timeout` is aborted. The drain retries a network error, a timeout and a `408`, `429`, `502`, `503` or `504` response, up to `retries` times, with exponential backoff and jitter. It waits for the response's `Retry-After` when that is 10 seconds or less, and stops retrying when it is longer. Any other status fails at once.

After the last attempt the drain logs `[evlog/loki] Failed to send events:` with the error and drops the events. The request that produced them is not affected. Wrapped in the pipeline, the drain makes one attempt per batch and the pipeline's `retry` takes over, unless you set `retries` yourself.

| What you see | Cause and fix |
| --- | --- |
| `Loki API error: 401` | On Grafana Cloud, `user` must be the numeric instance ID of the Loki data source |
| `Loki API error: 400` naming out-of-order entries | Older Loki versions reject an entry older than the latest one in its stream. The drain sorts within each push only. Enable `unordered_writes` in Loki or shorten the batch interval |
| Nothing in Grafana | You are querying another label set. Run `{service=~".+"}` to list the streams that arrived |

## Send without the drain

A script or a backfill can push events directly:

```typescript [scripts/backfill.ts]
import { sendBatchToLoki, sendToLoki } from 'evlog/loki'

await sendToLoki(event, { endpoint: 'http://localhost:3100' })
await sendBatchToLoki(events, { endpoint: 'http://localhost:3100' })
```

Both take a complete config, read nothing from the environment, and reject when the push fails. `buildLokiPayload()`, `toLokiLabels()`, `toLokiTimestamp()` and `resolveLokiPushUrl()` are exported too, for code that sends the push itself.
