---
title: File system
description: "Write wide events to NDJSON files on disk, rotated by day and size, for local development, agents and tests."
---

::product-facts{entry="evlog/fs" status="stable"}
::

The drain appends each wide event as one JSON line to a file under `.evlog/logs/`, one file per day. Nothing leaves the machine, and your editor, `jq` or an agent can read the logs where they are.

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { createFsDrain } from 'evlog/fs'

export default defineEvlog({
  service: 'my-app',
  drain: createFsDrain({ maxFiles: 7 }),
})
```

Add `.evlog/` to your `.gitignore`.

## Read it back

The files are plain NDJSON, so the usual tools work:

```bash [Terminal]
tail -f .evlog/logs/*.jsonl | jq 'select(.status >= 500)'
```

`evlog logs` reads and filters them from the terminal, and the [analyze-logs skill](/skills) teaches an agent to do the same while it debugs.

## Options

| Option | Env | What it is |
| --- | --- | --- |
| `dir` | `EVLOG_FS_DIR` | The directory, `.evlog/logs` by default |
| `maxFiles` | | How many files to keep. The oldest are deleted |
| `maxSizePerFile` | | Bytes per file before it rotates to a suffixed file |
| `pretty` | | Indented JSON instead of one line per event |

On Nuxt, `NUXT_EVLOG_FS_DIR` is read too.

::callout{color="warning"}
Serverless and edge platforms have no persistent disk. Use the file system drain locally, and a hosted drain in production.
::
