::

The drain appends each wide event as one JSON line to a file under `.evlog/logs/`, one file per day. Nothing leaves the machine, and your editor, `jq` or an agent can read the logs where they are.

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { createFsDrain } from 'evlog/fs'

export default defineEvlog({
  service: 'my-app',
  drain: createFsDrain({ maxFiles: 7 }),
})
```

On its first write the drain creates a `.gitignore` inside `.evlog/`, so the logs stay out of version control.

## Read it back

The files are plain NDJSON, so the usual tools work:

```bash [Terminal]
tail -f .evlog/logs/*.jsonl | jq 'select(.status >= 500)'
```

`evlog logs` reads and filters them from the terminal, and the [analyze-logs skill](/skills) teaches an agent to do the same while it debugs.

## Read events from code

`evlog/fs` also exports two readers. They work from any Node script, with no hook into the running app, so a sidecar process, a CI report or a local dashboard can use them.

::ndjson-tail
::

`readFsLogs()` replays history. It walks the files in date order, a day's rotated files (`2026-05-08.1.jsonl`) after its first one, and skips whole files outside the date window, so a replay stays fast with weeks of logs on disk:

```typescript [scripts/errors.ts]
import { readFsLogs } from 'evlog/fs'

for await (const event of readFsLogs({ since: '2026-03-01', level: 'error' })) {
  console.log(event.timestamp, event.action ?? event.message)
}
```

| Option | Type | What it does |
| --- | --- | --- |
| `dir` | `string` | The directory to read, `.evlog/logs` by default |
| `since` | `Date \| string` | Yields events with `timestamp >= since` |
| `until` | `Date \| string` | Yields events with `timestamp <= until` |
| `level` | `LogLevel \| LogLevel[]` | Yields events at these levels |
| `filter` | `(event) => boolean` | Your own predicate. `false` skips the event |

A line that does not parse, from a partial write or a manual edit, is skipped without an error. Files written with `pretty: true` are read too.

`tailFsLogs()` follows the files. It yields the existing events first, then each new one as it is appended, including events in a daily file created after it started:

```typescript [scripts/tail.ts]
import { tailFsLogs } from 'evlog/fs'

const ac = new AbortController()
process.on('SIGINT', () => ac.abort())

for await (const event of tailFsLogs({ signal: ac.signal })) {
  if (event.level === 'error') notifyOps(event)
}
```

It takes every `readFsLogs()` option, and three of its own:

| Option | Default | What it does |
| --- | --- | --- |
| `pollIntervalMs` | `500` | How often it checks for new bytes and new files, 50 ms at least |
| `fromEnd` | `false` | Skips the existing events and yields only new ones |
| `signal` | | An `AbortSignal` that stops the tail |

A write split across two polls is put back together before it is parsed.

To show history and then follow live traffic, replay from disk and switch to the [stream](/drains/stream) server:

```typescript [scripts/bootstrap.ts]
import { readFsLogs } from 'evlog/fs'
import { readFile } from 'node:fs/promises'
import type { WideEvent } from 'evlog'

async function bootstrap(handle: (e: WideEvent) => void) {
  // 1. Replay the last hour from `.evlog/logs/`
  const since = new Date(Date.now() - 60 * 60 * 1000)
  for await (const event of readFsLogs({ since })) {
    handle(event)
  }

  // 2. Switch to the live SSE stream
  const url = (await readFile('.evlog/stream.url', 'utf-8')).trim()
  const es = new EventSource(url)
  es.onmessage = (e) => {
    const env = JSON.parse(e.data)
    if (env.evlog !== '1') return
    if (env.type === 'event' || env.type === 'replay') {
      handle(env.data)
    }
  }
  return () => es.close()
}
```

Without the files, connect to the stream server with `?since=<iso>` and it replays its in-memory buffer instead.

## Options

| Option | Env | What it is |
| --- | --- | --- |
| `dir` | `EVLOG_FS_DIR` | The directory, `.evlog/logs` by default |
| `maxFiles` | | How many files to keep. The oldest are deleted |
| `maxSizePerFile` | | Bytes per file before it rotates to a suffixed file |
| `pretty` | | Indented JSON instead of one line per event |

On Nuxt, `NUXT_EVLOG_FS_DIR` is read too.

::callout{color="warning"}
Serverless and edge platforms have no persistent disk. Use the file system drain locally, and a hosted drain in production.
::
