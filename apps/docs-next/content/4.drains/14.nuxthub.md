`@evlog/nuxthub` writes wide events to an `evlog_events` table in your [NuxtHub](https://hub.nuxt.com) database. There is no external service and no per-event pricing; your logs live where your data does.

```bash [Terminal]
pnpm add @nuxthub/core @evlog/nuxthub
```

```typescript [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxthub/core', '@evlog/nuxthub'],
})
```

Your NuxtHub project needs a database. The module registers `evlog/nuxt` if you have not, adds an `evlog_events` table to NuxtHub's schema, and stores every event through the `evlog:drain` hook. Indexed columns hold the level, path, status and duration; the rest of the event is in a JSON column.

## Retention

Events older than the retention window are deleted by a scheduled task. The window is seven days unless you set it:

```typescript [nuxt.config.ts]
export default defineNuxtConfig({
  evlog: { retention: '30d' },
})
```

The schedule follows the window: a window in minutes or hours is cleaned up within it, a window in days once a day. When you install the module on a Vercel project, it offers to add that schedule to `vercel.json` as a cron.

## When to add another drain

The table is a good fit for development, staging and small apps. For high traffic, or retention past a few weeks, add a hosted drain such as [Axiom](/drains/axiom) next to it.
