An agent asked to add logging writes `console.log`. With the evlog skills installed, it writes a wide event, a structured error, and an audit call where the route touches money or auth, because the skills carry the same rules as these pages.

```bash [Terminal]
npx skills add https://www.evlog.dev
```

Claude Code, Cursor, Codex and any agent that reads [Agent Skills](https://agentskills.io) pick them up.

## The skills

| Skill | Use it to |
| --- | --- |
| `review-logging-patterns` | Find scattered logs, missing context and bare `Error`s, and move a codebase to evlog. Runs [`evlog map`](/map) first when the framework is supported |
| `build-audit-logs` | Design, wire and review an [audit](/audit) trail: policy, `auditEnricher`, `auditOnly`, `signed`, denials, redaction, tests |
| `analyze-logs` | Read the NDJSON the [file system drain](/drains/fs) writes to `.evlog/logs/`: errors, slow requests, one request end to end |

### review-logging-patterns

The skill reviews a codebase for four things:

- Scattered logging: several `console.log` or `logger.info` calls in one request handler.
- Missing context: logs without user, request or business fields.
- Unhelpful errors: `throw new Error()` without structured fields.
- Correlation gaps: no request ID or trace ID.

It then guides the change: it converts those calls to a wide event, designs the event's fields, writes [structured errors](/errors) with `why`, `fix` and `link`, and sets evlog up on every framework under [Integrations](/integrations).

On Nuxt, Nitro, Next.js, TanStack Start, Hono, Express, Fastify and Effect, and on eve agents, ask the agent to run the map first. It scores every entry point and lists the ones to fix first, which makes the review faster. The skill works without the CLI too.

```bash [Terminal]
npx evlog map --no-write
npx evlog map --json --no-write   # structured output for an agent
```

The skill ships four reference documents the agent opens when it needs them:

| File | What it holds |
| --- | --- |
| `references/wide-events.md` | Wide event anatomy, context grouping patterns, output format examples |
| `references/structured-errors.md` | Error field definitions, status code guidelines, frontend integration patterns |
| `references/code-review.md` | The review checklist, the anti-patterns to find, migration suggestions |
| `references/drain-pipeline.md` | When to recommend the drain pipeline, its configuration, and the batching mistakes to flag |

### build-audit-logs

The skill builds an audit trail in your application, or reviews the one you have. It starts with the decisions to write down before any code: where audit events live, whether you need `signed` integrity, multi-tenancy, retention, and how deletion requests fit an append-only log. It then wires the pipeline, defines the action vocabulary, instruments the call sites, covers denials, redacts and tests. A review runs four passes over pipeline wiring, call-site coverage, redaction and integrity, and tests. `references/framework-wiring.md` holds the wiring for Hono, Express, Next.js and standalone scripts.

### analyze-logs

The skill teaches the agent to read the events your app wrote to `.evlog/logs/`, through [`evlog logs`](/cli/logs) when the CLI is installed:

- Find errors and explain them from the stack trace and the `why`, `fix` and `link` fields.
- Find slow requests by `durationMs`.
- Follow one request by its `requestId`.
- Spot recurring failures: error rate by endpoint, client errors against server errors.

It needs the [file system drain](/drains/fs). When the directory is empty, the skill has the agent check for the drain with [`evlog doctor`](/cli/doctor) and preview [`evlog init`](/cli/init), which wires it.

## Conventions in AGENTS.md

[`evlog agents`](/cli/agents) installs the skills and writes a short block of evlog conventions into your project's `AGENTS.md`: the rules an agent follows on every logging change, which the skills then back with the detail.

```bash [Terminal]
npx evlog agents
```

It installs globally by default, into `~/.agents/skills`, the directory Codex and the other agents that read `.agents/skills` share. Claude Code gets a relative symlink to that copy in `~/.claude/skills`, so one set of files serves both. `--local` installs into the project instead: `.agents/skills` and `.claude/skills` at the project root, with a `skills-lock.json` beside them.

`evlog agents` names no other agent. To add one, run the skills CLI yourself:

```bash [Terminal]
npx skills add https://www.evlog.dev --agent cursor
```

## Ask

With the skills installed, ask in plain words. Each of these reaches a skill:

- Review this file for logging anti-patterns and move it to evlog wide events.
- Help me convert these `console.log` calls to a wide event.
- What context should I add to this wide event?
- How do I structure this error with evlog?
- Run `npx evlog map --no-write`, fix the entry points under FIX FIRST in order, and run it again to confirm the score went up.
- Follow the build-audit-logs skill and help me design, implement or review an audit trail.
- Why is the checkout endpoint failing?
- Show me the slowest requests from today.

## MCP server

An agent answers evlog questions from its training data, which can be a release behind the package you installed. The docs MCP server gives it the current pages. Add `https://www.evlog.dev/mcp` to your editor: no account, no key, read-only, over [streamable HTTP](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports#streamable-http).

| Client | How to add it |
| --- | --- |
| Cursor | [Add to Cursor](https://www.evlog.dev/mcp/deeplink), or the file below as `.cursor/mcp.json` in the project, or `~/.cursor/mcp.json` for every project ([Cursor MCP docs](https://cursor.com/docs/mcp)) |
| Claude Code | `claude mcp add --transport http evlog https://www.evlog.dev/mcp`. Add `--scope user` for every project ([Claude Code MCP docs](https://code.claude.com/docs/en/mcp)) |
| VS Code | [Install in VS Code](https://www.evlog.dev/mcp/deeplink?ide=vscode), or run **MCP: Add Server** from the Command Palette and pick HTTP, or commit `.vscode/mcp.json` for the team ([VS Code MCP docs](https://code.visualstudio.com/docs/agent-customization/mcp-servers)) |
| Any other client | Point a client that speaks streamable HTTP at `https://www.evlog.dev/mcp` |

::code-group
```json [.cursor/mcp.json]
{
  "mcpServers": {
    "evlog": {
      "url": "https://www.evlog.dev/mcp"
    }
  }
}
```

```json [.vscode/mcp.json]
{
  "servers": {
    "evlog": {
      "type": "http",
      "url": "https://www.evlog.dev/mcp"
    }
  }
}
```
::

### Tools

All three are read-only. None of them reads your project or your logs: they take a page path or the numbers you pass.

| Tool | Returns | Input |
| --- | --- | --- |
| `list-pages` | Every docs page: title, path, description, URL | None |
| `get-page` | The full Markdown of one page, the same bytes as `/raw/<path>.md` | `path`, such as `/start/installation` |
| `estimate-log-cost` | A month of logs before and after evlog: events, GB, cost, and the basis used | `requestsPerMonth`, plus optional `linesPerRequest` (default 4), `provider`, `perGb`, `perMillionIndexed`, `keepPercent` (default 100) |

`provider` is one of `datadog`, `grafana`, `sentry`, `posthog`, `betterstack`, `axiom`. [Cost](/reference/cost) has the byte counts and the rates behind `estimate-log-cost`. `list-pages` and `get-page` cache for one hour, so a docs change reaches the server within an hour of a deploy.

Name the server in the prompt so the agent reads the docs instead of guessing:

```text [Prompt]
Using the evlog MCP, read the Nuxt integration page and add evlog to this app.
```

```text [Prompt]
Using the evlog MCP, what does 10 million requests a month at 4 log lines each cost on Datadog, and with evlog?
```

### MCP, skills or llms.txt

| You want the agent to | Use |
| --- | --- |
| Look up a page in the middle of a task | The MCP server |
| Follow the evlog conventions and review logging code | The skills |
| Read the docs in a tool that has no MCP support | [`llms.txt`](https://www.evlog.dev/llms.txt), or any page as Markdown at `/raw/<path>.md` |

The skills carry the patterns and the server carries the current API, so install both.
