evlog is a TypeScript logger built around one idea: a unit of work produces one event. A request, a queue job or a script run collects its fields as it goes, and evlog emits them together when the work ends, whether it succeeded or threw.

::event-anatomy
::

That is the whole output for a failed checkout: one event instead of ten log lines, with the reason for the failure and what to do about it attached to the failure itself.

## What's in evlog

Each part of evlog has a one-word name, a page, and the same name in the code.

| Part | What it does |
| --- | --- |
| [Events](/events) | The wide event: accumulate context with `log.set()`, emit once. Sampling, redaction and enrichers shape it |
| [Errors](/errors) | `createError()` with `why`, `fix` and `link`, typed catalogs, and `parseError()` on the client |
| [Drains](/drains) | Where events leave the process: Axiom, OTLP, PostHog, Sentry, Datadog, Loki, ClickHouse and more |
| [Audit](/audit) | Who did what, on which resource, with which outcome. Signed, and kept past sampling |
| [Map](/map) | `evlog map` scores the entry points that still log nothing useful, and gates regressions in CI |
| [Signals](/signals) | Ask a model one question per event, such as who broke it, and get the answer back as a column |
| [Skills](/skills) | Agent skills that review logging, wire evlog in, and read the logs your app wrote |
| [Telemetry](/telemetry) | One event per CLI run or CI job, with consent, an outbox and a generated disclosure |

Events and Errors are the core, and every other part is built on them. You can ship with the core alone and add the rest when you need it: nothing else has to be configured for an event to print.

## What it costs you

- **A dependency.** `evlog` has no runtime dependencies of its own. Signals and Telemetry are separate packages.
- **Node.js 22 or later** for evlog 3. Edge runtimes and browsers run the core too.
- **A habit.** The payoff comes from calling `log.set()` where the context is, instead of logging a line. [Map](/map) shows which entry points have not picked it up yet.

evlog does not store or query your logs. It produces the events and sends them to the backend you already have, through a :term[drain]{of="drain"}.
