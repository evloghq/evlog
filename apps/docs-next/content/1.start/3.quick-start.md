Three changes to a route you already have, and one request prints a single event with the user, the cart and the reason the payment failed.

::callout{icon="i-lucide-info" color="neutral"}
This page assumes evlog is [installed](/start/installation) and wired into your framework.
::

## 1. Add context where you have it

The integration creates a logger when the request starts and emits it when the response ends. You only add fields to it. On Lambda and in a script, nothing frames the work for you, so you create the logger and emit it yourself:

::framework-tabs
```typescript [Nuxt] server/api/checkout.post.ts
export default defineEventHandler(async (event) => {
  const log = useLogger(event)
  const { cartId } = await readBody(event)

  const cart = await db.findCart(cartId)
  log.set({ user: { id: cart.userId }, cart: { items: cart.items.length, total: cart.total } })

  return { ok: true }
})
```

```typescript [AWS Lambda] src/checkout.ts
import type { APIGatewayProxyEventV2 } from 'aws-lambda'
import { createRequestLogger } from 'evlog'

export async function handler(event: APIGatewayProxyEventV2) {
  const log = createRequestLogger({ method: 'POST', path: '/api/checkout' })

  try {
    const { cartId } = JSON.parse(event.body ?? '{}')
    const cart = await db.findCart(cartId)
    log.set({ user: { id: cart.userId }, cart: { items: cart.items.length, total: cart.total } })

    return { statusCode: 200, body: JSON.stringify({ ok: true }) }
  }
  finally {
    log.emit()
  }
}
```

`log.set()` merges into the event already in flight, so calling it from three helpers is the same as calling it once. Nothing prints until the request ends:

```bash [Terminal]
  ├─ user: id=usr_123
  ├─ cart: items=3 total=9999
  └─ requestId: 4a8ff3a8-...
```

## 2. Throw an error that explains itself

A failure that only carries a message is a search through logs later. `createError()` carries the reason and the fix with it:

```typescript [route:POST /api/checkout]
import { createError } from 'evlog'

if (!charge.success) {
  throw createError({
    status: 402,
    message: 'Payment failed',
    why: charge.declineReason,
    fix: 'Try a different payment method',
  })
}
```

The same event now ends with the error, and the HTTP response carries `why` and `fix` under `data` for your client to show. On Nuxt, import `createError` from `evlog`: the auto-imported one is Nuxt's, and it drops `why`, `fix` and `link`. [Errors](/errors) covers catalogs and `parseError()`.

## 3. Send it somewhere

In development the event prints to your terminal. In production it goes through a drain. Add one to the config file and every route uses it:

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { createAxiomDrain } from 'evlog/axiom'

export default defineEvlog({
  service: 'my-app',
  drain: createAxiomDrain(),
})
```

`createAxiomDrain()` reads `AXIOM_API_KEY` and `AXIOM_DATASET` from the environment. [Drains](/drains) lists every destination.

## What you need on day one

Two calls: `log.set()` and `createError()`. A route still calling `console.log` next to a route using `log.set()` is a normal intermediate state: both write to the same output, and neither breaks the other. Start with the handler you last debugged in production, or let [`evlog map`](/map) rank them for you.

[Sampling](/events/sampling), [catalogs](/errors/catalogs) and [enrichers](/events/enrichers) are opt-in. Reach for each one the day you miss it.
