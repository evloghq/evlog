An assistant writing your handlers keeps reaching for `console.log` and `throw new Error(...)` until something in the repository tells it not to. `evlog agents` writes that something: a block of conventions in `AGENTS.md`, and the [skills](/skills) that back it.

```bash [Terminal]
evlog agents
```

```text [Output]
nuxt

✓ created AGENTS.md
✓ installed the evlog skills for Claude Code, Codex and the others
  ran      npx --yes skills add https://www.evlog.dev --agent universal --agent claude-code --global --yes
```

On a terminal the command shows the plan and waits for your confirmation. `--yes`, `--json`, CI or a missing terminal skip the confirmation.

## Flags

| Flag | What it does |
| --- | --- |
| `--skills <list>` | Comma-separated skill names, passed to `npx skills add --skill`. Default: all of them |
| `--no-skills` | Still writes `AGENTS.md` and skips the skill installation, so nothing is spawned |
| `--local` | Installs the skills into this project. The default is global, for every project |
| `--source <url>` | Where the skills are published, a plain http(s) origin. Default: `https://www.evlog.dev` |
| `--dry-run` | Shows the plan without writing or running anything |
| `--yes`, `-y` | Applies without confirming |

Earlier versions took `--global`. Global is now the default, so that flag is gone.

```bash [Terminal]
evlog agents --skills review-logging-patterns
evlog agents --local
evlog agents --no-skills
evlog agents --dry-run
```

The command exits `1` when the skills CLI fails or the `AGENTS.md` markers are broken, and `2` on a `--source` or `--skills` value it refuses.

## The block in AGENTS.md

`AGENTS.md` is created if missing. Otherwise the evlog block is replaced in place, between `<!-- evlog:start -->` and `<!-- evlog:end -->`, and everything outside those markers is left exactly as it was.

A marker counts when it stands alone on its line, outside a code fence, so you can quote one in a sentence or an example. If the pair is broken (one marker deleted, a block pasted twice, the end before the start), the command stops with `cli.AGENTS_MARKERS_UNPAIRED` and leaves the file as it is, because any rewrite would delete or duplicate text that is yours. Restore the pair around the evlog section, or delete the leftover marker with the old section, then run it again.

The block is short because it is loaded into every agent turn. It states the rules: one wide event per operation, grouped context, structured errors, audit on sensitive actions, and what never gets logged. It points at the skills for the detail. The logger accessor it names follows your framework: `useLogger(event)` on Nuxt and Nitro, `useLogger()` from your `lib/evlog.ts` on Next.js, `req.context.log` on TanStack Start, `c.get('log')` on Hono. When no framework is detected the block is still written, with a generic accessor.

`CLAUDE.md` is not written, and an existing one is never touched. Most agents read `AGENTS.md` directly, and Claude Code does too unless a `CLAUDE.md` sits above it. For an explicit pointer, add a one-line `@AGENTS.md` yourself.

Running the command again refreshes the block against the current CLI. Anything already identical is reported and not rewritten, so a second run leaves the working tree clean. Run it after you upgrade `evlog`.

## How the skills are installed

`evlog agents` does not copy skill files. It runs [`npx skills`](https://github.com/vercel-labs/skills), the same way [`evlog init`](/cli/init) runs your package manager. Every agent reads a different directory (`.claude/skills`, `.agents/skills`, `.codex/skills`), and the skills CLI already resolves them. It keeps no manifest, so a copy written behind its back would be a second one it could never update. With one copy, `npx skills update`, `remove` and `list` keep working on it.

Before it runs anything, the command looks for evlog skills already installed, for any agent, in the project or globally, and leaves them alone if it finds them:

```text [Output]
· AGENTS.md is up to date
✓ skills already installed · .agents/skills, .claude/skills
   npx skills update to refresh them
```

The command it runs is the one it shows, argument for argument:

```bash [Terminal]
npx --yes skills add https://www.evlog.dev --agent universal --agent claude-code --global
```

| Part | When it changes |
| --- | --- |
| `--agent universal --agent claude-code` | Never. `universal` is the shared `.agents/skills` directory that Codex and other agents read, and Claude Code gets a link into it. Naming the agents keeps the skills CLI from installing into every agent it detects |
| `--global` | Left out with `--local` |
| `--skill <names>` | Added with `--skills` |
| A trailing `--yes` | Added when the run is non-interactive, so nothing blocks on a prompt. Interactively the skills CLI can ask questions of its own, and `evlog agents` hands over the terminal |

Interactively the command is shown in the plan you confirm and again as the step starts. Non-interactively it appears in the report the run prints afterward. `--dry-run` shows it without running anything.

Running it means running third-party code, so four things are worth knowing:

- **It is not pinned.** `npx` resolves the latest [`skills`](https://www.npmjs.com/package/skills) at run time, so the version you get today is not the one you got last month. For a fixed version, pass `--no-skills` and run your own `npx skills@<version> add https://www.evlog.dev`.
- **`--source` is validated.** It must be a plain `http:` or `https:` origin: letters, digits, and `. _ ~ : / -` only, so no query string and no shell metacharacters. `--skills` entries must be lowercase dashed names. On Windows the spawn needs a shell to resolve `npx`, so both are checked before anything is spawned.
- **Nothing is spawned without a decision.** `--no-skills` skips it entirely, and the interactive flow does not reach the command until you confirm the plan.
- **It needs the network and a recent Node.** If the skills CLI fails, from no network or no `npx`, the block is still on disk without its pointer to the skills, and the command reports the failure and exits `1`. `skills` 1.9.0 declares Node 22.20 or later and does not start on Node 22.0 or 22.1, so pass `--no-skills` on those two versions.

`evlog agents --no-skills` writes `AGENTS.md` and never touches the network.

## As part of evlog init

`evlog init` offers this as its last question. The `AGENTS.md` write lands in the same plan as the rest of the setup, with one confirmation, and the skills install runs alongside the package manager. Skip it with `--no-agents`:

```bash [Terminal]
evlog init --no-agents
```
