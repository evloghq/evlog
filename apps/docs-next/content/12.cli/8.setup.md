`evlog setup <target>` prepares a platform so its logs can be read back. It has two targets: `vercel`, and `eve` for an eve agent's trace instrumentation. Any other target exits `2`.

## Read a Vercel project's logs

On Vercel, evlog prints one JSON line per event, and Vercel keeps those lines as the project's runtime logs. [`evlog logs --source vercel`](/cli/logs#read-a-vercel-deployment) reads them back through a Vercel Connect connector. Set it up once, from the project directory:

```bash [Terminal]
npx evlog setup vercel
```

The command uses the `vercel` CLI when it is installed and `npx vercel@latest` otherwise. It goes through five steps and skips each one that is already done, so you can run it again safely:

1. Link the directory with `vercel link`, if it is not linked yet.
2. Ask which connector to read through. The list holds the team's Vercel connectors that store an API key, such as the `vercel/mcp` one an agent's Vercel MCP connection uses. **Create a new connector** asks for a name.
3. Attach the connector to the project, for production and development by default, after saying what the attachment grants.
4. Write the connector to `evlog.config.ts` as `logs: { vercel: { connector: 'vercel/mcp' } }`.
5. Read the last hour of runtime logs through the connector, to check.

evlog picks no connector on its own, `vercel/evlog` included. Every read goes through the connector your config names.

::callout{icon="i-lucide-key" color="neutral"}
Attaching a connector gives code deployed to those environments the authority of the key the connector stores, whatever that key may read or change on the team. Give the connector the narrowest token Vercel lets you create for the team. When that still reaches more than this project's logs, create the token as a team member whose role grants no more than reading.
::

### Create a connector

When setup creates a connector, pick **API Key** when the Vercel CLI asks how to connect, and paste a [Vercel access token](https://vercel.com/account/tokens) scoped to the team. Connect stores it, and evlog only receives it for the length of a read. A token scoped to your personal account, or one that has expired, gets a 403 on every read. Replace the key in the connector's settings.

A connector's UID is what code passes to Connect, so rename it only together with every caller. The connector shows in the project's Connect tab, where you can revoke it. Using a connector the team already has hands its key to this project the same way.

### Choose the environments

Preview stays out unless you name it. A preview runs code from any branch, so `--environment production,preview,development` hands the key to every branch pushed. A connector that is already attached keeps the environments it has. Change them in the project's Connect tab.

### What happens to your config

An existing `evlog.config.ts` is edited only to add `logs.vercel.connector` where none is set, and setup prints the lines it added. The rest of the file stays as written. When the file computes its config or already names another connector, setup leaves it alone and prints the line to set. Without a config file, setup creates `evlog.config.ts`.

### Run it without a terminal

In CI or with `--json` there is nobody to ask, so pass the connector:

```bash [Terminal]
npx evlog setup vercel --connector vercel/mcp             # one the team has
npx evlog setup vercel --connector vercel/evlog --create  # a new one
```

A run with neither stops with exit code `2` and lists the team's connectors. `--create` on a connector the team already has, or a connector the team lacks without `--create`, stops with exit code `1`.

### Check each step

`--check` reports each stage on its own line and changes nothing:

```bash [Terminal]
npx evlog setup vercel --check
```

| Stage | What it checks |
| --- | --- |
| `linked` | The directory has a `.vercel/project.json` |
| `oidc` | Your `vercel login` gets the project's OIDC token |
| `connector` | `logs.vercel.connector`, or `--connector`, names a connector the team has. Warns when it is not an API-key connector |
| `attached` | The connector is attached to the project |
| `token` | Vercel Connect exchanges the OIDC token for a token |
| `read` | The last hour of runtime logs can be read |
| `traces` | For an eve agent: each agent's `instrumentation/` exports `evlogTraces()`. Warns when one does not |

A connector whose stored key gets a 403 fails on `read`, not on `token`: Connect issuing a token does not prove the key behind it may read runtime logs. The stages after the first failure are listed as skipped. The command exits `1` when a stage fails, names what to run, and says which of those steps is interactive. With `--json` it returns `stages` and `ready`.

## Add trace ids to an eve agent

`evlog setup eve` writes `instrumentation/evlog.ts` into each agent of an [eve](/extend/eve) project: `agent/`, or every `agents/<name>/agent/` of a workspace. The file puts each turn's `traceId` and `invoke_agent` `spanId` on its wide event. It is the same file [`evlog init`](/cli/init#eve-agents) writes.

```bash [Terminal]
npx evlog setup eve
```

```typescript [agent/instrumentation/evlog.ts]
import { evlogTraces } from '@evlog/eve/instrumentation'

// Puts each turn's traceId and invoke_agent spanId on its wide event.
// Reads span ids only: it exports nothing and adds no sampling.
export default evlogTraces()
```

It never overwrites. An agent that already has a file in `instrumentation/` exporting `evlogTraces()` is reported as present. An `instrumentation/evlog.ts` that does something else is left as it is, the command prints the line to add, and it exits `1`. With `--check` nothing is written, and a missing file exits `1`.

## Flags

| Flag | What it does |
| --- | --- |
| `vercel`, `eve` | The target. Required |
| `--check` | Reports each stage and changes nothing |
| `--connector <uid>` | `vercel`: the connector to read through, such as `vercel/mcp`. Default: `logs.vercel.connector` in `evlog.config.ts`, asked for when neither names one |
| `--create` | `vercel`: creates the `--connector` connector, whose UID must be `vercel/<name>`, and does not use one the team has |
| `--environment <a,b>` | `vercel`: the environments to attach the connector for. Default: `production,development` |
| `--cwd <dir>` | Sets up another project |
| `--json` | The result as JSON on stdout. Implies no prompt |

An environment name that Vercel would not accept, or a `--create` UID outside `vercel/<name>`, exits `2`.
