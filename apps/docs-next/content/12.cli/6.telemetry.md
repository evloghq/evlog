The evlog CLI records one anonymous wide event per run, so the maintainers know which commands people use and which ones fail. It uses the [`@evlog/telemetry`](/telemetry) package, the one you can add to a CLI of your own. This page covers what the evlog CLI itself sends.

```bash [Terminal]
evlog telemetry status
```

```text [Output]
Telemetry: enabled (preference: enabled)
Data directory: ~/.config/evlog-cli/telemetry
```

`status` then prints the full disclosure: every field, its type, and what it is for. The disclosure is generated from the code that sends the event.

| Command | What it does |
| --- | --- |
| `evlog telemetry status` | Prints the current state, the data directory, and the full disclosure |
| `evlog telemetry enable` | Enables anonymous usage telemetry |
| `evlog telemetry disable` | Disables it and deletes the events not yet delivered |

`evlog telemetry` with no subcommand is a usage error and exits `2`.

## Turn it off

Any one of these is enough:

```bash [Terminal]
# persisted preference
evlog telemetry disable

# per-run, or in a shell profile
EVLOG_TELEMETRY=0 evlog map

# the cross-tool standard, respected everywhere
export DO_NOT_TRACK=1
```

`evlog telemetry disable` also deletes anything that was queued and not yet delivered, and the `disable` run itself is neither sent nor queued. `evlog telemetry enable` turns it back on.

Both variables read `true`, `yes` and `on` like `1`, and `false`, `no` and `off` like `0`, in any case. `EVLOG_TELEMETRY=false` and `DO_NOT_TRACK=true` therefore opt out too. `DO_NOT_TRACK` wins over `EVLOG_TELEMETRY`, which wins over the persisted preference.

## What is in an event

Every run sends one event with:

- The command name, how long it took, and whether it succeeded.
- The error code when it did not: the CLI's own id, such as `cli.UNKNOWN_FLAG` or `cli.LOGS_NO_SINK`, never the message.
- The Node version, the OS and the architecture.
- Whether the run was in CI and on which provider, whether stdout is a terminal, and whether an AI coding agent was driving it.
- The flags you passed.
- A hashed machine id, left out entirely in ephemeral CI.

A run fails when the command stops on an error, such as a flag it cannot read or a log directory that does not exist. A `--min-score` or `--baseline` gate that fails is a successful run, recorded as `mapGateFailed`.

Flags are recorded as the ones you passed. Booleans and numbers keep their value. A string value is recorded as `<set>` and not by content, unless the flag is on an allowlist. Positional arguments are never recorded, and a flag left at its default is not recorded either, so `evlog map` on its own sends an empty `flags` object. A flag the command does not declare is dropped with its name, so a mistyped or pasted argument never leaves your machine.

No file path, source code, project name, route path or argument value is sent.

## What each command adds

Every string below is an id from the CLI's own closed set, checked against an allowlist before it is sent. A value outside the list is dropped, not transmitted. Everything read out of your source is a count.

| Command | Recorded | Example |
| --- | --- | --- |
| `init` | Framework, development drain, sampling preset | `nuxt`, `fs`, `medium` |
| `init` | One flag per production drain, extra and enricher chosen | `initProdAxiom: true` |
| `init` | Counts: files written, manual steps left, doctor failures, production drains | `initFilesWritten: 4` |
| `init` | Whether the run was interactive, cancelled or a dry run, and whether the `AGENTS.md` step ran and the skills install failed | `initInteractive: true` |
| `init` | Whether an offer had anything behind it | `initHadRepeatedErrors: true` |
| `map` | Score and grade | `mapScore: 72`, `mapGrade: good` |
| `map` | Entry point counts by coverage | `mapEntryPoints: 34`, `mapDark: 9` |
| `map` | Per kind: entry points and dark entry points | `mapKindPage: 12`, `mapDarkPage: 3` |
| `map` | Per sensitivity: money, auth and PII entry points, and dark | `mapSensitiveMoney: 2`, `mapDarkMoney: 1` |
| `map` | Per rule: how many entry points failed it, how many waived it | `mapFailWideEvent: 6`, `mapSuppressedWideEvent: 2` |
| `map` | Which gate ran, and whether it failed | `mapGate: baseline`, `mapGateFailed: true` |
| `logs` | Which view ran | `logsView: errors` |
| `logs` | Whether it followed the file, read a URL, or asked a question | `logsFollow: true`, `logsUrl: false`, `logsAsk: false` |
| `logs` | Counts: events matched, `--where` clauses, sources read | `logsEvents: 50`, `logsWhere: 2`, `logsSources: 1` |
| `doctor` | Counts of checks passed, warned and failed, frameworks detected, and whether the project is a workspace | `checksFailed: 0` |
| `doctor` | Whether evlog, the config and the local logs were found | `doctorEvlogFound: true` |

What these fields leave out:

- `init` never records your service name, package names, paths, or anything read out of your source. `initHadRepeatedErrors` says only whether the scan found something, never what it found.
- `map` records no route path, no file name, no project name and no snippet. A kind absent from the project is left out, not sent as zero. The dark count for a kind that is present and fully covered is `0`, so `mapKindPage: 12, mapDarkPage: 3` always reads as 12 pages, 3 dark. Sensitivity is a heuristic classification from imports and path terms, so the per-sensitivity counts estimate what the classifier found.
- `logs` records no event, no field name, no filter value, no path, no URL and no question. A `--where` clause counts as one, whatever it says.

## When events are sent

Events wait in the data directory until a later command sends them: 15 minutes after the last successful flush (60 minutes in CI), or once 20 events have queued. The data directory is `evlog-cli/telemetry` under `XDG_CONFIG_HOME`, or under `~/.config` when that is not set.

## Inspect a run before trusting it

To see what a run would send, without sending it:

```bash [Terminal]
EVLOG_TELEMETRY_DEBUG=1 evlog map
```

The payload is printed to stderr. A debug run makes no request and queues nothing, so a later run never sends the event it printed.
