You followed the [installation guide](/start/installation) and nothing shows up. `evlog doctor` says which part of the setup is missing.

```bash [Terminal]
npx evlog doctor
```

It prints one line per check under two headings, `ENVIRONMENT` and `EVLOG`, then the counts of checks that passed, warned and failed.

## What it checks

| Check | Passes when | Warns or fails when |
| --- | --- | --- |
| `node` | Always. It shows the Node version in use. On a Node older than 22 the CLI stops before any check runs | Never |
| `project` | A `package.json` was resolved | Warns when none is found above the working directory |
| `stack` | A framework was detected and evlog reaches the app. The check is left out when no framework is detected | Warns when a framework was detected and evlog is not installed |
| `evlog` | `evlog` resolves from `node_modules`, or reaches the app through a wrapper package | Warns when it is declared in `package.json` and not installed, or missing entirely |
| `cli` | Always. It shows the CLI version that answered and whether `package.json` pins `@evlog/cli` | Never. Without a pin, the hint gives the install command |
| `config` | [`evlog.config.ts`](/cli/config) was read, and the config it extends was found. The check is left out when there is no config | Fails when the file cannot be read: a syntax error, a misspelt setting, or a CLI setting computed at runtime |
| `logs` | `.evlog/logs` exists, or the [file system drain](/drains/fs) is configured. The check is left out when there is no local drain | Never |

In a workspace, the first line names the workspace kind and `project` shows which package was resolved. That is the fastest way to notice you are diagnosing the repo root and not your app.

A local drain is optional. The file system drain creates `.evlog/logs` on first write, so a configured drain passes before any event exists, and the check reads `empty sink`.

## Exit code

`0` when nothing failed, `1` when a check failed. Warnings do not fail the command, because a project that has not written logs yet is not broken. Today only `config` can fail.

## Read the result as JSON

```bash [Terminal]
evlog doctor --json | jq '.checks'
```

The payload carries `project` (`cwd`, `root`, `packageDir`, the workspace `kind`, the package `name`, the detected `stack`), `checks`, each with its `id`, `status`, `message` and `hint`, and the `summary` counts.

With `--debug`, each warning and failure is also a finding on the debug event, with a code from the CLI's own [error catalog](/errors/catalogs): `cli.EVLOG_NOT_FOUND`, `cli.EVLOG_DECLARED_NOT_INSTALLED`, `cli.PROJECT_NO_PACKAGE` or the `cli.CONFIG_*` code of the config error, each with a `why` and a `fix`.

## Flags

`doctor` has no flags of its own. It takes the [global flags](/cli#global-flags):

| Flag | What it does |
| --- | --- |
| `--cwd <dir>` | Diagnoses another directory |
| `--json` | Machine-readable output on stdout |
| `--debug` | Prints the steps the command went through |
| `--no-header` | Skips the branded header |

Once the checks pass, [`evlog map`](/map) shows which entry points still log nothing.
