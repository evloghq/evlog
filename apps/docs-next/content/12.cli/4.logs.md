`evlog logs` reads the events the [file system drain](/drains/fs) wrote and prints one line per request, with what mattered at the end of it. It reads files and never touches the app.

```bash [Terminal]
evlog logs
```

```text [Output]
6 events · .evlog/logs

08:00:00  GET    /api/health                                 200      2ms
10:00:00  POST   /api/checkout                               402    412ms  ✗ Error: Payment processing failed · Card declined by issuer
10:30:00  GET    /api/reports                                200    1.2s   report.id=r-1
11:00:00  POST   /api/refund                                 200     80ms  audit billing.refund user:usr_42 → invoice:inv_1 success
11:30:00  GET    /api/items                                  500     30ms
11:45:00  GET    /api/items                                  warn   700ms  user.id=usr_7

evlog logs errors — the 2 that failed · evlog logs <requestId> — one request in full · evlog logs slow — worst first
```

The newest event is at the bottom, like `tail`. The command reads both the compact and the `pretty: true` layout, across the dated files, one event at a time, so memory does not grow with the log.

## Views

| Command | Shows |
| --- | --- |
| `evlog logs` | The last 50 events, oldest first |
| `evlog logs errors` | Events that failed: a `5xx` status, an `error` or `fatal` level, or an `error` block |
| `evlog logs slow` | Events over 500ms, worst first. `--over 1s` moves the bar |
| `evlog logs <requestId>` | Every event carrying that id, in full: request, error with `why`, `fix` and `link`, audit record, then the business fields |
| `evlog logs sessions` | One summary per AI session (`gen_ai.conversation.id`), latest first |
| `evlog logs stats` | Per route: count, errors, p50 and p95, routes with the most errors first. Then counts by status class and by level |

A request id matches `requestId`, `traceId`, `spanId` or the parent request id. A prefix of eight characters or more is enough, so the first block of a UUID works. A complete id shows only the events carrying it whole, so `wrun_1:turn_1` does not pull in `turn_10`.

A session summary gives the turns and how each ended, failed tool calls, the model and its tool calls, tokens with cache reads, the provider-reported cost, the slowest turn and the latest failure. Working time (the turns' durations summed) and elapsed time (first turn's start to last event) are kept apart. Each token count sums the turns that reported it, with `turnsReporting` next to it, and a field no turn reported is left out, not written as 0.

## Flags

Filters compose with any view.

| Flag | What it does |
| --- | --- |
| `--since <when>` | Only events after: a duration back from now (`15m`, `2h`, `3d`) or a date (`2026-10-01`, `2026-10-01T09:00`) |
| `--until <when>` | Only events before, same spellings. Without it a read stops at now, so an event stamped ahead of the clock is left out. `--follow` has no end |
| `--level <a,b>` | Only these levels: `trace`, `debug`, `info`, `warn`, `error`, `fatal` |
| `--path <path>` | Only requests on this exact path |
| `--status <n>` | Only this status (`404`) or class (`4xx`) |
| `--where <clause>` | Only events where a field matches. Repeat the flag for several clauses, and all must hold |
| `--session <id>` | Only one AI conversation: the events whose `gen_ai.conversation.id` is `<id>`, such as an eve session's turns |
| `--over <duration>` | For `slow`: what a request has to exceed. Default `500ms`. A bare number is milliseconds |
| `--limit <n>` | Most events to show, or sessions for `sessions`. Default 50 |
| `--expect <a,b>` | Refuses to answer from another store or environment: `files`, `vercel`, `production`, `preview`, `development` |
| `--ask <question>` | Ranks the selected events by a yes/no question a decision model answers |
| `--model <id>` | With `--ask`: the decision model, as an AI Gateway id. Default: the `@evlog/signals` default |
| `--dry-run` | With `--ask`: prints how many model calls and input tokens it would take, and sends nothing |
| `--dir <path>` | Reads another directory. Default: the project's `.evlog/logs` |
| `--source <store>` | `files` (default) or `vercel`, the linked Vercel project's runtime logs |
| `--url <endpoint>` | Reads the [memory drain](/drains/memory)'s dev endpoint: a JSON array of events, or `{ "events": [...] }` |
| `-f`, `--follow` | Keeps reading as the app writes, like `tail -f`. `Ctrl-C` stops |
| `--json` | The events as JSON on stdout |
| `--cwd <dir>` | Another project in the workspace |

```bash [Terminal]
evlog logs errors --since 1h
evlog logs slow --over 2s --path /api/reports
evlog logs --status 5xx --level error,fatal --limit 20
evlog logs -f --path /api/checkout
```

An event delivered twice under the same `idempotencyKey`, for example by a drain write that was retried, shows once. Events without one are never merged.

`--dir`, `--limit` and `--source` can be set once for the project in [`evlog.config.ts`](/cli/config), as `logs.dir`, `logs.limit` and `logs.source`. The flag wins when both are set.

## Exit codes

| Code | When |
| --- | --- |
| `0` | The read worked, even when nothing matched |
| `1` | There are no local logs and no file system drain, the `--url` endpoint cannot be read, `--expect` does not match, a Vercel read failed, `--ask` failed, or `evlog.config.ts` cannot be read |
| `2` | A `--since`, `--until`, `--level`, `--status`, `--over`, `--limit`, `--where` or `--source` value cannot be read, or two flags do not combine |

A value that cannot be read stops the command. It never widens the query without saying so. `--expect production` on local files written in development exits `1` and prints no empty list.

## Filter on any field

A `--where` clause is a dotted field, an operator, and a value. The field can sit anywhere in the event, so the business fields you set with `log.set()` are there to be queried.

| Clause | Matches when |
| --- | --- |
| `user.id=usr_42` | The field equals the value. `true`, `false` and numbers are read as such |
| `audit.outcome!=success` | The field differs |
| `payment.amount>5000` | Greater. Also `>=`, `<`, `<=` |
| `error.message~declined` | The field matches the regular expression, case-insensitive. An object is matched as JSON |
| `audit` | The field is present |
| `!error` | The field is absent |

```bash [Terminal]
evlog logs --where 'payment.amount>5000' --where audit.outcome=failure
evlog logs errors --where 'error.why~card declined'
evlog logs stats --where user.plan=pro
evlog logs -f --where '!error' --where 'durationMs>1000'
```

Numbers compare as numbers, everything else as text. A value is a number when it spells one exactly: `5000`, `-3`, `12.5`. Leading zeros, an exponent, or more digits than a 64-bit float holds keep it as text, so `zip=00123` and a 19-digit id match only themselves. The same reading applies to a field that arrived as text. `>`, `>=`, `<` and `<=` against a number never match a field that is not one.

Quote the whole clause when it carries `>`, `<` or `!`, which the shell reads as redirection or history, and when the value has a space.

## Ask a question no filter can

Some questions are not a field. "The customer tried to pay but did not end up with a confirmed order" covers a declined card, a payment taken without an order, and the cases nobody has written a `--where` for. `--ask` puts the question to a decision model and ranks the events by the probability that the answer is yes:

```bash [Terminal]
evlog logs --path /api/checkout --ask 'The customer tried to pay but did not end up with a confirmed order'
```

```text [Output]
3 events · .evlog/logs

ranked by P(yes) · The customer tried to pay but did not end up with a confirmed order

0.96  10:05:00  POST   /api/checkout                          402    412ms  ✗ Error: Payment processing failed · Card declined by issuer
0.81  10:10:00  POST   /api/checkout                          200    380ms  cart.items=2 payment.provider=stripe
0.03  10:20:00  POST   /api/checkout                          200    290ms  cart.items=1 order.id=ord_9

model calls 3 · input tokens 1429
```

Read the result as a ranking, not a verdict, and open the top of the list instead of filtering on a probability.

The filters run first and the question ranks what is left, so the model sees at most `--limit` events. Three things keep a large `--limit` affordable:

- Each event is cut down before it is sent: every string stops at 256 characters, every array at 10 items and every stack at 3 lines, each cut saying how much it left out. No field is dropped.
- Events that differ only in what is per-event by construction share one call. The timestamp, the request id, the idempotency key, and the trace, span and parent span ids are left out of the comparison, and durations and token counts are floored to two significant figures, so 412ms and 419ms match and 412ms and 490ms do not. Every other value has to match, ids included. A thousand health checks cost a handful of calls, and a thousand checkouts with their own order ids cost a thousand.
- `--dry-run` prints the events, the calls after grouping and the input tokens, and sends nothing.

```bash [Terminal]
evlog logs --limit 10000 --ask 'The customer tried to pay but did not end up with a confirmed order' --dry-run
```

```text [Output]
10000 events · .evlog/logs

The customer tried to pay but did not end up with a confirmed order

would judge 10000 events in 8457 model calls, about 6765112 input tokens. Nothing was sent
```

The token count is fitted to what `typesafe-ai/jev` reports, and another model tokenizes differently. The calls run one at a time, so the length of a run follows the call count.

`--ask` has four requirements and limits:

- `@evlog/signals` 0.2.0 or later and `ai` 7 from 7.0.130 (`>=7.0.130 <8`), installed in the project beside `@evlog/cli`: `pnpm add -D @evlog/cli @evlog/signals 'ai@^7.0.130'`, then `pnpm evlog logs --ask …`. The CLI loads them from where it is installed, so a copy fetched by `npx` or `bunx` does not find them.
- A key for the model: `AI_GATEWAY_API_KEY`, through Vercel AI Gateway. `--model liquid/d1` picks another model by its gateway id. Without it the question goes to the [`@evlog/signals`](/signals) default, `typesafe-ai/jev` today.
- A failed call, or an event still over 100000 characters of JSON once cut down, stops the run with the reason and exits `1`. An event the model declines to answer is left out.
- It does not combine with `--follow`, `stats` or `sessions`.

Each event leaves your machine cut down as above, less any `signals` column it already carries. Narrow with `--path`, `--since` or `--where` before you ask about anything sensitive.

## JSON output

`--json` returns one envelope: where it read (`origin`, with `kind` `files`, `url` or `vercel`, and the environments), the time range read (`window`), the view, how many events matched and how many are shown, `coverage`, and the events.

```bash [Terminal]
evlog logs errors --since 2026-11-20 --until 2026-11-21 --json
```

```json
{
  "schemaVersion": 2,
  "sources": [".evlog/logs"],
  "origin": { "kind": "files", "environments": ["development"] },
  "window": { "since": "2026-11-20T00:00:00.000Z", "until": "2026-11-21T00:00:00.000Z" },
  "view": "errors",
  "count": 1,
  "matched": 1,
  "coverage": { "complete": true },
  "events": [ { "requestId": "wrun_A:turn_1", "level": "warn", "status": 200, "eve": { "outcome": "completed", "failedCalls": 1 }, "error": { "message": "Refund service timed out" } } ]
}
```

A tool that failed and recovered leaves a `warn` event with an `error` block, so `errors` lists it even with a 200 status.

| View or flag | What changes in the envelope |
| --- | --- |
| `slow` | Adds `over`, the threshold in milliseconds, so "nothing was slow" always reads "nothing over N ms" |
| `sessions` | `sessions` and `sessionsMatched` in place of `events` |
| `stats` | `stats` (`total`, `errors`, `byRoute`, `byStatus`, `byLevel`) in place of `events` |
| `--ask` | `question`, `answers`, each a `{ probability, event }`, `shared`, the events that took another event's verdict, and `signals`, the counters of the model calls, in place of `events` |
| `--ask --dry-run` | `question` and `estimate` in place of `events` |
| `--follow` | Each new event is one JSON line on stdout, since a stream has no end |

`coverage.complete` is `false`, with `reasons`, when the read was cut short: Vercel cut lines, or more lines were left past the 10,000 read. An empty result then says nothing about the events it did not reach.

The `analyze-logs` [skill](/skills) calls `evlog logs` first and reads the files itself only when the CLI is not available.

## Read a workspace or a running app

From a monorepo root with no `.evlog/logs` of its own, the command reads every app that has one (`apps/*`, `packages/*`, `examples/*`, `services/*`), merges the events by time, and shows the app in a column. `--cwd apps/web` reads one app, and `--dir` reads one directory.

An app on the memory drain, on Cloudflare Workers for instance, has no files to read, but it can expose `readMemoryLogs()` on a dev route. Point `--url` at it:

```bash [Terminal]
evlog logs errors --url http://localhost:8787/_evlog/logs
```

Every view and filter works the same, and `-f` polls the endpoint once a second. A failed poll is a gap, not the end, since the app restarting under a follower is normal. If the endpoint stays quiet, the run says so once and keeps trying.

## Read a Vercel deployment

On Vercel, evlog prints one JSON line per event, and Vercel keeps those lines as the project's runtime logs. `--source vercel` reads them back, so a deployment needs no drain for `evlog logs` to work on it. Run [`evlog setup vercel`](/cli/setup) once from the project directory, then:

```bash [Terminal]
evlog logs --source vercel
evlog logs errors --source vercel --since 2h
evlog logs --source vercel --session wrun_01M7NNNW
```

Until `logs.vercel.connector` names a connector, `--source vercel` stops with `Vercel logs are not set up` and points at `npx evlog setup vercel`. It never guesses one. Reading local files needs none of this.

No token goes in an environment variable or in your code. The CLI asks Vercel for the linked project's OIDC token with your `vercel login`, exchanges it for a short-lived token from the connector, and takes the team, project and environment from the OIDC token itself, so a read never reaches another project.

| Behaviour | Detail |
| --- | --- |
| Default source | `logs: { source: 'vercel' }` in `evlog.config.ts` makes Vercel the default. `--source files`, `--dir`, `--url` and `-f` still read local files |
| Header | Every run prints what it read above the events, such as `Vercel prj_… (production) · 2026-11-19 12:00 → 2026-11-20 12:00 UTC` |
| Window | Without `--since`, the last day, which is Pro's log retention. Hobby keeps an hour |
| Size | At most the newest 10,000 log lines. `--session` narrows them on Vercel's side first |
| Cut lines | When lines are left, or Vercel cut a line to its size limit so it no longer parses as an event, the output says so under the header and in `notes` with `--json` |
| `--follow`, `--dir`, `--url` | Do not apply, and stop the command with exit code `2` |

`evlog logs` reads local files, a dev endpoint and Vercel runtime logs. A hosted drain such as Axiom or Datadog has its own query language and UI, and this command does not wrap them.
