Your logs say a request returned 502. A signal says it was Stripe, that a retry would have worked, and that it is not worth waking anyone. Your logs say a checkout returned 200. A signal says the customer left without an order.

```json [Wide Event]
{
  "method": "POST",
  "path": "/api/checkout",
  "status": 502,
  "error": { "name": "FetchError", "message": "request to https://api.stripe.com/... failed, reason: read ECONNRESET" },
  "signals": {
    "fault": { "value": "upstream", "confidence": 0.93 }
  }
}
```

`@evlog/signals` asks a decision model one question per matching event and writes the answer onto the event, with a confidence. `WHERE signals.fault.value = 'upstream' AND signals.fault.confidence > 0.9` is then a query like any other.

## Ask your first question

```bash [Terminal]
pnpm add @evlog/signals ai
```

A signal is a name, a predicate that picks the events it applies to, and the question:

```typescript [server/signals.ts]
import { defineSignal } from '@evlog/signals'

export const fault = defineSignal({
  name: 'fault',
  when: e => (e.status ?? 0) >= 400,
  ask: 'Who is responsible for this failure?',
  choice: {
    client: 'Bad input, expired session, client mistake',
    app: 'A bug or misconfiguration in our own code',
    upstream: 'A third-party dependency failed',
  },
})
```

`createSignals()` returns an evlog plugin. Nuxt and Nitro take its two hooks, every other integration takes it in `plugins`:

::framework-tabs
```typescript [Nuxt] server/plugins/evlog-signals.ts
import { createSignals } from '@evlog/signals'
import { fault } from '../signals'

export default defineNitroPlugin((nitroApp) => {
  const plugin = createSignals({ signals: [fault] })
  nitroApp.hooks.hook('evlog:emit:keep', plugin.keep)
  nitroApp.hooks.hook('evlog:enrich', plugin.enrich)
})
```
```typescript [Hono] src/index.ts
import { evlog } from 'evlog/hono'
import { createSignals } from '@evlog/signals'
import { fault } from './signals'

app.use(evlog({ plugins: [createSignals({ signals: [fault] })] }))
```
```typescript [Standalone] src/index.ts
import { initLogger } from 'evlog'
import { createSignals } from '@evlog/signals'
import { fault } from './signals'

initLogger({ plugins: [createSignals({ signals: [fault] })] })
```
::

The default model is `typesafe-ai/jev` through Vercel AI Gateway. Set `AI_GATEWAY_API_KEY`, or nothing on Vercel, where OIDC is picked up.

## Three kinds of answer

| You write | You get |
| --- | --- |
| A yes or no question | A boolean, with its probability |
| `choice: { ... }` | One of the options |
| `score: [...]` | A level on an ordered rubric, and its position |

## Keep what sampling would drop

Add `keep` to a signal, and an answer that matches forces the event past [sampling](/events/sampling). A checkout that answered 200 and created no order is a normal success to every rule on its fields. A signal that asks whether the customer got what they came for keeps it.

## What it costs

A decision model answers every due signal on an event in one short call. In the demo run, 15 requests came to 14 calls, 1,569 input tokens, and $0.00007. In tests, pass `evaluate` from `scriptedEvaluate()` in `@evlog/signals/testing` and no model is called.
