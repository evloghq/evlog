A CLI runs on someone else's machine, so you cannot read its logs. `@evlog/telemetry` applies the wide event to it: one command run is one event, with the command name, sanitized flags, duration and outcome, and nothing from raw `argv`.

::code-group
```bash [pnpm]
pnpm add @evlog/telemetry
```
```bash [npm]
npm install @evlog/telemetry
```
```bash [yarn]
yarn add @evlog/telemetry
```
```bash [bun]
bun add @evlog/telemetry
```
::

```typescript [scripts/migrate.ts]
import { createTelemetry, telemetry } from '@evlog/telemetry'

const t = createTelemetry({ name: 'my-migrator', version: '2.0.0' })

await t.run('migrate', async () => {
  const rows = await migrateBatch()
  telemetry.set({ rowsMigrated: rows.length, batchSize: 500 })
})
```

With events arriving, you can tell which commands people run, where runs fail and on which version, how long each command takes, and whether CI or local use dominates.

The package is standalone: about 11.5 KB gzipped, ESM only, Node 22 or later, with `citty` and `std-env` as its only dependencies and no dependency on `evlog`. The evlog CLI uses it on itself, which [`evlog telemetry`](/cli/telemetry) documents.

## From the user's machine to your backend

```text
CLI → @evlog/telemetry → outbox.ndjson → POST /ingest → validate → store
```

1. A run ends. The package checks consent, sanitizes the flags and builds one event.
2. The event is appended to `~/.config/<tool>/telemetry/outbox.ndjson`, before any network call.
3. When 15 minutes have passed since the last successful send (60 minutes in CI), or 20 events are queued, the backlog is posted to your endpoint as `{ events: [...] }`.
4. Your endpoint validates it with `parseIngestBody()`, which allowlists tools and custom keys, then stores it. [Ingest](/telemetry/ingest) builds that route.
5. A `2xx` removes the delivered events from the outbox.

The outbox is a buffer, not the destination. A short CI job or an offline machine sends its backlog on a later run. Nothing is sent until you set an endpoint. Telemetry never throws into your command, and a send is cut off after 500 ms.

## Wrap a citty CLI

Wrap the root command in `withTelemetry()`, in the file that calls `runMain()`. Every `run` handler in the tree then produces one event, with no code in the commands themselves:

```typescript [src/index.ts]
import { defineCommand, runMain } from 'citty'
import { withTelemetry, defineTelemetryCommands } from '@evlog/telemetry'
import { doctorCommand } from './commands/doctor'
import { syncCommand } from './commands/sync'

const TOOL = 'my-tool'
const VERSION = '1.0.0'

export const main = withTelemetry(
  defineCommand({
    meta: { name: 'my-tool', description: '…', version: VERSION },
    subCommands: {
      doctor: doctorCommand,
      sync: syncCommand,
      telemetry: defineTelemetryCommands({ name: TOOL }),
    },
  }),
  {
    name: TOOL,
    version: VERSION,
    endpoint: 'https://telemetry.my-tool.dev/api/telemetry/ingest',
    collect: {
      flags: { format: ['json', 'csv'] },
      fields: { framework: ['nuxt', 'next'] },
    },
  },
)

runMain(main)
```

| Invocation | `command` | `flags` |
| --- | --- | --- |
| `my-tool doctor` | `doctor` | `{}`. Nothing was passed, and a default is not a choice |
| `my-tool doctor --json` | `doctor` | `{ json: true }` |
| `my-tool sync --dry-run --output ./out` | `sync` | `{ dryRun: true, output: "<set>" }`. The path is never sent |
| `my-tool sync --format json` | `sync` | `{ format: "json" }`, because `collect.flags` allows that value |
| `my-tool telemetry status` | `telemetry status` | Nested subcommands join with a space |

The root `meta.name` is left out of `command` when the root only delegates to subcommands. Lazily imported subcommands stay lazy.

`defineTelemetryCommands()` adds `telemetry status`, `telemetry enable` and `telemetry disable` to your CLI. `status` prints the current state, the data directory and the disclosure. Pass it the same `collect` as `withTelemetry()` so the disclosure lists your allowlists.

## Wrap a script or a GitHub Action

Without citty, create the handle yourself and wrap each unit of work in `t.run()`, as in the migrator above. `await t.flush()` sends the backlog at once instead of waiting for the window.

In a GitHub Action, the runner discards the outbox when the job ends. `createGitHubActionsTelemetry()` flushes after every `run()`, and adds `ghaAction` and `ghaEvent` to `custom` from `GITHUB_ACTION` and `GITHUB_EVENT_NAME`. It reads no repository content.

```typescript [scripts/ci-report.ts]
import { createGitHubActionsTelemetry, telemetry } from '@evlog/telemetry'

const t = createGitHubActionsTelemetry({ name: 'my-action', version: '1.0.0' })

await t.run('report', async () => {
  const artifacts = await collectArtifacts()
  telemetry.set({ artifactCount: artifacts.length })
})
```

## Add your own fields

Call `telemetry.set()` in a command handler, or in any function it calls: the run is tracked with `AsyncLocalStorage`. The fields land in `custom` on the event.

```typescript [src/commands/sync.ts]
import { telemetry } from '@evlog/telemetry'

export const syncCommand = {
  meta: { name: 'sync', description: 'Pull remote state' },
  args: {
    dryRun: { type: 'boolean' },
    output: { type: 'string', description: 'Output path' },
  },
  async run() {
    const itemsSynced = await pullRemoteState()
    telemetry.set({ itemsSynced })
  },
}
```

Numbers and booleans are always accepted. A string is kept only when `collect.fields` declares that value for that key, and is dropped silently otherwise. [Reference](/telemetry/reference#what-is-collected) has the full rules.

## Record a failure

A run whose handler throws is recorded with `outcome: "error"`. If the error has a string `code`, it becomes `errorCode`:

```typescript [src/commands/doctor.ts]
throw Object.assign(new Error('Config missing'), { code: 'CONFIG_NOT_FOUND' })
```

A command that catches the error, prints it and sets an exit code returns normally, so the run would count as a success. Call `telemetry.fail()` where you handle it:

```typescript [src/commands/sync.ts]
try {
  await pullRemoteState()
} catch (error) {
  console.error(error.message)
  telemetry.fail(error.code) // outcome: "error", errorCode: error.code
  process.exitCode = 1
}
```

The code is optional. An error thrown later in the same run replaces it.

## Choose where events go

Set `endpoint` in the options when you ship the tool. Leave it out during development: events queue locally and nothing is sent.

| Variable | Effect |
| --- | --- |
| `EVLOG_TELEMETRY_ENDPOINT` | Replaces the `endpoint` option, for staging or a self-hosted backend |
| `EVLOG_TELEMETRY=0`, `DO_NOT_TRACK=1` | No recording, no send |
| `EVLOG_TELEMETRY_DEBUG=1` | Prints the run's event to stderr, sends nothing, queues nothing |
| `EVLOG_TELEMETRY_FLUSH_INTERVAL_MS` | The send window. Default `900000` (15 minutes), `3600000` in CI. `0` sends on every run |
| `EVLOG_TELEMETRY_FLUSH_THRESHOLD` | The queue size that forces a send. Default `20`, at most `50` |

The request is a `POST` with `Content-Type: application/json`, a 400 ms timeout, and no redirect following, so give it the final URL. What happens next depends on the status:

| Response | Outbox |
| --- | --- |
| `2xx` | The delivered events are removed |
| `429`, `5xx`, a redirect, a network error, a timeout | Kept, and sent again by a later run that meets the window or the threshold |
| Any other `4xx` | Dropped. The server rejected that payload, and sending it again would block every later batch |

On its first run in an interactive terminal, the tool prints a notice with the commands to check the status and to opt out. When people type something other than `name` to run it, pass that as `bin` (`bin: 'my'` for the tool `my-tool`) so the notice prints the right command.

## Check what a run sends

```bash [Terminal]
EVLOG_TELEMETRY_DEBUG=1 my-tool doctor
EVLOG_TELEMETRY=0 my-tool sync
```

A debug run prints its event to stderr, makes no request and does not queue the event, so a later run never sends it either.

[Reference](/telemetry/reference) lists every field of the event, every option, and the consent rules.
