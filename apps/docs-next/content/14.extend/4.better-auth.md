A request event that does not say who made the request sends you to a second system to find out. `evlog/better-auth` resolves the [Better Auth](https://better-auth.com/) session once per request and writes the user, the session and the lookup time onto the event. You call `log.set({ user })` nowhere.

evlog does not bundle Better Auth: `better-auth` is a dependency of your app. The integration is tested against Better Auth 1.6.9 and later.

## Identify every request

`createAuthMiddleware(auth, options)` returns an `identify(log, headers, path?)` function. Create it once at startup and call it where your framework runs code before the handler:

::framework-tabs
```typescript [Nuxt] server/middleware/auth-identify.ts
import { createAuthMiddleware } from 'evlog/better-auth'

const identify = createAuthMiddleware(auth, {
  exclude: ['/api/auth/**'],
})

export default defineEventHandler(async (event) => {
  if (!event.context.log) return
  await identify(event.context.log, event.headers, event.path)
})
```

```typescript [Next.js] app/api/checkout/route.ts
import { withEvlog, useLogger } from '@/lib/evlog'
import { createAuthMiddleware } from 'evlog/better-auth'
import { auth } from '@/lib/auth'

const identify = createAuthMiddleware(auth)

export const POST = withEvlog(async (request: Request) => {
  const log = useLogger()
  await identify(log, request.headers)
  log.set({ action: 'checkout' })
  return Response.json({ success: true })
})
```

```typescript [Hono] src/index.ts
import { createAuthMiddleware } from 'evlog/better-auth'

const identify = createAuthMiddleware(auth, {
  exclude: ['/api/auth/**'],

app.use(async (c, next) => {

  await next()

```

```typescript [Express] src/index.ts
  exclude: ['/api/auth/**'],
```


```typescript [NestJS] src/auth-identify.middleware.ts
import { createAuthMiddleware } from 'evlog/better-auth'
import { useLogger } from 'evlog/nestjs'

const identify = createAuthMiddleware(auth, {
  exclude: ['/api/auth/**'],
})

@Injectable()
export class AuthIdentifyMiddleware implements NestMiddleware {
  async use(req: Request, res: Response, next: NextFunction) {
    await identify(useLogger(), req.headers, req.path)
    next()
  }
}
```

```typescript [Standalone] scripts/sync-job.ts
import { identifyUser } from 'evlog/better-auth'
import { createLogger } from 'evlog'

const log = createLogger()
const session = await auth.api.getSession({ headers })
if (session) identifyUser(log, session)
log.emit()
```
::

`headers` is a Web `Headers` object or a Node header record. `identify` resolves to `true` when it identified a user. The route filters need the path: when you call `identify` without one, as the Next.js tab does, `include` and `exclude` are not applied.

## What lands on the event

```json [Wide Event]
{
  "level": "info",
  "method": "POST",
  "path": "/api/checkout",
  "status": 200,
  "duration": "120ms",
  "requestId": "a5669202-7765-4f59-b6f0-b9f40ce71599",
  "userId": "QBX9tPjJQExWawAbNll75",
  "user": {
    "id": "QBX9tPjJQExWawAbNll75",
    "name": "Hugo Richard",
    "email": "hugo@example.com",
    "emailVerified": true,
    "createdAt": "2024-01-15T10:00:00.000Z"
  },
  "session": {
    "id": "Xhmh6TxKJQrVKFX0Y0II",
    "expiresAt": "2024-01-22T10:00:00.000Z",
    "ipAddress": "192.168.1.42",
    "userAgent": "Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_7)",
    "createdAt": "2024-01-15T10:00:00.000Z"
  },
  "auth": {
    "resolvedIn": 12,
    "identified": true
  },
  "cart": { "items": 3, "total": 9999 }
}
```

Only the fields below are copied from the session. Passwords and tokens are never read.

| Field | Source | What it holds |
| --- | --- | --- |
| `userId` | `session.user.id` | The user ID at the top level. The [PostHog drain](/drains/posthog) reads it as `distinct_id` |
| `user.id` | `session.user.id` | The user ID. Always copied, whatever `fields` says |
| `user.name` | `session.user.name` | Display name |
| `user.email` | `session.user.email` | Email, masked with `maskEmail: true` |
| `user.image` | `session.user.image` | Avatar URL |
| `user.emailVerified` | `session.user.emailVerified` | Email verification status |
| `user.createdAt` | `session.user.createdAt` | Account creation date, as an ISO string |
| `session.id` | `session.session.id` | Session ID |
| `session.expiresAt` | `session.session.expiresAt` | Session expiry, as an ISO string |
| `session.ipAddress` | `session.session.ipAddress` | Client IP stored with the session |
| `session.userAgent` | `session.session.userAgent` | User agent stored with the session |
| `session.createdAt` | `session.session.createdAt` | Session creation date, as an ISO string |
| `auth.resolvedIn` | Measured | Milliseconds `getSession()` took |
| `auth.identified` | Computed | Whether a user was identified |
| `auth.error` | Computed | `true` when `getSession()` threw |

The three `auth` fields come from `createAuthMiddleware`. `identifyUser` on its own sets `userId`, `user` and `session` only.

## Choose the fields

`identifyUser(log, session, options)` is the function underneath. It takes a session you already resolved, sets the fields, and returns `true`, or `false` when the session has no user ID. `createAuthMiddleware` accepts the same options.

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `maskEmail` | `boolean` | `false` | Writes the email as `h***@example.com` |
| `session` | `boolean` | `true` | Includes the `session` block |
| `fields` | `string[]` | `['id', 'name', 'email', 'image', 'emailVerified', 'createdAt']` | The user fields to copy |
| `extend` | `(session) => Record<string, unknown> \| undefined` | none | Adds fields of your own, read from the session |

```typescript [services/checkout.ts]
identifyUser(log, session, {
  maskEmail: true,
  fields: ['id', 'name'],
  session: false,
})
```

`maskEmail` is also exported as a function: `maskEmail('hugo@example.com')` returns `'h***@example.com'`.

Better Auth plugins such as organizations, roles and two-factor add fields to the session. `extend` puts them on the event:

```typescript [server/middleware/auth-identify.ts]
import { createAuthMiddleware } from 'evlog/better-auth'

const identify = createAuthMiddleware(auth, {
  extend: (session) => ({
    organization: session.user.activeOrganization,
    role: session.user.role,
  }),
})
```

```json [Wide Event]
{
  "userId": "QBX9tPjJQExWawAbNll75",
  "user": { "id": "QBX9tPjJQExWawAbNll75", "name": "Hugo Richard" },
  "organization": { "id": "org_42", "name": "Acme" },
  "role": "admin"
}
```

`extend` runs on every identified request. Read what Better Auth already loaded into the session, and make no database call in it.

## Filter routes and react to the result

`createAuthMiddleware` adds four options to the ones above:

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `exclude` | `string[]` | `['/api/auth/**']` | Globs of the routes to skip |
| `include` | `string[]` | none | When set, only matching routes are resolved |
| `onIdentify` | `(log, session) => void \| Promise<void>` | none | Runs after a user is identified |
| `onAnonymous` | `(log) => void \| Promise<void>` | none | Runs when no session is found, or when the lookup fails |

Patterns use `*` for one path segment and `**` for any depth. `exclude` wins over `include`. Setting `exclude` replaces the default, so list `/api/auth/**` again:

```typescript [server/middleware/auth-identify.ts]
const identify = createAuthMiddleware(auth, {
  exclude: ['/api/auth/**', '/api/public/**', '/api/health'],
  include: ['/api/**'],
})
```

A skipped route costs no session lookup and gets no `auth` block. The hooks run on every request that passes the filter, after the fields are set, and they are awaited:

```typescript [server/middleware/auth-identify.ts]
const identify = createAuthMiddleware(auth, {
  onIdentify: (log, session) => {
    log.set({ plan: session.user.plan })
  },
  onAnonymous: (log) => {
    log.set({ anonymous: true })
  },
})
```

To keep every event of one plan past sampling, set the field in `onIdentify` and match it in the `keep` callback of your config. See [tail sampling](/events/sampling#tail-sampling).

## When the session lookup fails

`createAuthMiddleware` catches every error `getSession()` throws, so an auth backend that is down never fails the request. The event gets `auth: { resolvedIn, identified: false, error: true }`, `onAnonymous` runs, and `identify` resolves to `false`. Outside production, the error is also printed with `console.warn`. Alert on `auth.error` to watch the health of the session store.

## Watch what the lookup costs

`getSession()` is a database query on every request. `auth.resolvedIn` holds the time it took:

```json [Wide Event]
{
  "auth": { "resolvedIn": 245, "identified": true },
  "duration": "312ms"
}
```

When `auth.resolvedIn` is most of `duration`, the auth backend is the bottleneck. Three things lower it:

1. Turn on Better Auth's [cookie cache](https://www.better-auth.com/docs/guides/optimizing-for-performance#cookie-cache), so a lookup does not reach the database every time.
2. Use `exclude` for the public routes that need no user.
3. Use `include` to resolve the session on a few route patterns only.

## Standalone Nitro

`createAuthIdentifier(auth, options)` returns a Nitro `request` hook, with the same options as `createAuthMiddleware`:

```typescript [server/plugins/evlog-auth.ts]
import { createAuthIdentifier } from 'evlog/better-auth'
import { auth } from './lib/auth'

export default defineNitroPlugin((nitroApp) => {
  nitroApp.hooks.hook('request', createAuthIdentifier(auth, {
    exclude: ['/api/auth/**', '/api/public/**'],
  }))
})
```

The hook does nothing when the request has no logger yet. On Nuxt, plugin order can run it before evlog creates the logger, so use `createAuthMiddleware` in a server middleware there, as in the Nuxt tab above.

## The same user on browser logs

The middleware identifies requests on the server. For logs sent from the browser, watch the Better Auth client session and pass the user to `setIdentity`:

::framework-tabs
```typescript [Nuxt] composables/useAuthIdentity.ts
import { authClient } from '~/lib/auth-client'

export function useAuthIdentity() {
  const session = authClient.useSession()

  watch(() => session.value?.data?.user, (user) => {
    if (user) {
      setIdentity({ userId: user.id, userName: user.name })
    } else {
      clearIdentity()
    }
  }, { immediate: true })
}
```

```tsx [React] hooks/useAuthIdentity.tsx
import { useEffect } from 'react'
import { setIdentity, clearIdentity } from 'evlog/client'
import { authClient } from '@/lib/auth-client'

export function useAuthIdentity() {
  const { data } = authClient.useSession()

  useEffect(() => {
    if (data?.user) {
      setIdentity({ userId: data.user.id, userName: data.user.name })
    } else {
      clearIdentity()
    }
  }, [data?.user?.id])
}
```

```typescript [Svelte] src/lib/auth-identity.ts
import { setIdentity, clearIdentity } from 'evlog/client'
import { authClient } from '$lib/auth-client'

export function setupAuthIdentity() {
  const session = authClient.useSession()

  session.subscribe(({ data }) => {
    if (data?.user) {
      setIdentity({ userId: data.user.id, userName: data.user.name })
    } else {
      clearIdentity()
    }
  })
}
```
::

Call it once at the root of the app: `app.vue` on Nuxt, the root layout or a top-level provider in React, app start in Svelte. On Nuxt, `setIdentity` and `clearIdentity` are auto-imported. Every browser log then carries the identity:

```json [Client Log]
{
  "level": "info",
  "tag": "checkout",
  "message": "User clicked checkout",
  "userId": "QBX9tPjJQExWawAbNll75",
  "userName": "Hugo Richard"
}
```

[Browser events](/events/client) covers how those logs reach your server and your drain.

## Exports

| Export | What it does |
| --- | --- |
| `createAuthMiddleware(auth, options?)` | Returns `(log, headers, path?) => Promise<boolean>`, with route filters, timing and hooks |
| `identifyUser(log, session, options?)` | Sets the user and session fields from a resolved session. Returns `true` when identified |
| `createAuthIdentifier(auth, options?)` | Returns a Nitro `request` hook |
| `maskEmail(email)` | `hugo@example.com` becomes `h***@example.com` |

An endpoint that calls a model can carry the user and the token usage on one event: see [AI SDK](/extend/ai-sdk).
