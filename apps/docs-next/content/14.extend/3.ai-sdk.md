An AI endpoint is a black box in a request log: you see a 200 after four seconds, not the tokens it burned or the tool the model called. `evlog/ai` wraps the model and writes all of it onto the request's event.

::code-group
```typescript [Before]
export default defineEventHandler(async (event) => {
  const result = streamText({
    model: 'anthropic/claude-sonnet-4.6',
    messages,
  })
  return result.toTextStreamResponse()
})
```
```typescript [After]
import { useLogger } from 'evlog'
import { createAILogger } from 'evlog/ai'

export default defineEventHandler(async (event) => {
  const log = useLogger(event)
  const ai = createAILogger(log)

  const result = streamText({
    model: ai.wrap('anthropic/claude-sonnet-4.6'),
    messages,
  })
  return result.toTextStreamResponse()
})
```
::

```json [Wide Event]
{

  "path": "/api/chat",
  "status": 200,
  "duration": "4.5s",
  "durationMs": 4512,
  "gen_ai": {
    "calls": 1,
    "provider": { "name": "anthropic" },
    "request": { "model": "claude-sonnet-4.6" },
    "usage": {
      "input_tokens": 3312,
      "output_tokens": 814,
      "total_tokens": 4126,
      "reasoning": { "output_tokens": 225 }
    },

      "finish_reasons": ["stop"],

      "tokens_per_second": 180
```

The `ai` package is a dependency of your app. evlog supports AI SDK 6, from 6.0.168, and 7.

In evlog 3 the block is `gen_ai`, with OpenTelemetry's field names. In 2.x it was `ai`, with names such as `ai.inputTokens`: saved queries and dashboards need the new paths.

## Create the AI logger

`createAILogger(log, options?)` takes the request logger, however your framework hands it to you:

::framework-tabs
```typescript [Nuxt]
import { useLogger } from 'evlog'
import { createAILogger } from 'evlog/ai'

const log = useLogger(event)
const ai = createAILogger(log)
```

```typescript [Next.js]
import { withEvlog, useLogger } from '@/lib/evlog'
import { createAILogger } from 'evlog/ai'

export const POST = withEvlog(async () => {
  const log = useLogger()
  const ai = createAILogger(log)
  // ...
})
```

```typescript [Hono] src/index.ts
import { createAILogger } from 'evlog/ai'

app.post('/api/chat', (c) => {
  const ai = createAILogger(c.get('log'))
  // ...
})
```

```typescript [Express] src/index.ts
import { createAILogger } from 'evlog/ai'

app.post('/api/chat', (req, res) => {
  const ai = createAILogger(req.log)
  // ...
})
```

```typescript [Fastify] src/index.ts
import { createAILogger } from 'evlog/ai'

app.post('/api/chat', async (request) => {
  const ai = createAILogger(request.evlog)
  // ...
})
```

```typescript [NestJS] src/app.module.ts
import { useLogger } from 'evlog/nestjs'
import { createAILogger } from 'evlog/ai'

const log = useLogger()
const ai = createAILogger(log)
```

```typescript [Standalone]
import { createLogger } from 'evlog'
import { createAILogger } from 'evlog/ai'

const log = createLogger()
const ai = createAILogger(log)
// ...
log.emit()
```
::

It returns an `AILogger`:

| Method | What it does |
| --- | --- |
| `wrap(model)` | Wraps a language model. Takes a model string such as `'anthropic/claude-sonnet-4.6'`, resolved through the AI SDK gateway, or a `LanguageModelV3` (AI SDK 6) or `LanguageModelV4` (AI SDK 7) object. Works with `generateText`, `streamText` and `ToolLoopAgent` |
| `captureEmbed(result)` | Records the tokens, model, dimensions and count of an `embed()` or `embedMany()` call |
| `getMetadata()` | Returns a snapshot of what was recorded so far |
| `getEstimatedCost()` | Returns the estimated cost in dollars, when a `cost` map is set |
| `onUpdate(callback)` | Calls you each time the recorded data changes |

The middleware observes calls at the provider level. It does not touch your prompts, your responses or your callbacks, so an `onFinish` you pass to `streamText` runs as before.

## Streaming, agents and embeddings

A streaming handler returns before the model is done. On Nuxt, Nitro, Next.js, SvelteKit, React Router, Hono, Elysia, oRPC and Cloudflare Workers, evlog waits for a streaming body such as `text/event-stream` or an AI SDK UI stream to finish before it emits, so the late `gen_ai` fields are on the request's event. Express, Fastify and NestJS emit when Node finishes the response.

`generateText` needs nothing more than the wrapped model:

```typescript [server/api/summarize.post.ts]
const ai = createAILogger(log)

const result = await generateText({
  model: ai.wrap('anthropic/claude-sonnet-4.6'),
  prompt: 'Summarize this document',
})
```

In an agent loop the middleware runs once per step, and adds up the steps, the tool calls and the tokens:

```typescript [server/api/agent.post.ts]
import { useLogger } from 'evlog'
import { ToolLoopAgent, createAgentUIStreamResponse, stepCountIs } from 'ai'
import { createAILogger } from 'evlog/ai'

export default defineEventHandler(async (event) => {
  const log = useLogger(event)

  const { messages } = await readBody(event)
  const ai = createAILogger(log, {
    toolInputs: { maxLength: 500 },
  })

  const agent = new ToolLoopAgent({
    model: ai.wrap('anthropic/claude-sonnet-4.6'),
    tools: { searchWeb, queryDatabase },
    stopWhen: stepCountIs(5),
  })

  return createAgentUIStreamResponse({
    agent,
    uiMessages: messages,
  })
})
```

An embedding model is a different type and cannot be wrapped. Call `captureEmbed` with the result:

```typescript [server/api/rag.post.ts]
const { embedding, usage } = await embed({
  model: openai.embedding('text-embedding-3-small'),
  value: query,
})

ai.captureEmbed({
  usage,
  model: 'text-embedding-3-small',
  dimensions: 1536,
})
```

After `embedMany`, pass the batch size as `count`: `ai.captureEmbed({ usage, model: 'text-embedding-3-small', count: documents.length })`. Each capture counts as one call, and its tokens are added to `gen_ai.usage.input_tokens`.

Several models share one AI logger. Wrap each one, and the event carries the last model as `request.model` and every distinct one in `request.models`:

::code-group
```typescript [server/api/chat.post.ts]
const ai = createAILogger(log)

const fast = ai.wrap('anthropic/claude-haiku-4.5')
const smart = ai.wrap('anthropic/claude-sonnet-4.6')

const classification = await generateText({ model: fast, prompt: classifyPrompt })
const response = await generateText({ model: smart, prompt: detailedPrompt })
```
```json [Wide Event]
{
  "gen_ai": {
    "calls": 2,
    "provider": { "name": "anthropic" },
    "request": {
      "model": "claude-sonnet-4.6",

    },
    "usage": { "input_tokens": 450, "output_tokens": 300, "total_tokens": 750 }
  }
}
```

## Options

Every option is off by default. Nothing a model was sent or returned reaches your drain until you ask for it by name.

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `toolInputs` | `boolean \| ToolInputsOptions` | `false` | Records each tool call's input next to its name |
| `prompt` | `boolean \| CaptureOptions` | `false` | Records the prompt sent to the first model call as `gen_ai.input.text` |
| `output` | `boolean \| CaptureOptions` | `false` | Records the text of the last model call as `gen_ai.output.text` |
| `cost` | `Record<string, ModelCost>` | none | Prices per model, as `{ input, output }` in dollars per million tokens |

::callout{icon="i-lucide-triangle-alert" color="neutral"}
Tool inputs, prompts and outputs carry SQL, API keys and whatever your users typed, and they get large. Set `maxLength` and `transform` before you turn raw capture on in production.
::

### Tool inputs

Without `toolInputs`, `gen_ai.tool_calls` is a `string[]` of tool names. With it, the field becomes an `Array<{ name, input }>`:

```typescript
const ai = createAILogger(log, {
  toolInputs: {
    maxLength: 500,
    transform: (input, toolName) => {
      if (toolName === 'queryDB') return { sql: '***' }
      return input
    },
  },
})
```

| Sub-option | Type | What it does |
| --- | --- | --- |
| `maxLength` | `number` | Cuts a stringified input longer than this many characters, and appends `…` |
| `transform` | `(input, toolName) => unknown` | Runs before `maxLength`. Use it to redact fields or reshape the input |

`toolInputs: true` records every input as is.

### Prompt and output

`prompt` and `output` are independent: turn on one, the other, or both.

```typescript
const ai = createAILogger(log, { prompt: true, output: true })
```

- `gen_ai.input.text` is the prompt sent to the first model call, as text: one block per message, prefixed with its role. Text parts are inlined, and other parts become markers such as `[tool-call name]`, `[tool-result name]` or `[file]`.
- `gen_ai.output.text` is the text generated by the last model call, which is the final answer of a multi-step run. A streamed response is assembled from its text chunks.

Each takes the same two sub-options:

```typescript
const ai = createAILogger(log, {
  prompt: {
    maxLength: 500,
    transform: text => redact(text),
  },
})
```

| Sub-option | Type | What it does |
| --- | --- | --- |
| `maxLength` | `number` | Cuts text longer than this many characters, and appends `…` |
| `transform` | `(content) => string` | Runs before `maxLength` |

Capture needs the model call's parameters, so it works with `createAILogger` and `createAIMiddleware`. A standalone `createEvlogIntegration` only sees telemetry events and leaves both fields out.

### Cost

Pass prices per million tokens and the event carries `gen_ai.usage.estimated_cost`, in dollars:

```typescript [route:POST /api/chat]
const ai = createAILogger(log, {
  cost: {
    'claude-sonnet-4.6': { input: 3, output: 15 },
    'gpt-4o': { input: 2.5, output: 10 },
  },
})
```

Keys are model IDs as they appear in `gen_ai.request.model`. The estimate is the request's total input and output tokens at the rates of the last model used, so it is approximate when one request calls several models. A model that is not in the map gives no estimate. Keep one map next to your model selection, so renaming a model updates its price.

## When a model call fails

The middleware records the error on the event, then throws it again, so your `try/catch` and your route's error handler work as before:

```json [Wide Event]
{
  "gen_ai": {
    "calls": 1,
    "provider": { "name": "anthropic" },
    "request": { "model": "claude-sonnet-4.6" },
    "response": { "finish_reasons": ["error"] },
    "error": "API rate limit exceeded"
  }
}
```

An error that arrives inside a stream, such as a content filter, is recorded from the stream's error chunk.

## Read the data in your handler

The same data is available in your code, to store it, bill against it or show progress to the user.

`getMetadata()` returns an `AIMetadata` object with the shape of the `gen_ai` field. Call it at any point, including inside the AI SDK's `onFinish`. The snapshot is a copy: changing it changes nothing else.

```typescript [server/api/chat.post.ts]
import { useLogger } from 'evlog'
import { createAILogger } from 'evlog/ai'
import { generateText } from 'ai'

export default defineEventHandler(async (event) => {
  const log = useLogger(event)
  const ai = createAILogger(log, {
    cost: { 'claude-sonnet-4.6': { input: 3, output: 15 } },
  })

  await generateText({
    model: ai.wrap('anthropic/claude-sonnet-4.6'),
    prompt: 'Summarize this document',
  })

  const metadata = ai.getMetadata()

  await db.aiRuns.insert({
    userId: event.context.userId,
    model: metadata.request?.model,
    inputTokens: metadata.usage.input_tokens,
    outputTokens: metadata.usage.output_tokens,
    estimatedCost: metadata.usage.estimated_cost,
    finishReasons: metadata.response?.finish_reasons,
    responseId: metadata.response?.id,
  })

  return { ok: true }
})
```

`getEstimatedCost()` is `getMetadata().usage.estimated_cost`: dollars, or `undefined` without a `cost` map or when the model is not in it.

`onUpdate(callback)` calls you with a fresh snapshot once per step of an agent run, once per `captureEmbed` call, on a model error, and when `createEvlogIntegration` sees the generation end. It returns a function that unsubscribes. An error thrown by your callback is swallowed and never breaks the model call.

```typescript [server/api/agent.post.ts]
ai.onUpdate((metadata) => {
  pushToClient(event, {
    type: 'ai-progress',
    step: metadata.steps,
    tokens: metadata.usage.total_tokens,
    cost: metadata.usage.estimated_cost,
  })
})
```

`AIMetadata` and `AIMetadataListener`, the callback's type, are exported from `evlog/ai`.

## Tool timing and total duration

The middleware sees model calls, not tool executions. `createEvlogIntegration()` implements the AI SDK's telemetry interface (`TelemetryIntegration` in AI SDK 6, `Telemetry` in 7) and adds what the middleware cannot see. Pass it the AI logger and both write to the same `gen_ai` field:

```typescript [server/api/agent.post.ts]
import { useLogger } from 'evlog'
import { generateText } from 'ai'
import { createAILogger, createEvlogIntegration } from 'evlog/ai'

export default defineEventHandler(async (event) => {
  const log = useLogger(event)

  const ai = createAILogger(log)

  const result = await generateText({
    model: ai.wrap('anthropic/claude-sonnet-4.6'),
    tools: { getWeather, searchDB },
    telemetry: {
      integrations: [createEvlogIntegration(ai)],
    },
  })

  return { text: result.text }
})
```

```json [Wide Event]
{
  "gen_ai": {
    "calls": 2,
    "steps": 2,
    "provider": { "name": "anthropic" },
    "request": { "model": "claude-sonnet-4.6" },
    "usage": { "input_tokens": 3500, "output_tokens": 800, "total_tokens": 4300 },
    "response": {
      "time_to_first_chunk": 0.18,
      "duration_ms": 2100,
      "tokens_per_second": 380
    },
    "tool_calls": ["getWeather", "searchDB"],
    "tools": [
      { "name": "getWeather", "duration_ms": 150, "success": true },
      { "name": "searchDB", "duration_ms": 45, "success": true }
    ],
    "duration_ms": 2340
  }
}
```

| Field | Telemetry hook | What it holds |
| --- | --- | --- |
| `gen_ai.tools[]` | `onToolExecutionEnd` (7), `onToolCallFinish` (6) | Per tool: `name`, `duration_ms`, `success`, and `error` when it failed |
| `gen_ai.duration_ms` | `onStart` to `onEnd` (7) or `onFinish` (6) | Wall time from the start of the generation to its end |
| `gen_ai.embedding` | `onEmbedEnd` (7) | `embed()` and `embedMany()` calls, with no `captureEmbed` call |
| `gen_ai.response.finish_reasons` ending in `'abort'` | `onAbort` (7) | A streaming generation was aborted |
| `gen_ai.error` | `onAbort`, `onError` (7) | The abort reason, or an error the generation did not recover from |

When the model is already wrapped by something else and you do not want the middleware, pass the request logger: `createEvlogIntegration(log)`. It takes the same options as `createAILogger` as a second argument.

## Compose with other middleware

`ai.wrap()` accepts a model another tool already wrapped, such as supermemory or a guardrails middleware:

```typescript [server/api/chat.post.ts]
import { createAILogger } from 'evlog/ai'
import { withSupermemory } from '@supermemory/tools/ai-sdk'
import { createGateway } from 'ai'

const gateway = createGateway({ ... })
const ai = createAILogger(log)
const base = gateway('anthropic/claude-sonnet-4.6')
const model = ai.wrap(withSupermemory(base, 'your-org-id', { mode: 'full' }))
```

To choose the order yourself, `createAIMiddleware(log, options)` returns the middleware `createAILogger` uses, for `wrapLanguageModel`:

```typescript [server/api/chat.post.ts]
import { createAIMiddleware } from 'evlog/ai'
import { wrapLanguageModel } from 'ai'

const model = wrapLanguageModel({
  model: base,
  middleware: [createAIMiddleware(log, { toolInputs: true }), otherMiddleware],
})
```

It has no `captureEmbed`, since embedding models do not go through middleware.

## Fields

Every field sits under `gen_ai`. Names follow the [OpenTelemetry GenAI semantic conventions](https://github.com/open-telemetry/semantic-conventions-genai) where they define one, so a drain that flattens the event, such as [OTLP](/drains/otlp), sends the attributes OpenTelemetry backends read. Fields the conventions do not define are marked evlog. The conventions are still in Development status upstream, and evlog follows their renames in a minor release.

| Field | Source | What it holds |
| --- | --- | --- |
| `gen_ai.calls` | evlog | Number of model and embedding calls in the request |
| `gen_ai.provider.name` | OTel | Provider: `anthropic`, `openai`, `google` and so on |
| `gen_ai.request.model` | OTel | The model that served the last response |
| `gen_ai.request.models` | evlog | Every distinct model used, once there is more than one |
| `gen_ai.usage.input_tokens` | OTel | Input tokens across all calls, cached ones included |
| `gen_ai.usage.output_tokens` | OTel | Output tokens across all calls |
| `gen_ai.usage.total_tokens` | evlog | `input_tokens + output_tokens` |
| `gen_ai.usage.cache_read.input_tokens` | OTel | Tokens served from the prompt cache |
| `gen_ai.usage.cache_write.input_tokens` | OTel | Tokens written to the prompt cache |
| `gen_ai.usage.reasoning.output_tokens` | OTel | Reasoning tokens |
| `gen_ai.usage.estimated_cost` | evlog | Estimated dollars, with the `cost` option |
| `gen_ai.usage.cost` | evlog | Dollars as the runtime reports them. `evlog/ai` leaves it unset, and [`@evlog/eve`](/extend/eve) fills it |
| `gen_ai.response.finish_reasons` | OTel | One reason per call: `stop`, `length`, `tool-calls`, `error`, `abort` |
| `gen_ai.response.id` | OTel | The provider's response ID, such as Anthropic's `msg_...` |
| `gen_ai.response.time_to_first_chunk` | OTel | Seconds to the first streamed chunk. Streaming only |
| `gen_ai.response.duration_ms` | evlog | Stream duration in milliseconds. Streaming only |
| `gen_ai.response.tokens_per_second` | evlog | Output tokens per second. Streaming only |
| `gen_ai.tool_calls` | evlog | `string[]` of tool names, or `Array<{ name, input }>` with `toolInputs` |
| `gen_ai.tools` | evlog | Per tool `{ name, duration_ms, success, error? }`, with `createEvlogIntegration` |
| `gen_ai.input.text` | evlog | The prompt of the first model call, with the `prompt` option |
| `gen_ai.output.text` | evlog | The text of the last model call, with the `output` option |
| `gen_ai.steps` | evlog | Number of model calls, once there is more than one |
| `gen_ai.steps_usage` | evlog | Per step `{ model, input_tokens, output_tokens, tool_calls? }`, once there is more than one step |
| `gen_ai.error` | evlog | The error message when a model call fails |
| `gen_ai.duration_ms` | evlog | Wall time of the generation, with `createEvlogIntegration` |
| `gen_ai.embedding` | evlog | `{ model?, tokens, dimensions?, count? }` |

The cache and reasoning counts appear only when they are above zero. An agent that runs on eve gets the same block without this wrapper: see [eve](/extend/eve).
