A plugin is one object that opts into any of evlog's hooks. An enricher and a drain are each a plugin with a single hook. Write a plugin when several hooks belong together or share state. For one hook, the `enrich`, `keep` and `drain` options of your config are enough.

::lifecycle-flow
::

```typescript [plugins/tenant.ts]
import { definePlugin } from 'evlog'

export const tenantPlugin = definePlugin({
  name: 'tenant',
  onRequestStart({ logger, headers }) {
    const tenantId = headers?.['x-tenant-id']
    if (tenantId) logger.set({ tenant: { id: tenantId } })
  },
  enrich({ event }) {
    event.region = process.env.REGION
  },
})
```

Register it in the config file, and every framework that loads the file gets it:

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { tenantPlugin } from './plugins/tenant'

export default defineEvlog({
  service: 'my-app',
  plugins: [tenantPlugin],
})
```

`initLogger({ plugins })` and the `plugins` option of an integration, as in `evlog({ plugins: [tenantPlugin] })`, take the same array. An integration merges its own plugins with the logger's.

## Hooks

Every hook is optional. `name` is required.

| Hook | When it runs | Use it to |
| --- | --- | --- |
| `setup({ env })` | Once, when the logger starts with the plugin | Read `env` and set up shared state |
| `onRequestStart(ctx)` | Each request, before the handler | Copy values from the headers onto `logger` |
| `extendLogger(logger)` | Each request, on that request's logger | Add methods, such as `logger.audit.refund()` |
| `keep(ctx)` | Each request, at the tail sampling decision | Force-keep on the outcome: set `ctx.shouldKeep = true` |
| `enrich(ctx)` | Each request event, after redaction, before the console and the drain | Add derived fields |
| `drain(ctx)` | Every emitted event | Send it somewhere, alert, mirror it to a queue |
| `onRequestFinish(ctx)` | Each request, after the event is emitted and handed to the drain | Post-process the request |
| `onClientLog(ctx)` | A browser event reaches the ingest route the Nuxt module serves | Observe client traffic |

What each hook receives:

| Context | Fields |
| --- | --- |
| `setup` | `env`: `service`, `environment`, `version`, `commitHash`, `region` |
| `onRequestStart` | `logger`, `request: { method, path, requestId? }`, `headers` with sensitive ones removed |
| `onRequestFinish` | The same, plus `event` (`null` when the event was sampled out or disabled), `status`, `durationMs`, `error` |
| `keep` | `status`, `duration` in ms, `path`, `method`, `context`, `shouldKeep` |
| `enrich` | `event` (mutable), `request`, `headers`, `response: { status, headers? }` |
| `drain` | `event`, `request`, `headers` |
| `onClientLog` | `payload` as the browser sent it, `request: { method?, path? }`, `headers` |

`setup`, `enrich`, `keep` and `drain` may be async. The other hooks are synchronous.

## Several hooks, one plugin

Here one `request-metrics` plugin starts a metrics client in `setup`, tags each event in `enrich`, and reports timings in `drain`:

```typescript [plugins/request-metrics.ts]
import { definePlugin } from 'evlog/toolkit'

export const requestMetricsPlugin = definePlugin({
  name: 'request-metrics',

  setup({ env }) {
    statsd.init({ service: env.service })
  },

  enrich({ event }) {
    if (event.durationMs !== undefined) event.tier = event.durationMs > 1000 ? 'slow' : 'fast'
  },

  drain({ event }) {
    if (event.durationMs !== undefined) {
      statsd.timing('http.request', event.durationMs, { path: event.path as string })
    }
  },

  onRequestStart({ logger, request }) {
    logger.set({ trace: { startedAt: Date.now() } })
  },

  onRequestFinish({ event, durationMs }) {
    if (event && (event.level === 'error' || durationMs > 5000)) {
      // alert / forward / etc.
    }
  },
})
```

`definePlugin` is exported from both `evlog` and `evlog/toolkit`.

## One hook

`drainPlugin()` and `enricherPlugin()` wrap a single function. Each is the same as `definePlugin({ name, drain })` or `definePlugin({ name, enrich })`:

```typescript [evlog.config.ts]
import { drainPlugin, enricherPlugin } from 'evlog/toolkit'

const drainOnly = drainPlugin('axiom', createAxiomDrain())
const enricherOnly = enricherPlugin('user-agent', createUserAgentEnricher())
```

## How plugins run

- Two plugins with the same `name` are one plugin, and the last one registered wins. An integration's plugin replaces a logger plugin of the same name.
- A hook that throws is contained. The runner logs `[evlog/<name>] <hook> failed:` and moves on to the next plugin. The event still reaches the drain, without whatever the hook had not written yet.
- Plugin drains run next to the `drain` option, concurrently, and one failing does not stop the others.
- `setup` belongs to the logger. It runs for plugins in the config file or in `initLogger()`, and it is not awaited. A plugin passed only to an integration's `plugins` option gets every other hook, never `setup`.
- `enrich` runs for the event an integration emits when a request ends, and for browser events on the Nuxt ingest route. An event from `log.info({ ... })` or `createLogger().emit()` goes to `drain` without passing through `enrich`.
- `drain` runs for every event, not once per request. For per-request work, use `onRequestFinish`.
- `extendLogger` changes the logger object, not its type. Augment `RequestLogger` in a `.d.ts` so `useLogger()` shows the new methods to TypeScript. See [Typed fields](/events/typed-fields).
- `onClientLog` runs before sampling, returns nothing and cannot reject an event.

For the hooks on their own, see [Enrichers](/events/enrichers), [Sampling](/events/sampling) for `keep`, and [Custom drain](/extend/custom-drain).
