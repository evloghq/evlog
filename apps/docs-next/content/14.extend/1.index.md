Every part of evlog that runs on an event is a hook you can use yourself. The built-in enrichers, the sampling rules and the drains are plugins with one hook each, so your own code sits in the same pipeline as theirs, at the same stages.

## Connect the libraries around it

These integrations put another library's context on the event your framework already writes.

| Library | What lands on the event | Page |
| --- | --- | --- |
| AI SDK | Tokens, tool calls, streaming timings and cost per model call | [AI SDK](/extend/ai-sdk) |
| Better Auth | The signed-in user, the session and how long the lookup took | [Better Auth](/extend/better-auth) |
| eve | One event per agent turn, with its tokens, tool calls and the errors tools throw | [eve](/extend/eve) |
| Vite | The logger set up at build time, `log.debug()` stripped from production, source locations | [Vite](/extend/vite) |

## Hook into the pipeline

One concern is one option in your config. Several concerns that share state are one plugin.

| You want to | Use |
| --- | --- |
| Add a field to every event | [An enricher](/events/enrichers#your-own) |
| Decide after the request whether an event is kept | [A keep rule](/events/sampling#your-own-keep-rule) |
| Group request start and finish, enrich, keep and drain in one object | [Plugins](/extend/plugins) |
| Let a consumer subscribe to events without importing evlog | [Diagnostics channel](/extend/diagnostics-channel) |
| Mark your traffic on the receiving side with `User-Agent` and `X-Evlog-Source` | [Identity headers](/drains/http#identity-headers) |

## Build your own

| You want to | Use |
| --- | --- |
| Send events to a backend evlog has no drain for | [Custom drain](/extend/custom-drain) |
| Batch, retry and buffer that drain in production | [Pipeline](/drains/pipeline) |
| Support a framework or runtime that is not in the list | [Custom integration](/extend/custom-integration) |
| Watch events live, in-process or over SSE | [Stream](/drains/stream) |
| Read past events back from disk | [File system](/drains/fs#read-events-from-code) |

## What works where

The [stream](/drains/stream) is the one local-only piece: it lives in one Node, Bun or Deno process, so it does not work on Vercel Functions, Cloudflare Workers or AWS Lambda. Everything else on this page runs wherever evlog runs.
