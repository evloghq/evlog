title: Standalone
description: "Use evlog in scripts, workers and CLIs with initLogger() and createLogger(), and flush the drain before the process exits."

Without a framework, you start evlog once and create a logger for each unit of work: a job, a message, a script run.

```typescript [scripts/sync.ts]
import { createLogger, initLogger, toLoggerConfig } from 'evlog'
import config from '../evlog.config'

initLogger(toLoggerConfig(config))

const log = createLogger({ job: 'sync', source: 'postgres', target: 's3' })

const records = await sync()
log.set({ records: records.length })

log.emit()
```

## createLogger or createRequestLogger

| | Use it for | Fields it starts with |
| --- | --- | --- |
| `createLogger(fields)` | Jobs, queue messages, scripts | Only the ones you pass |
| `createRequestLogger({ method, path })` | Something that looks like a request, such as a webhook | `method`, `path` and a `requestId` |

Both emit when you call `log.emit()`, with the duration since they were created.

A script exits as soon as its work is done. When the drain is batched through a pipeline, `await drain.flush()` before the end, or the last batch is lost.
