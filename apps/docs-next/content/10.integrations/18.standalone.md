Without a framework, you start evlog once and create a logger for each unit of work: a job, a message, a script run.

::emits{step="run"}
```typescript [scripts/sync.ts]
import { createLogger, initLogger, toLoggerConfig } from 'evlog'
import config from '../evlog.config'

initLogger(toLoggerConfig(config))

const log = createLogger({ job: 'sync', source: 'postgres', target: 's3' })

const records = await sync()
log.set({ records: records.length })

log.emit()
```
::

Nothing frames the work for you here: there is no `evlog()` middleware, no `useLogger()` and no `log.fork()`. You pass `log` to the functions that add to the event, and you call `log.emit()`. On Cloudflare Workers, use [`evlog/workers`](/integrations/cloudflare-workers). [AWS Lambda](/integrations/aws-lambda) has its own page for the freeze after each invocation.

## createLogger or createRequestLogger

| | Use it for | Fields it starts with |
| --- | --- | --- |
| `createLogger(fields)` | Jobs, queue messages, scripts | Only the ones you pass |
| `createRequestLogger({ method, path })` | Something that looks like a request, such as a webhook | `method`, `path`, `requestId` and `operation`, each only when you pass it |

Both emit when you call `log.emit()`, with the duration since they were created.

`createRequestLogger()` takes five options, all optional:

| Option | What it does |
| --- | --- |
| `method`, `path` | The HTTP fields of the event. A `sampling.keep` rule on `path` reads them |
| `requestId` | The event's `requestId`. None is generated when you leave it out |
| `operation` | Names a task, a queue worker or a cron job on its event, the field `log.fork()` sets on a child |
| `waitUntil` | Registers the drain with a runtime that stops after the response, as in `ctx.waitUntil.bind(ctx)` |

```typescript [tasks/sync.ts]
import { createRequestLogger } from 'evlog'

const log = createRequestLogger({
  operation: 'galaxy:sync-analyses',
  requestId: crypto.randomUUID(),
})
```

Any other field goes through `log.set()`, or through `createLogger()` with the full initial context.

## What emit does

`log.emit()` builds the event, applies [sampling](/events/sampling) and [redaction](/events/redaction), prints it and hands it to the drain. It returns the event, or `null` when sampling dropped it. Three things follow:

- A logger you never emit produces no event. Emit in a `finally` block when the work can throw.
- Emitting seals the logger. A later `set()` is dropped with an `[evlog]` warning, and a second `emit()` is ignored.
- Enrichers do not run. `enrich`, `keep`, `include`, `exclude` and `routes` belong to the request integrations and do nothing here. Tail sampling still works through the `sampling.keep` rules.

[Lifecycle](/events/lifecycle#outside-a-request) compares the stages with a request's.

For a line that belongs to no unit of work, `log.info({ action: 'sync_started' })` emits an event at once, to the same drain. See [Simple logging](/events/simple-logging).

## Start the logger

A small script can keep its options inline:

```typescript [scripts/migrate-users.ts]
import { initLogger, createLogger } from 'evlog'

initLogger({
  env: { service: 'migrate' },
})

const log = createLogger({ task: 'user-migration' })

const users = await db.query('SELECT * FROM legacy_users')
log.set({ found: users.length })

let migrated = 0
for (const user of users) {
  await newDb.upsert({ id: user.id, email: user.email, plan: user.plan })
  migrated++
}

log.set({ migrated, status: 'complete' })
log.emit()
```

For anything bigger, put them in `evlog.config.ts` next to the `package.json`, the file the [CLI](/cli) reads too, and pass it with `toLoggerConfig(config)` as the first example does. It keeps every option `initLogger()` takes: the service and environment, `enabled`, `pretty`, `stringify`, `silent`, `minLevel`, `sampling`, `redact`, the drain and the plugins. [Configuration](/reference/configuration) lists them with their defaults.

| Situation | What happens |
| --- | --- |
| `initLogger()` is never called | Events are still emitted, with the service `app`, no redaction and no drain. In production evlog prints a warning once |
| `initLogger()` is called twice | The second call replaces every setting of the first, including the drain |
| `enabled: false` | `createLogger()` returns a logger whose every call does nothing |
| The script runs through Vite or `vite-node` | The [`evlog/vite` plugin](/extend/vite) starts the logger at build time, so the `initLogger()` call is only needed for a drain or plugins |

## Errors

`log.error(error)` puts the error on the event and raises its level. Throw [`createError()`](/errors) where the failure should carry a `why` and a `fix`, and read them back with `parseError()`:

```typescript [scripts/sync-job.ts]
import { createError, parseError } from 'evlog'

try {
  const result = await externalApi.sync()
  if (!result.ok) {
    throw createError({
      message: 'Sync failed',
      why: `API returned ${result.status}`,
      fix: 'Check the API status page and retry',
    })
  }
} catch (error) {
  log.error(error instanceof Error ? error : new Error(String(error)))
  log.emit()

  const { message, why, fix } = parseError(error)
  console.error(`${message}\nWhy: ${why}\nFix: ${fix}`)
  process.exitCode = 1
}
```

`process.exitCode` lets the process end on its own, after the drain has sent the event. `process.exit(1)` at that point would stop it first.

## Flush before the process exits

A script exits as soon as its work is done, and `log.emit()` does not wait for the drain. A [pipeline](/drains/pipeline) only buffers, so flush it at the end:

```typescript [scripts/sync-job.ts]
import type { DrainContext } from 'evlog'
import { initLogger, log, createLogger } from 'evlog'
import { createAxiomDrain } from 'evlog/axiom'
import { createDrainPipeline } from 'evlog/pipeline'

const pipeline = createDrainPipeline<DrainContext>({ batch: { size: 10 } })
const drain = pipeline(createAxiomDrain())

initLogger({
  env: { service: 'my-script', environment: 'production' },
  drain,
})

log.info({ action: 'sync_started' })

const syncLog = createLogger({ jobId: 'sync-001', source: 'postgres', target: 's3' })
syncLog.set({ recordsSynced: 150 })
syncLog.emit()

await drain.flush()
```

On Node and Bun, a pipeline that holds events also flushes on `beforeExit`, `SIGTERM` and `SIGINT`, so a script that simply runs to its end delivers its last batch. `process.exit()`, an uncaught exception and `SIGKILL` stop the process before any of that runs. `await drain.flush()` is the one call that works on every runtime: [Shutdown](/drains/pipeline#shutdown) has the deadlines.

## Typing

`createLogger<MyFields>()` and `createRequestLogger<MyFields>()` type the fields you set, so a wrong shape fails to compile. See [Typed fields](/events/typed-fields).
