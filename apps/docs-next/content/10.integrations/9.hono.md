Hono does not load `evlog.config.ts` on its own, so the entry file passes it in two calls: one to start the logger, one for the middleware.

```typescript [src/index.ts]
import { serve } from '@hono/node-server'
import { Hono } from 'hono'
import { initLogger, toLoggerConfig, toMiddlewareOptions } from 'evlog'
import { evlog, type EvlogVariables } from 'evlog/hono'
import config from '../evlog.config'

initLogger(toLoggerConfig(config))

const app = new Hono<EvlogVariables>()
app.use(evlog(toMiddlewareOptions(config)))

serve({ fetch: app.fetch, port: 3000 })
```

`EvlogVariables` types `c.get('log')` in every handler.

## In a handler

```typescript [src/routes/users.ts]
app.get('/users/:id', async (c) => {
  const log = c.get('log')
  const userId = c.req.param('id')

  const user = await db.findUser(userId)
  log.set({ user: { id: userId, plan: user.plan } })

  return c.json(user)
})
```

```bash [Terminal]
14:58:15 INFO [my-api] GET /users/usr_123 200 in 12ms
  ├─ user: id=usr_123 plan=pro
  └─ requestId: 4a8ff3a8-...
```

In a service the route calls, `useLogger()` from `evlog/hono` returns the same logger without passing `c` down.

A field you pass next to the config replaces that field: `evlog({ ...toMiddlewareOptions(config), exclude: ['/health'] })` uses your `exclude`, not the file's.
