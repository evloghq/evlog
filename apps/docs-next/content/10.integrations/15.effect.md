Two layers: one starts the logger, one wraps the router so each request gets its own event. The logger is an Effect service, `EvlogLogger`:

```typescript [src/index.ts]
import { createServer } from 'node:http'
import { NodeHttpServer, NodeRuntime } from '@effect/platform-node'
import { Layer } from 'effect'
import { HttpRouter } from 'effect/http'
import { toLoggerConfig, toMiddlewareOptions } from 'evlog'
import { initLoggerLayer, routerLayer } from 'evlog/effect'
import config from '../evlog.config'

const Server = HttpRouter.serve(
  Routes.pipe(Layer.provide(routerLayer(toMiddlewareOptions(config)))),
  { disableLogger: true },
).pipe(
  Layer.provide(NodeHttpServer.layer(createServer, { port: 3000 })),
  Layer.provide(initLoggerLayer(toLoggerConfig(config))),
)

NodeRuntime.runMain(Layer.launch(Server))
```

::callout{icon="i-lucide-flask-conical" color="neutral"}
`evlog/effect` is in beta, and Effect still marks `effect/http` as unstable. Its exports and the fields it writes can change in a minor release of evlog, breaking changes included. Pin your evlog version and read the changelog when you upgrade. It needs `effect` 4.
::

| Piece | What it does |
| --- | --- |
| `initLoggerLayer(config)` | Calls `initLogger()` when the layer is built, and flushes a [pipeline](/drains/pipeline) drain when its scope closes |
| `routerLayer(options)` | Installs the middleware on every route of the router and provides `EvlogLogger` to their handlers |
| `evlog(options)` | The same middleware without a router: `HttpServer.serve(app, evlog(options))` |
| `disableLogger: true` | Turns off the router's own `Sent HTTP response` line, which the event replaces |

`routerLayer` also works with `HttpRouter.toWebHandler` and with `HttpApiBuilder.layer(Api)` for an `HttpApi`. `@effect/platform-node` serves the router on Node. On Cloudflare Workers you leave it out: see [On Workers and Durable Objects](#on-workers-and-durable-objects).

## In a route

```typescript [src/routes/users.ts]
import { Effect } from 'effect'
import { HttpRouter, HttpServerResponse } from 'effect/http'
import { EvlogLogger } from 'evlog/effect'

export const UserRoute = HttpRouter.add('GET', '/users/:id', Effect.gen(function* () {
  const log = yield* EvlogLogger
  const { id } = yield* HttpRouter.params

  const user = yield* Users.find(id)
  log.set({ user: { id, plan: user.plan } })

  return HttpServerResponse.jsonUnsafe(user)
}))
```

Any effect the route runs can `yield* EvlogLogger` and add to the same event. Background work runs in a nested `withLogger` and produces its own event, where other integrations use `log.fork()`.

The request runs in an Effect span, so the event carries its `traceId` and `spanId`, and `parentSpanId` when the span has a parent.

## In the layers underneath

A function that reads `EvlogLogger` declares the requirement in its type:

```typescript [src/services/payment.ts]
import { Effect } from 'effect'
import { EvlogLogger } from 'evlog/effect'

export const chargeCard = (amount: number) => Effect.gen(function* () {
  const log = yield* EvlogLogger
  log.set({ payment: { amount } })
})
```

`chargeCard` has the type `Effect<void, never, EvlogLogger>`, so running it outside a unit of work fails to type-check. Library code that should not carry that requirement uses `set`, which merges fields into the current event and does nothing outside one:

```typescript [src/services/cache.ts]
import { Effect } from 'effect'
import { set } from 'evlog/effect'

export const recordCacheHit = Effect.gen(function* () {
  yield* set({ cache: { hit: true } })
})
```

`useLogger<T>()` is an Effect too. It returns the same logger typed with your [fields](/events/typed-fields), so a wrong shape fails to compile:

```typescript [src/routes/checkout.ts]
import { Effect } from 'effect'
import { useLogger } from 'evlog/effect'

interface CheckoutFields {
  cart: { items: number, total: number }
  user: { id: string }
}

const checkout = Effect.gen(function* () {
  const log = yield* useLogger<CheckoutFields>()
  log.set({ cart: { items: 3, total: 9999 } })
  log.set({ cart: { items: 'three' } }) // type error
})
```

The entry point imports no `AsyncLocalStorage`, so it runs on Cloudflare Workers without the `nodejs_compat` flag. For the same reason it has no zero-argument `useLogger()` and no `log.fork()`.

## When a handler fails

evlog reads the `Cause` the effect failed with:

| The cause holds | The event gets |
| --- | --- |
| A failure or a defect | `error`, from the primary one. An expected failure ranks before a defect, as in `Cause.squash` |
| More than one | The others under `error.suppressed`, as `{ name, message }` |
| Only an interruption | `status: 499`, evlog's status for a cancelled request, and no `error` |
| A failure that is not an `Error` | An error built from the string, or named after the value's `_tag`, or `UnknownError`. No other property is copied, so a failure that carries a prompt or a payload does not leak it |

The event's `status` is the one the client received. Effect's router does not read `status` off an error, so a `createError({ status: 402 })` that reaches it is answered with `500`. To answer with the error's own status, catch it in the handler, record it, and build the response with `parseError()`:

```typescript [src/routes/checkout.ts]
import { Effect } from 'effect'
import { HttpRouter, HttpServerResponse } from 'effect/http'
import { createError, parseError } from 'evlog'
import { EvlogLogger } from 'evlog/effect'

const respondWithError = (error: unknown) => Effect.gen(function* () {
  const log = yield* EvlogLogger
  log.error(error instanceof Error ? error : String(error))
  const parsed = parseError(error)
  return HttpServerResponse.jsonUnsafe(
    { message: parsed.message, why: parsed.why, fix: parsed.fix, link: parsed.link },
    { status: parsed.status },
  )
})

export const CheckoutRoute = HttpRouter.add('POST', '/checkout', Effect.gen(function* () {
  const log = yield* EvlogLogger
  log.set({ cart: { items: 3, total: 9999 } })

  return yield* Effect.fail(createError({
    message: 'Payment failed',
    status: 402,
    why: 'Card declined by issuer',
    fix: 'Try a different payment method',
    link: 'https://docs.example.com/payments/declined',
  }))
}).pipe(Effect.catch(respondWithError)))
```

Three limits:

- A route that does not exist is recorded as `404`, with the router's `HttpServerError` as the error.
- `HttpApi` encodes an endpoint's declared errors into responses before the middleware sees them. The event gets that response's status and no `error` field. Call `log.error()` in the handler when a declared error should carry its details. Defects and undeclared failures are recorded as `error`.
- A streamed response emits its event when the handler returns the `HttpServerResponse`, not when the body finishes. The stream's duration and an error while streaming are not on the event.

## Jobs, queues and alarms

Work that is not an HTTP request gets its own event with `withLogger`. It provides `EvlogLogger`, runs the effect in a span named after the action, and emits when the effect succeeds, fails or is interrupted:

```typescript [src/jobs/digest.ts]
import { Effect } from 'effect'
import { EvlogLogger, withLogger } from 'evlog/effect'

export const sendDigest = Effect.gen(function* () {
  const log = yield* EvlogLogger
  const users = yield* Users.subscribed()
  log.set({ digest: { recipients: users.length } })
  yield* Mailer.sendDigest(users)
}).pipe(withLogger('send-digest', { fields: { job: { queue: 'mail' } } }))
```

The event carries `action` in place of `method` and `path`. Run inside a request, it shares the request's `traceId` and records the request span as its `parentSpanId`, which is how background work stays tied to the request that started it.

`withLogger(action, options)` takes `drain`, `enrich`, `keep`, `redact`, `plugins` and `waitUntil` as `routerLayer` does, plus:

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `fields` | `Record<string, unknown>` | None | Fields the event starts with |
| `emit` | `'always' \| 'onError'` | `'always'` | `'onError'` emits when the effect fails or dies, and keeps that event even when sampling would drop it. A run that succeeds or is interrupted is discarded like `log.discard()` |
| `traceparent` | `string` | The current span | Continues this W3C trace, such as the one a queue message carries. A malformed value starts a new trace |
| `tracestate` | `string` | None | Forwarded on outgoing requests next to `traceparent` |

A job that found nothing to report can drop its own event with [`log.discard()`](/events#discard-an-event). A discarded run still emits when it recorded an `error()`, a `fatal()` or an `audit()`, with `emit: 'onError'` too.

## On Workers and Durable Objects

`HttpRouter.toWebHandler` turns the routes into a Fetch handler. Drains need the request's `waitUntil` to outlive the response, so provide it per request through the handler's context argument:

```typescript [src/worker.ts]
import { Context, Layer } from 'effect'
import { HttpRouter } from 'effect/http'
import { WaitUntil, routerLayer } from 'evlog/effect'
import { createAxiomDrain } from 'evlog/axiom'
import { initWorkersLogger } from 'evlog/workers'

initWorkersLogger({ env: { service: 'my-worker' } })

const { handler } = HttpRouter.toWebHandler(
  Routes.pipe(Layer.provide(routerLayer({ drain: createAxiomDrain() }))),
  { disableLogger: true },
)

export default {
  fetch(request: Request, _env: Env, ctx: ExecutionContext) {
    return handler(request, Context.make(WaitUntil, ctx.waitUntil.bind(ctx)))
  },
}
```

Outside a router, `Effect.provideService(WaitUntil, fn)` sets it for any effect, and the `waitUntil` option does the same for one unit. Without either, the unit awaits its drains before it settles.

A Durable Object `fetch` receives a raw `Request`. `withRequestLogger(request, options)` wraps an effect that produces the `Response` and records it like a router request, with the same options as `routerLayer`. A failure's status is the one the error carries (`status` or `statusCode`), or `500`. An alarm has no request, so it uses `withLogger`:

```typescript [src/room.ts]
import { DurableObject } from 'cloudflare:workers'
import { Effect } from 'effect'
import { withRequestLogger, withLogger } from 'evlog/effect'

export class Room extends DurableObject {
  fetch(request: Request) {
    return Effect.runPromise(join(request).pipe(withRequestLogger(request)))
  }

  alarm() {
    return Effect.runPromise(sweepIdleMembers.pipe(withLogger('room-alarm')))
  }
}
```

## Follow one action across services

Each unit continues an incoming W3C `traceparent` and keeps its `tracestate`. A request that crosses a gateway, a Durable Object and two services produces one event per hop with the same `traceId`, and each event's `parentSpanId` points at the span that made the call.

Effect's `HttpClient` already sends `traceparent` for the current span. `withTracePropagation` adds the received `tracestate` to every request of a client:

```typescript [src/services/search.ts]
import { Effect } from 'effect'
import { HttpClient } from 'effect/http'
import { withTracePropagation } from 'evlog/effect'

export const search = (query: string) => Effect.gen(function* () {
  const client = withTracePropagation(yield* HttpClient.HttpClient)
  return yield* client.get(`https://search.internal/q?${new URLSearchParams({ query })}`)
})
```

Calls that do not go through `HttpClient`, such as a Durable Object stub `fetch` or a queue message, take the headers from `traceHeaders`. It is empty outside a span:

```typescript [src/routes/messages.ts]
import { Effect } from 'effect'
import { traceHeaders } from 'evlog/effect'

export const postMessage = (stub: DurableObjectStub, body: string) => Effect.gen(function* () {
  const headers = yield* traceHeaders
  return yield* Effect.promise(() => stub.fetch('https://room/messages', { method: 'POST', headers, body }))
})
```

## Fold Effect.log into the event

`Effect.logInfo` and the other `Effect.log*` calls print one line each by default. `loggerLayer()` sends them to the current event:

```typescript [src/index.ts]
import { loggerLayer } from 'evlog/effect'

const Server = HttpRouter.serve(App, { disableLogger: true }).pipe(
  Layer.provide(NodeHttpServer.layer(createServer, { port: 3000 })),
  Layer.provide(loggerLayer()),
)
```

- Each call goes through the evlog method of the same severity (`fatal`, `error`, `warn`, `info`, `debug`, `trace`), so `Effect.logError` raises the event's level.
- An Error or Fatal entry logged with a `Cause` records the cause's error.
- Messages use evlog's printf-style formatting (`%s`, `%d`, `%j`), and `Effect.annotateLogs` annotations merge into the event as fields.
- Outside a unit, a call goes to the loggers that were installed before `loggerLayer()`, so your existing logger keeps working.

## Options

`routerLayer()`, `evlog()` and `withRequestLogger()` take the request options of `evlog.config.ts`, which `toMiddlewareOptions(config)` passes. [Configuration](/reference/configuration) lists the logger options that go to `initLoggerLayer()`.

| Option | Default | What it does |
| --- | --- | --- |
| `include` | Every route | Globs of the routes to log. `*` stops at a `/`, `**` crosses it |
| `exclude` | None | Globs of the routes to skip. Wins over `include` |
| `routes` | None | A `service` name per route glob. The first glob that matches wins, so list the specific ones first |
| `drain` | The drain given to `initLoggerLayer()` | Receives every emitted event. See [Drains](/drains) |
| `enrich` | None | Adds fields after redaction, before the console output and the drain. See [Enrichers](/events/enrichers) |
| `keep` | None | Tail sampling: set `ctx.shouldKeep = true` to keep an event the rates would drop. See [Sampling](/events/sampling) |
| `redact` | The `initLoggerLayer()` setting | Redacts the event when the logger config did not: `true` for the built-in patterns, or a config. See [Redaction](/events/redaction) |
| `plugins` | None | Merged with the plugins given to `initLoggerLayer()`. A plugin here replaces a global one of the same `name` |
| `waitUntil` | The `WaitUntil` service, then the Vercel Functions runtime | Registers the drain with the runtime instead of awaiting it |

```typescript [src/index.ts]
routerLayer({
  include: ['/api/**'],
  exclude: ['/_internal/**', '/health'],
  routes: {
    '/api/auth/**': { service: 'auth-service' },
    '/api/payment/**': { service: 'payment-service' },
  },
  keep: (ctx) => {
    if (ctx.duration && ctx.duration > 2000) ctx.shouldKeep = true
  },
})
```

A field you pass replaces the one from the file. An excluded route still runs: its handlers get an `EvlogLogger` that accepts every call, and nothing is emitted. The event's `requestId` is the `x-request-id` header when the caller sends one, and a random UUID otherwise.

## Flush on shutdown

A pipeline drain buffers events, so it has to be flushed before the process exits. Give it to `initLoggerLayer`: the layer flushes it when its scope closes, which `NodeRuntime.runMain` does on shutdown. `routerLayer` and `withLogger` fall back to that drain when they have none of their own:

```typescript [src/index.ts]
import type { DrainContext } from 'evlog'
import { createAxiomDrain } from 'evlog/axiom'
import { initLoggerLayer } from 'evlog/effect'
import { createDrainPipeline } from 'evlog/pipeline'

const pipeline = createDrainPipeline<DrainContext>({
  batch: { size: 50, intervalMs: 5000 },
  retry: { maxAttempts: 3 },
})

const EvlogLive = initLoggerLayer({
  env: { service: 'my-api' },
  drain: pipeline(createAxiomDrain()),
})
```
