The module reads `evlog.config.ts`, creates a logger for each server request, and emits it when the response ends.

```typescript [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['evlog/nuxt'],
})
```

`useLogger` and `parseError` are auto-imported. Import `createError` from `evlog`: the auto-imported one is Nuxt's, and it drops `why`, `fix` and `link`.

## In a route

```typescript [server/api/checkout.post.ts]
import { createError } from 'evlog'

export default defineEventHandler(async (event) => {
  const log = useLogger(event)
  const body = await readBody(event)

  const cart = await db.findCart(body.cartId)
  log.set({ cart: { items: cart.items.length, total: cart.total } })

  if (body.amount <= 0) {
    throw createError({
      status: 400,
      message: 'Invalid payment amount',
      why: 'The amount must be a positive number',
      fix: 'Pass a positive integer in cents, such as 4999 for $49.99',
    })
  }

  return { ok: true }
})
```

The module's error handler returns an `EvlogError` as JSON with `why`, `fix` and `link` under `data`. Errors thrown with h3's `createError` keep their own `data`.

## Configuration

Options go in `evlog.config.ts`. The `evlog` key in `nuxt.config.ts` takes the same options and overrides the file key by key, with one exception: the file's `drain`, `enrich` and `keep` always run, alongside any `evlog:*` hook.

Two options exist only in `nuxt.config.ts`:

| Option | Default | What it does |
| --- | --- | --- |
| `console` | `true` | Browser console output |
| `transport.enabled` | `false` | Sends browser logs to `/api/_evlog/ingest`, then through your drain. See [HTTP](/drains/http) |

## Hooks

Nitro hooks run next to the config file, for what needs the Nitro app:

| Hook | Runs |
| --- | --- |
| `evlog:enrich` | Before the event is printed and drained |
| `evlog:drain` | After the event is emitted |
| `evlog:emit:keep` | Before sampling, to force-keep an event |
