Next.js has no request middleware evlog can hook into for every route, so you create one instance and wrap the handlers you want logged.

```typescript [lib/evlog.ts]
import { createEvlog } from 'evlog/next'
import config from '../evlog.config'

export const { withEvlog, useLogger, log, createError } = createEvlog(config)
```

`createEvlog(config)` starts the logger the first time `lib/evlog.ts` is imported. Routes wrapped with `withEvlog` use the file's route filters, drain, `enrich` and `keep`.

## In a route

```typescript [app/api/checkout/route.ts]
import { withEvlog, useLogger, createError } from '@/lib/evlog'

export const POST = withEvlog(async (req) => {
  const log = useLogger()
  const { cartId } = await req.json()

  const cart = await db.findCart(cartId)
  log.set({ cart: { items: cart.items.length, total: cart.total } })

  if (!cart.items.length) {
    throw createError({ status: 400, message: 'Empty cart', fix: 'Add an item before checking out' })
  }

  return Response.json({ ok: true })
})
```

`useLogger()` takes no argument: inside `withEvlog`, it reads the request from `AsyncLocalStorage`, so a service called from the route reaches the same logger.

## Errors outside a wrapped route

`instrumentation.ts` reports what `withEvlog` never sees, such as a render error in a server component. `defineNodeInstrumentation` loads evlog in the Node.js runtime only:

```typescript [instrumentation.ts]
import { defineNodeInstrumentation } from 'evlog/next/instrumentation'

export const { register, onRequestError } = defineNodeInstrumentation({
  service: 'my-app',
  captureOutput: true,
})
```

To run your own startup code next to evlog, pass a loader function instead of the options, and call `createInstrumentation()` from `evlog/next/instrumentation/create` inside it.
