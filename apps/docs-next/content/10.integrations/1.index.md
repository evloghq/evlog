Every framework integration does the same three things: it creates a logger when the request starts, gives your handler a way to reach it, and emits the event when the response ends, with the status, the duration and any error.

Two things differ from one framework to the next: how you start evlog, and how a handler reaches the logger.

| Framework | Import | Start | In a handler |
| --- | --- | --- | --- |
| [Nuxt](/integrations/nuxt) | `evlog/nuxt` | Module | `useLogger(event)` |
| [Next.js](/integrations/next) | `evlog/next` | `createEvlog()` | `useLogger()` |
| [Hono](/integrations/hono) | `evlog/hono` | Middleware | `c.get('log')` |
| [Nitro](/integrations/nitro) | `evlog/nitro` | Module | `useLogger(event)` |
| [SvelteKit](/integrations/sveltekit) | `evlog/sveltekit` | Hooks | `event.locals.log` |
| [TanStack Start](/integrations/tanstack-start) | `evlog/nitro` | Module | `useRequest().context.log` |
| [React Router](/integrations/react-router) | `evlog/react-router` | Middleware | `context.get(loggerContext)` |
| [NestJS](/integrations/nestjs) | `evlog/nestjs` | `EvlogModule.forRoot()` | `useLogger()` |
| [Express](/integrations/express) | `evlog/express` | Middleware | `req.log` |
| [Fastify](/integrations/fastify) | `evlog/fastify` | Plugin | `request.log` |
| [Elysia](/integrations/elysia) | `evlog/elysia` | Plugin | `log` in the context |
| [oRPC](/integrations/orpc) | `evlog/orpc` | Handler wrapper | `context.log` |
| [Effect](/integrations/effect) | `evlog/effect` | Layer | `yield* EvlogLogger` |
| [Cloudflare Workers](/integrations/cloudflare-workers) | `evlog/workers` | `withEvlog()` | The handler's fourth argument |
| [Standalone](/integrations/standalone), [AWS Lambda](/integrations/aws-lambda), [Astro](/integrations/astro) | `evlog` | `initLogger()` | `createLogger()`, `createRequestLogger()` |

The framework accessor (`c.get('log')`, `req.log`) is the idiomatic path inside a handler. `useLogger()` reaches the same logger from the layers underneath, a service or a repository, through `AsyncLocalStorage`. Workers and Effect have no `useLogger()`: Workers avoids `node:async_hooks`, and Effect carries the logger in its context.

## Beyond frameworks

| Integration | What it adds | |
| --- | --- | --- |
| AI SDK | Tokens, tool calls, streaming timings and cost on the event | [AI SDK](/integrations/ai-sdk) |
| Better Auth | The signed-in user on every event, and as the audit actor | [v2 page](/v2/use-cases/better-auth/overview) |
| Vite | Strips `log.debug()` from production builds, injects source locations, and reads `service`, `sampling` and the other serializable settings from `evlog.config.ts` | [v2 page](/v2/reference/vite-plugin) |

A framework that is not listed can still use the [toolkit](/v2/extend/custom-framework) to build the same contract.
