Each setup below is the audit drain only: `auditOnly`, an optional `signed`, and `await: true`, around a different store. Register it next to your main drain, as [Integrity](/audit/integrity) shows for a config file. The snippets use the Nuxt and Nitro `evlog:drain` hook.

## A signed journal on disk

```typescript [server/plugins/evlog.ts]
import { auditOnly, signed } from 'evlog'
import { createFsDrain } from 'evlog/fs'

nitro.hooks.hook('evlog:drain', auditOnly(
  signed(createFsDrain({ dir: '.audit', maxFiles: 30 }), { strategy: 'hash-chain' }),
  { await: true },
))
```

The [file system drain](/drains/fs) writes one JSON line per event to a file per day, such as `.audit/2026-04-24.jsonl`. Each line's `audit.prevHash` equals the `audit.hash` of the line before it, and the first line of a chain has no `prevHash`. Pass a [`state` store](/audit/integrity#sign-the-events) so the chain continues across restarts.

`maxFiles: 30` deletes the oldest file once there are more than 30. Leave it out if the journal is your only copy.

## A dedicated Axiom dataset

```typescript [server/plugins/evlog.ts]
import { auditOnly } from 'evlog'
import { createAxiomDrain } from 'evlog/axiom'

nitro.hooks.hook('evlog:drain', createAxiomDrain({ dataset: 'logs' }))
nitro.hooks.hook('evlog:drain', auditOnly(
  createAxiomDrain({ dataset: 'audit', apiKey: process.env.AXIOM_AUDIT_API_KEY }),
))
```

The audit dataset gets its own retention, its own access rules and its own billing line, and the rest of your pipeline does not change. Two queries to start from, the outcomes of one action per hour and the denials per actor:

::code-group
```kusto [Outcomes per hour]
['audit']
| where audit.action == "invoice.refund"
| summarize count() by audit.outcome, bin(_time, 1h)
```
```kusto [Denials by actor]
['audit']
| where audit.outcome == "denied"
| summarize count() by audit.actor.id, audit.action
| order by count_ desc
```
::

## A Postgres table

A drain is a function, so the audit drain can be an insert:

```typescript [server/plugins/evlog.ts]
import { auditOnly } from 'evlog'
import type { DrainContext } from 'evlog'

const postgresAudit = async (ctx: DrainContext) => {
  await db.insert(auditEvents).values({
    id: ctx.event.audit!.idempotencyKey,
    timestamp: new Date(ctx.event.timestamp),
    payload: ctx.event,
  }).onConflictDoNothing()
}

nitro.hooks.hook('evlog:drain', auditOnly(postgresAudit, { await: true }))
```

`idempotencyKey` as the primary key is what makes a retry safe: the second insert of the same event hits `ON CONFLICT DO NOTHING` and no duplicate row appears. The audit fields stay queryable inside the payload:

```sql [Query]
SELECT id, timestamp, payload->'audit'->>'action' AS action,
       payload->'audit'->>'outcome' AS outcome
FROM audit_events
WHERE payload->'audit'->>'action' = 'invoice.refund';
```

## Test what you recorded

`mockAudit()` captures every audit event as it is emitted, whether it came from `log.audit()`, `audit()` or `log.set({ audit })`:

```typescript [test/refund.test.ts]
import { mockAudit } from 'evlog'

it('refunds the invoice and records an audit', async () => {
  const captured = mockAudit()

  await refundInvoice({ id: 'inv_889' }, { actor: { type: 'user', id: 'u1' } })

  captured.assertAudit({
    action: 'invoice.refund',
    target: { type: 'invoice', id: 'inv_889' },
    outcome: 'success',
  })

  captured.restore()
})
```

| Member | What it does |
| --- | --- |
| `events` | The captured `audit` fields, in order, each with its `idempotencyKey` |
| `assertAudit(matcher)` | Returns the first match, or throws an error that lists the captured actions and outcomes |
| `toIncludeAuditOf(matcher)` | Returns `true` when an event matches, for use inside `expect()` |
| `restore()` | Removes the collector |

A matcher takes `action` as a string or a `RegExp`, `outcome`, and partial `actor` and `target` objects. Call `restore()` in an `afterEach`, so a failed assertion does not leak the collector into the next test.

## Every audit export

Everything is exported from `evlog`.

| Symbol | Kind | What it is |
| --- | --- | --- |
| `log.audit(fields)` | method | Sets `audit` on the request's event, kept past sampling |
| `log.audit.deny(reason, fields)` | method | The same, with `outcome: 'denied'` |
| `audit(fields)` | function | Emits a one-shot audit event, for scripts and jobs |
| `withAudit(options, fn)` | wrapper | Emits `success`, `failure` or `denied` from the result of `fn` |
| `AuditDeniedError` | class | Thrown inside `withAudit()` to record a denial |
| `defineAuditAction(name, options?)` | factory | One typed action, with a fixed target type |
| `defineAuditCatalog(prefix, map)` | factory | Typed actions under one prefix |
| `auditDiff(before, after, options?)` | helper | A redacted JSON Patch for `changes` |
| `auditEnricher(options?)` | enricher | Fills `audit.context` from the request |
| `auditOnly(drain, { await? })` | drain wrapper | Forwards only events with an `audit` field |
| `signed(drain, options)` | drain wrapper | Adds an HMAC signature or a hash chain |
| `auditRedactPreset` | config | Redaction paths for credentials and session headers |
| `mockAudit()` | test helper | Captures audit events on emit |
| `withAuditMethods(logger)` | function | Adds `audit()` and `audit.deny()` to a logger that lacks them |
| `buildAuditFields(input)` | function | Turns the input of `log.audit()` into `AuditFields`, with the defaults |
| `AUDIT_SCHEMA_VERSION` | constant | `1`, the default of `audit.version` |

The types are exported too: `AuditFields`, `AuditActor`, `AuditTarget`, `AuditChanges`, `AuditPatchOp`, `AuditInput`, `AuditSeverity`, `AuditActionDefinition`, `AuditAction`, `RegisteredAuditCatalogs`, `AuditableLogger`, `AuditMethod`, `AuditMatcher`, `MockAudit`, `AuditDiffOptions`, `AuditEnricherOptions`, `AuditOnlyOptions`, `SignedOptions`, `SignedChainState`, `WithAuditOptions`, `WithAuditContext`, `DefinedAuditAction`, `AuditCatalog`, `AuditCatalogEntry` and `AuditCatalogMap`.

[Recording](/audit/recording) covers the first eight in detail, and [Integrity](/audit/integrity) the enricher, the two drain wrappers and the redaction preset.
