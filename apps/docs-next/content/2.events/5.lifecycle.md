An event that never reached your drain was stopped at one stage, and a field that reached it unmasked was added after another. This page gives the order, so you know which option to change.

::lifecycle-flow
::

## The stages of a request

With a [framework integration](/integrations), every request goes through these stages. A stage that drops the event ends the list: nothing is printed, enriched or drained after it.

| # | Stage | What evlog does | Option |
| --- | --- | --- | --- |
| 1 | Route filter | Checks the path against the route globs. A route that does not match gets no event | `include`, `exclude` |
| 2 | Create | Creates the request logger with `method`, `path` and `requestId`, and starts the timer | |
| 3 | Accumulate | Merges each `log.set()` into the context | |
| 4 | Request end | Records the status, the duration and the error if one was thrown | |
| 5 | Discard and floor | Drops the event if you called `log.discard()`, or if its level is below the floor | `sampling.minLevel` |
| 6 | Tail sampling | Asks your `keep` callback, then the `keep` rules, whether the event must be kept | `keep`, `sampling.keep` |
| 7 | Head sampling | Draws against the rate of the event's level, unless stage 6 kept it | `sampling.rates` |
| 8 | Build | Adds `timestamp`, `level`, `service`, `environment`, `duration` and `durationMs`, plus `version`, `commitHash` and `region` when evlog detects them, then seals the logger | |
| 9 | Redact | Masks the event | `redact` |
| 10 | Enrich | Runs your enrichers on the masked event | `enrich` |
| 11 | Console | Prints the event, as a tree in development and as JSON in production | `pretty`, `silent` |
| 12 | Drain | Hands the event to your drain | `drain` |

The console line waits for the enrichers, so your terminal shows the same event your drain receives.

## Route filter

Every route is logged by default. `include` limits logging to the globs you list, and `exclude` wins over `include`:

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'

export default defineEvlog({
  service: 'my-app',
  include: ['/api/**'],
})
```

On Nuxt, Nitro, Hono, Fastify, React Router, SvelteKit, Elysia and oRPC, the logger your route code reads (`useLogger(event)`, `c.get('log')`, `request.evlog`, `context.get(loggerContext)`, `event.locals.log`, `log`, `context.log`) is still there on an excluded route. It accepts every call and emits nothing.

## Create and accumulate

The request logger starts with three fields:

| Field | Source |
| --- | --- |
| `method` | HTTP method |
| `path` | Request path |
| `requestId` | The `x-request-id` header when the request has one, then `cf-ray` on Cloudflare Workers, otherwise a generated UUID |

`useLogger(event)` and the framework accessors return that logger. They never create one.

Each `log.set()` deep-merges into what is already there, so you call it as often as you learn something:

```typescript [server/api/checkout.post.ts]
import { useLogger } from 'evlog'

const log = useLogger(event)

const user = await getUser(event)
log.set({ user: { id: user.id, plan: user.plan } })

const cart = await getCart(user.id)
log.set({ cart: { items: cart.items.length, total: cart.total } })
```

Only plain objects merge. A class instance or a `Date` is a value: the next `set()` on that key replaces it, and evlog never writes into the object you passed. Two arrays on the same key are concatenated.

## Request end and level

When the response is sent or the handler throws, evlog records the status and the duration, and picks the level:

| Level | When |
| --- | --- |
| `fatal` | The handler called `log.fatal()` |
| `error` | An error was thrown, or the handler called `log.error()` |
| `warn` | The handler called `log.warn()` |
| `info` | Everything else, including a `500` returned without throwing |

`log.setLevel()` wins over all four.

## Sampling

Stages 5 to 7 decide whether the event exists at all. They run before the event is built, so a dropped event costs no redaction, no enrichment and no drain call. [Sampling](/events/sampling) covers the options. The order matters in three cases:

- The `sampling.minLevel` floor runs before `keep`, so a `keep` rule cannot bring back an event below the floor.
- A `keep` callback or rule that matches skips head sampling entirely. The callback is called on every logged request, before the floor is checked, but its answer only counts at stage 6.
- `fatal` events and [audit](/audit) events are kept whatever the rates say. `error` events are kept unless you set `sampling.rates.error` yourself.

## Seal

Stage 8 seals the logger, also when sampling dropped the event. A later `set()`, `error()`, `info()` or `warn()` on it changes nothing and prints an `[evlog]` warning that names the dropped keys. Background work that outlives the request gets its own event with [`log.fork()`](/events#after-the-event-is-emitted).

## Redact, enrich, print, drain

[Redaction](/events/redaction) runs once, on the built event, before anything can read it. [Enrichers](/events/enrichers) run next, which means a field an enricher adds is not masked: an enricher that reads a header or a session masks what it writes.

Each stage has a config option, and a hook on Nuxt and Nitro that runs alongside it:

| Order | Option | Hook | Runs |
| --- | --- | --- | --- |
| 1 | `keep` | `evlog:emit:keep` | After the request ends, before sampling |
| 2 | `enrich` | `evlog:enrich` | After redaction, before the console output and the drain |
| 3 | `drain` | `evlog:drain` | After enrichment |

The [drain](/drains) never fails the request: evlog catches what it throws and prints `[evlog] drain failed`. On a runtime with `waitUntil` (Cloudflare Workers, Vercel), the drain is registered with it and finishes after the response. Without `waitUntil`, evlog awaits the drain, so a serverless function that freezes after the response does not lose the event.

## When the handler throws

A thrown error takes the same stages. Only the start differs:

| | Success | Error |
| --- | --- | --- |
| Level | `info`, or what the handler set | `error` |
| Status | From the response | From the error's `status` or `statusCode`, and `500` when neither is set |
| `error` field | None | `name`, `message`, `stack`, and the `why` and `fix` of a [structured error](/errors) |

The integration emits once. On Nuxt and Nitro the error hook emits the event and marks the request, so the response hook does not emit a second one.

## Outside a request

`log.info()` and `createLogger()` take a shorter path. Neither has a route, and neither runs enrichers: the `enrich` option and the `evlog:enrich` hook belong to the integrations.

| Stage | `log.info()` | `createLogger()`, `createRequestLogger()` | Framework integration |
| --- | --- | --- | --- |
| Create | Each call | When you call it | Request start |
| Accumulate | No | `log.set()` | `log.set()` |
| Emit | Immediately | When you call `log.emit()` | Response end |
| Level filter | `minLevel` | `sampling.minLevel` | `sampling.minLevel` |
| Sampling | Head only | Head, and the `sampling.keep` rules | Head, the `sampling.keep` rules and the `keep` callback |
| Redact | Yes | Yes | Yes |
| Enrich | No | No | Yes |
| Console | Yes | Yes | Yes, after enrichers |
| Drain | The `initLogger()` drain | The `initLogger()` drain | The integration's drain, or the `initLogger()` drain |

A `sampling.keep` rule reads `status` and `path` from the fields you set on a standalone logger, and the duration since `createLogger()`.

A tagged call such as `log.info('auth', 'User logged in')` only prints while `pretty` is on, which is the default in development. With `pretty` off it becomes an event with `tag` and `message` and takes the full path. The object form, `log.info({ action: 'deploy' })`, always does. See [Simple logging](/events/simple-logging).

A standalone logger configures all of it in `initLogger()`:

```typescript [scripts/migrate.ts]
import { initLogger, createLogger } from 'evlog'
import { createAxiomDrain } from 'evlog/axiom'

initLogger({
  env: { service: 'worker' },
  drain: createAxiomDrain(),
  sampling: { rates: { info: 10 } },
})

const log = createLogger({ task: 'migrate' })
log.set({ records: 500, status: 'complete' })
log.emit()
```
