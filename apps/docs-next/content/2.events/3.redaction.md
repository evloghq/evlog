A wide event collects a lot of context, which makes it easy to log a field you should not. Redaction scrubs the event before it is printed and before any drain receives it.

It is on by default when `NODE_ENV` is `production` and off in development, where you want the full values to debug. You have nothing to configure to get it.

::redaction-stream
::

## What is masked

Built-in patterns mask partially, so a redacted value still helps you debug:

| Pattern | Input | Output |
| --- | --- | --- |
| `creditCard` | `4111111111111111` | `****1111` |
| `email` | `alice@example.com` | `a***@***.com` |
| `ipv4` | `192.168.1.100` | `***.***.***.100` |
| `phone` | `+33 6 12 34 56 78` | `+33 ****5678` |
| `jwt` | `eyJhbGciOiJIUzI1NiIs...` | `eyJ***.***` |
| `bearer` | `Bearer sk_live_abc123...` | `Bearer ***` |
| `apiKeys` | `ghp_` followed by 36 characters | `ghp_***` |
| `privateKey` | `-----BEGIN RSA PRIVATE KEY-----` block | `-----BEGIN RSA PRIVATE KEY-----***` |
| `urlPassword` | `postgres://user:hunter2@db` | `postgres://user:***@db` |
| `iban` | `FR76 3000 6000 0112 ...189` | `FR76****189` |

`apiKeys` finds a provider credential by its fixed prefix, anywhere in a string: GitHub (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`), npm (`npm_`), AWS access key IDs (`AKIA`, `ASIA`), Anthropic (`sk-ant-`), OpenAI (`sk-proj-`), Stripe (`sk_live_`, `rk_live_`) and Slack (`xoxb-`, `xoxp-`, `xapp-`). A value shorter than its format, such as `ghp_abc`, is left as it is. `privateKey` keeps only the header of a PEM block, and `urlPassword` keeps the scheme, user and host of a URL.

A password has no recognizable shape, so the `secrets` built-in reads the key instead: any key ending in `password`, `passwd`, `secret`, `token`, `apiKey`, `privateKey`, `credentials`, `authorization`, `dsn` or `connectionString`, at any depth, is replaced in full with `[REDACTED]`. The snake case forms (`api_key`, `private_key`, `connection_string`) match too. `totalTokens`, `tokenType` and `cacheKey` are left alone. Booleans and `null` stay readable (`hasPassword: true`), and any other value is replaced, so a fetch option such as `credentials: 'include'` is masked too.

## Narrow it or extend it

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'

export default defineEvlog({
  service: 'my-app',
  redact: {
    paths: ['password', '*_token', 'headers.x-forwarded-for'],
    builtins: ['email', 'creditCard'],
    patterns: [/sk_live_\w+/g],
  },
})
```

| Option | What it does |
| --- | --- |
| `paths` | Dot paths and globs whose whole value is replaced. A bare `password` matches that key at any depth |
| `builtins` | The built-in patterns to run. Leave it out to run all of them |
| `patterns` | Your own regexes, applied to string values |
| `replacement` | The text that replaces a match, `[REDACTED]` by default, or a function of the match |
| `transform` | A synchronous function that edits the event in place before the other rules run |

`redact: false` turns it off in production, and `redact: true` turns it on in development.

::callout{icon="i-lucide-triangle-alert" color="warning"}
A function in `replacement` or `transform` cannot go in `nuxt.config.ts`: that config is serialized to JSON at build time, which drops functions. Put it in `evlog.config.ts`.
::

Redaction is a safety net. Choose what you pass to `log.set()` rather than relying on it.
