A wide event collects a lot of context, which makes it easy to log a field you should not. Redaction scrubs the event before it is printed and before any drain receives it.

A signup handler that logs more than it should:

::emits{step="development"}
```typescript [route:POST /api/users]
log.set({
  user: { email: body.email, phone: body.phone },
  card: { number: body.cardNumber },
  session_token: body.sessionToken,
})
```
::

Redaction is on by default when `NODE_ENV` is `production` and off in development, where you want the full values to debug. You have nothing to configure to get it. The default applies once `initLogger()` has run: a script that only calls `createLogger()` has no redaction. To see the masked event on your machine, turn it on:

::emits{step="on"}
```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'

export default defineEvlog({
  service: 'my-app',
  redact: true,
})
```
::

## What is masked

Built-in patterns mask partially, so a redacted value still helps you debug:

| Pattern | Input | Output |
| --- | --- | --- |
| `creditCard` | `4111111111111111` | `****1111` |
| `email` | `alice@example.com` | `a***@***.com` |
| `ipv4` | `192.168.1.100` | `***.***.***.100` |
| `phone` | `+33 6 12 34 56 78` | `+33******78` |
| `jwt` | `eyJhbGciOiJIUzI1NiIs...` | `eyJ***.***` |
| `bearer` | `Bearer sk_live_abc123...` | `Bearer ***` |
| `apiKeys` | `ghp_` followed by 36 characters | `ghp_***` |
| `privateKey` | `-----BEGIN RSA PRIVATE KEY-----` block | `-----BEGIN RSA PRIVATE KEY-----***` |
| `urlPassword` | `postgres://user:hunter2@db` | `postgres://user:***@db` |
| `iban` | `FR76 3000 6000 0112 ...189` | `FR76****189` |

`apiKeys` finds a provider credential by its fixed prefix, anywhere in a string: GitHub (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`), npm (`npm_`), AWS access key IDs (`AKIA`, `ASIA`), Anthropic (`sk-ant-`), OpenAI (`sk-proj-`), Stripe (`sk_live_`, `rk_live_`) and Slack (`xoxb-`, `xoxp-`, `xapp-`). A value shorter than its format, such as `ghp_abc`, is left as it is. `privateKey` keeps only the header of a PEM block, and masks a block with no END line to the end of the value. `urlPassword` keeps the scheme, user and host of a URL, also when there is no user: `redis://:***@cache:6379`. `ipv4` leaves `127.0.0.1` and `0.0.0.0` alone, since neither is a client address.

A password has no recognizable shape, so the `secrets` built-in reads the key instead: any key ending in `password`, `passwd`, `secret`, `token`, `apiKey`, `privateKey`, `credentials`, `authorization`, `dsn` or `connectionString`, at any depth and in any case, is replaced in full with `replacement`, `[REDACTED]` by default. The snake case forms (`api_key`, `private_key`, `connection_string`) match too:

| Key | Replaced |
| --- | --- |
| `password`, `newPassword`, `user_password` | Yes |
| `secret`, `clientSecret`, `client_secret` | Yes |
| `token`, `accessToken`, `refresh_token`, `API_TOKEN` | Yes |
| `apiKey`, `api_key`, `privateKey`, `credentials` | Yes |
| `authorization`, `dsn`, `connectionString` | Yes |
| `totalTokens`, `tokensPerSecond`, `tokenType` | No |
| `cacheKey`, `idempotencyKey` | No |

No part of a password is safe or useful to keep, so secrets get no partial mask. Booleans and `null` stay readable (`hasPassword: true`), and any other value is replaced, so a fetch option such as `credentials: 'include'` is masked too.

## Narrow it or extend it

::emits{step="narrowed"}
```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'

export default defineEvlog({
  service: 'my-app',
  redact: {
    paths: ['password', '*_token', 'headers.x-forwarded-for'],
    builtins: ['email', 'creditCard'],
    patterns: [/sk_live_\w+/g],
  },
})
```
::

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `paths` | `string[]` | None | Dot paths and globs whose whole value is replaced. A bare `password` matches that key at any depth |
| `builtins` | `false \| string[]` | All | The built-in patterns to run. Pass `false` to run none and keep only your `paths` and `patterns` |
| `patterns` | `RegExp[]` | None | Your own regexes, applied to string values. A match is replaced with `replacement`, not partially masked |
| `replacement` | `string \| (matched, ctx) => string` | `'[REDACTED]'` | The text that replaces a match, or a function of the match. The built-in patterns keep their own masks |
| `transform` | `(event) => void` | None | A synchronous function that edits the event in place before the other rules run |

`redact: false` turns it off in production, and `redact: true` turns it on in development.

The names `builtins` accepts are `creditCard`, `email`, `ipv4`, `phone`, `jwt`, `bearer`, `apiKeys`, `privateKey`, `urlPassword`, `iban` and `secrets`.

A path replaces the whole value under it, nested objects included:

| Path | Matches |
| --- | --- |
| `user.email` | That exact path |
| `password` or `**.password` | A `password` key at any depth |
| `*_token` | Key names such as `access_token` and `refresh_token`, at any depth |
| `user.*` | Everything directly under `user` |
| `audit.changes.*.password` | Exact and wildcard segments mixed |

`auditDiff({ redactPaths: ['password'] })` takes the same syntax.

## Compute the replacement

When the replacement has to come from the value it replaces, pass a function. The usual case keeps requests correlatable without exposing the credential that identifies them:

```typescript
initLogger({
  redact: {
    patterns: [/\/public\/claim\/([A-Za-z0-9._-]{12,})/g],
    replacement: (_match, ctx) => `/public/claim/[tok:${fingerprint(ctx.groups?.[0] ?? '')}]`,
  },
})
// /public/claim/eyJhbGciOi...  →  /public/claim/[tok:9f3a1c]
```

The function receives the matched value and a context:

| Field | Type | Description |
| --- | --- | --- |
| `path` | `string` | Dot path from the event root, such as `user.email` or `items.0.token` |
| `key` | `string` | Leaf key of the field, such as `email` |
| `groups` | `Array<string \| undefined>` | Capture groups of the `patterns` entry that matched. Not set for `paths` |

For `paths`, the matched value is the whole field value, of any type. For `patterns`, it is the matched substring. If the function throws or returns something other than a string, evlog uses `[REDACTED]` and logs the failure, so a broken function redacts too much, never too little.

## Rules a list cannot express

Redacting a field for some tenants only, or when a sibling field has a given value, or keeping an allowlist, takes code. `transform` receives the event before `paths`, `builtins` and `patterns` run:

```typescript
initLogger({
  redact: {
    transform: (event) => {
      if (event.tenant === 'regulated') delete event.query
    },
  },
})
```

It sees the raw values, and the other rules still apply to whatever it leaves, so a `transform` that misses a field is not your last line of defence. The event it edits is a private copy: the object you logged is never touched. If it throws, evlog reports the error like a drain failure, runs the other rules, and still logs the event.

::callout{icon="i-lucide-triangle-alert" color="warning"}
A function in `replacement` or `transform` cannot go in `nuxt.config.ts` or in the options of the Nitro module: that config is serialized to JSON at build time, which drops functions, and the module warns at build time when it finds one. Put it in `evlog.config.ts`.
::

## Where it runs

Redaction runs once, when the event is emitted and before anything can read it, in this order:

1. `transform`
2. `paths`
3. The `secrets` built-in
4. The other built-in patterns
5. `patterns`

[Enrichers](/events/enrichers) run after it, then the console output and the drain, which both receive the same event. A field an enricher adds is not masked, so an enricher that reads a header or a session masks what it writes. [Lifecycle](/events/lifecycle) has the full order.

It runs synchronously, and the cost of the built-in patterns grows linearly with the length of the values you log, whatever characters they contain. Hono emits before it returns the response, so the caller waits for redaction, except on a streaming response, which Hono returns first and emits when the stream ends. Express emits once the response has finished.

Redaction is a safety net. Choose what you pass to `log.set()` rather than relying on it.
