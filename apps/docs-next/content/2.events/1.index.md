A request that logs ten lines leaves you to stitch them back together during an incident. The same request as a :term[wide event]{of="wide-event"} is one record, with the user, the input, every step and the outcome as fields you can query.

::wide-event-collapse
::

## The shape it replaces

```typescript [src/jobs/sync.ts]
logger.info('Job started')
logger.info('User authenticated', { userId: user.id })
logger.info('Fetching data', { source: 'postgres' })
logger.info('Job finished', { duration: 234 })
```

Four lines, one correlation problem, and no line at all if the job throws between the second and the third. The wide event version accumulates the same facts and emits them together:

```typescript [src/jobs/sync.ts]
import { createLogger } from 'evlog'

const log = createLogger({ jobId: 'sync-001', queue: 'emails' })

log.set({ user: { id: user.id } })
log.set({ source: 'postgres', target: 's3' })
log.set({ records: { found: 1250, synced: 1250 } })
log.emit()
```

## Three ways to get a logger

| You are in | Use | Emits |
| --- | --- | --- |
| A route, with a framework integration | `useLogger(event)`, or the framework accessor (`c.get('log')`, `req.log`) | When the response ends |
| A script, job, queue worker or workflow | `createLogger(context)` | When you call `log.emit()` |
| An HTTP handler without an integration | `createRequestLogger({ method, path })` | When you call `log.emit()` |

For a one-off line that belongs to no unit of work, `log.info('tag', 'message')` still works, and prints straight away.

## What every event carries

The integration fills in what it knows: `method`, `path`, `status`, `duration` and `requestId` on a request, the `service` and `environment` on every event. You add the rest with `log.set()`, grouped into objects (`user`, `cart`, `payment`) rather than flat keys, so a query reads `user.plan = 'pro'`.

An error thrown during the work lands on the same event as `error`, with its `why` and `fix`. See [Errors](/errors).
