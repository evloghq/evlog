An enricher adds fields to an event after the work ends and before the event is printed or drained. The built-in ones read the request headers, so your handlers stay about the business logic.

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'
import { createDefaultEnrichers } from 'evlog/enrichers'

export default defineEvlog({
  service: 'my-app',
  enrich: createDefaultEnrichers(),
})
```

## The built-in enrichers

`createDefaultEnrichers()` composes all four. Import them one by one from `evlog/enrichers` to pick:

| Enricher | Sets | Reads |
| --- | --- | --- |
| `createUserAgentEnricher()` | `userAgent` | `user-agent`: browser, OS, device |
| `createGeoEnricher()` | `geo` | `x-vercel-ip-*` on Vercel, `cf-ipcountry` on Cloudflare |
| `createRequestSizeEnricher()` | `requestSize` | `content-length` of the request and the response |
| `createTraceContextEnricher()` | `traceContext` | `traceparent`, so the event joins a distributed trace |

Each one takes `{ overwrite: false }` by default, so a field you set yourself is never replaced.

On Cloudflare, only the country comes as a header. The rest of the geo data lives on `request.cf`, which a custom enricher can read.

## Your own

An enricher is a function that receives the event context and edits it:

```typescript [evlog.config.ts]
import { defineEvlog } from 'evlog'

export default defineEvlog({
  service: 'my-app',
  enrich: (ctx) => {
    ctx.event.region = process.env.VERCEL_REGION
  },
})
```
