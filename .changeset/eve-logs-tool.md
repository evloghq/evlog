The extension adds a `logs` tool (`evlog__logs` for a mount named `evlog`) that reads the agent's own events with the query behind `evlog logs`: the `recent`, `errors`, `slow`, `stats` and `trace` views, and the `session`, `where`, `since`, `until`, `level`, `path`, `status` and `over` filters. List views return one short row per turn (status, duration, the error's code, why and fix, the tools that failed, tokens), with extra fields on request through `fields`; `trace` returns one request's events in full. On Vercel (`source: 'auto'` or `'vercel'`) it reads the project's runtime logs with the deployment's OIDC token, through the connector `logs.vercel.connector` names, set up once with `npx evlog setup vercel`. With no connector, every call fails with `Vercel logs are not set up`, the turn's event records the call as failed, and the tool does not fall back to the local files. Elsewhere it reads `logs.dir`. The agent's scheduled work reads every turn, a signed-in caller its own session, and an anonymous caller gets no tool; `logs.access(ctx)` returns `'agent'`, `'session'` or `false` to change that per caller. The new `logs: { dir, vercel: { connector }, access }` option configures it.
